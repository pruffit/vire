# VireMusic — git и GitHub

История репозитория — продукт, а не побочный след работы. Ведётся она агентом: Danya
не должен просить «закоммить», «открой PR», «посмотри, почему красный CI». Триггеры ниже
срабатывают сами.

Дополняет `vire-loop`: там инженерный цикл задачи, здесь всё, что происходит с ветками,
коммитами и GitHub. Фаза Ship из `vire-loop` — это процедуры данного скилла.

## Триггеры (действовать без просьбы)

| Что вижу | Что делаю |
|---|---|
| Работа началась, ветка `main` | Сначала ветка (§Ветка), потом код |
| Набор изменений закончен, гейты зелёные | Коммит серией (§Коммит) |
| Задача доведена, ветка отстоит от main | Push + PR (§PR) |
| Открыт PR — мой или dependabot | Ревью чистым агентом до мержа (§Ревью) |
| Прогон CI красный | Разбор (§CI), не «перезапущу» |
| Находка не чинится в этом PR | Issue (§Issues) |
| PR зелёный, блокеров нет | Мерж + удаление ветки (§Мерж) |
| В дереве неделю висит несвязанный WIP | Сказать об этом и предложить разнос по веткам |

Первым делом в сессии, где предстоит работа с кодом, — сводка:
`"C:\Program Files\Git\bin\bash.exe" .claude/scripts/git-sweep.sh` (ветка, незакоммиченное,
открытые PR и issues, последние прогоны). Висящий PR, красный прогон, забытая ветка —
повод действовать, а не ждать вопроса. Если в `.claude/settings.local.json` заведён
SessionStart-хук на этот скрипт, сводка приезжает сама (фрагмент — в §Хук).

## Граница полномочий

**Делаю сам, не спрашивая:** ветка, коммит, push ветки, PR (создать, переписать тело,
метки), ревью и комментарии в PR, issues (завести, дополнить), диагностика CI, мерж
в `main` на зелёном CI, удаление слитой ветки, `git revert` собственного мержа.

**Только по явной команде Danya:** тег `vX.Y.Z` (это деплой на прод), `push --force`
и любое переписывание опубликованной истории, удаление неслитой ветки, удаление
и переименование репозитория, смена видимости, правка секретов и настроек Actions,
закрытие PR и issues, которые завёл не я.

Мерж в `main` деплой не запускает — деплой только по тегу, поэтому цена ошибки здесь
это `git revert`, а не упавший прод. Тег — другая история, он всегда через вопрос.

Branch protection на приватном репозитории free-плана недоступна: «required checks»
держу я. Мерж без зелёного CI — дыра в этом месте, а не мелкая вольность.

## Непредвзятость: чистый агент на шаг

Свою работу ревьюит тот, кто её не делал и не знает, что задумывалось. Поэтому шаги
с суждением идут сабагентом со свежим контекстом.

**Что кладу в бриф:** цель («ревью PR #72»), где взять дифф (`gh pr diff 72` — команду,
не сам дифф), где лежат правила (`CLAUDE.md`, `docs/`), формат ответа. Всё.

**Чего в брифе не бывает никогда:**

- пересказа замысла — «я выносил знак в общее место, чтобы не расходился»: агент начнёт
  проверять намерение вместо кода;
- моих оценок — «там всё чисто», «я уже прогнал гейты», «посмотри только X»: модель
  подтверждает якорь, а не проверяет;
- истории прошлых ревью и отклонённых находок: верная находка не должна умереть
  оттого, что её однажды отклонили;
- авторства («это писал ты вчера»): на код не влияет, на тон влияет;
- сужений «сообщай только критичное», «будь консервативен»: исполняется буквально,
  реальные баги теряются молча.

Самопроверка брифа: есть в нём «я», «мы хотели», «должно быть ок» — переписать.

**Один прогон на срез.** Нашёл находки → чиню → повторное ревью только если сам фикс
оказался крупным. Агент, проверяющий агента, — не независимость, а удвоение счёта.

**Где чистый агент НЕ нужен.** Механика без суждения: `git status`, создание ветки, push,
`gh pr create` с готовым телом, мерж, удаление слитой ветки, чтение статуса чеков.
Это исполнение уже принятого решения — делаю сам, парой команд. Агент поднимается там,
где есть что оценивать: ревью, формулировка коммита, формулировка issue, разбор красного
прогона.

## Агенты

| Агент | Модель | Что делает | Чем не является |
|---|---|---|---|
| `vire-reviewer` | sonnet | Ревью диффа/PR по чеклисту VireMusic, находки с серьёзностью и уверенностью | Не чинит, не пушит, не комментирует PR |
| `vire-scribe` | sonnet | Серия коммитов и тело PR по диффу, стиль истории репо | Не пушит, не мержит, не переписывает историю |
| `vire-triage` | sonnet | Issues: дедуп, формулировка, метки `area:*` | Не закрывает issues, не назначает |
| `vire-ci` | sonnet | Разбор красного прогона: лог → диагноз → правка | Не чинит сам, не гоняет rerun вслепую |

## Ветка

От свежего `main`, не от текущего HEAD (иначе в ветку уезжает чужой неслитый PR):

```bash
git fetch origin
git switch -c <префикс>/<кратко-латиницей> origin/main
```

Префиксы из истории репозитория: `feat/`, `fix/`, `test/`, `chore/`, `release/vX.Y.Z`.
Одна ветка — одна задача. В дереве посторонний WIP — не тащить его в новую ветку.

## Коммит

Гейты зелёные (verify-контракт из `vire-loop`) → `vire-scribe`. Бриф:

```
Собери коммиты из рабочего дерева в C:\Users\KOTLAEV\vire.
Дифф возьми сам: git status --porcelain, git diff, git diff --staged.
Коммить только пути: <перечень>. Остальное в дереве не трогай.
Стиль и правила — в твоём определении агента.
```

Перечень путей — обязательная часть брифа: в дереве VireMusic регулярно лежит
несвязанный WIP.

Не копить дифф на десятки файлов «до конца задачи»: коммит на каждый законченный
смысловой шаг, иначе история нечитаема, а откат невозможен.

## PR

```bash
git push -u origin <ветка>
gh pr create --base main --title "<заголовок>" --body-file <файл> --label area:<область>
```

Тело — по `.github/pull_request_template.md`, пишет `vire-scribe`. Галочка «прогнано»
ставится только за гейт, вывод которого видели.

## Ревью

До мержа — всегда, включая свои PR и dependabot. Бриф ровно такой:

```
Ревью PR #<N> в репозитории C:\Users\KOTLAEV\vire.
Дифф и описание возьми сам: gh pr diff <N>, gh pr view <N>.
Правила проекта: CLAUDE.md в корне репозитория.
Выложи все находки, включая неуверенные и мелкие, с серьёзностью и уверенностью.
```

Больше в бриф не идёт ничего.

Находки, пережившие проверку, уходят **инлайн-комментами в PR одним ревью**, а не
россыпью комментариев. Тело ревью кладу в `review.json`:

```json
{
  "event": "COMMENT",
  "body": "Вердикт: FIX-THEN-MERGE. <одна фраза>.",
  "comments": [
    { "path": "apps/web/app/...", "line": 42, "side": "RIGHT",
      "body": "**блокер · уверенность высокая** — что не так и как ломается." }
  ]
}
```

и постю одной командой:

```bash
gh api repos/pruffit/vire/pulls/<N>/reviews -X POST --input review.json
```

`event: COMMENT`, а не `APPROVE`: собственный PR апрувить GitHub не даёт, да и смысла
в самоапруве нет. Строка вне диффа даёт 422 — такую находку клади в `body` сводки.
Находки проверяю сам перед постингом: агент отдаёт всё, включая догадки, а в PR уходит
то, что подтвердилось по коду.

## Issues

Находка не чинится в этом PR → `vire-triage`, метка `area:*` обязательна. Бриф: сама
находка (путь, симптом), без истории обсуждения. Дедуп агент делает первым шагом.

Не заводить issue на то, что чинится прямо сейчас, и на однотипную мелочь пачкой —
такое собирается в один issue списком.

## CI

Красный прогон → `vire-ci`, бриф: номер прогона или PR. Дальше по классу: «код» —
правка через обычный цикл; «окружение» — правка workflow; «флейка» — один перезапуск
с доказательством из лога.

Дифф целиком из `docs/**`, `**/*.md`, `icons/**` попадает под `paths-ignore`, и чеков
не будет вообще. Это зелёный статус, но убедиться, что дифф действительно такой,
обязан я — `gh pr diff <N> --name-only`.

## Мерж

```bash
gh pr checks <N>          # все зелёные, либо чеков нет по paths-ignore
gh pr merge <N> --merge --delete-branch
```

`--merge`, а не squash: история проекта — merge-коммиты. `deleteBranchOnMerge`
на репозитории включён, флаг дублирует его для локальной ветки.

Красный чек, неразобранная находка-блокер, неотревьюенный PR — мерж не делается.

## Dependabot

PR приезжает по понедельникам, минорные пачкой. Порядок: `vire-reviewer` на дифф
lockfile (что реально уехало и не задевает ли игнор-лист из `.github/dependabot.yml` —
RN/React, libsodium, Skia/reanimated), зелёный CI, мерж. Мажоры в PR не приходят
намеренно, они идут отдельной задачей.

## Релиз — стоп-линия

Тег `vX.Y.Z` запускает `deploy.yml` и выкатку на прод. Всегда через вопрос Danya.
Порядок при команде: версия в двух местах (корневой `package.json` и `apps/web/package.json`),
`pnpm install` → коммит lockfile, `pnpm audit --audit-level=high` руками (шаг в CI
пропускается при недоступном реестре), ветка `release/vX.Y.Z` → PR → мерж → тег.

## Хук

Сводка в начало сессии и снятие лишних промптов на чтение git/gh — фрагмент для
`.claude/settings.local.json` (файл в `.gitignore`, правит его Danya: конфиг харнесса
агенту писать не дают):

```json
{
  "permissions": {
    "allow": [
      "Bash(git status:*)", "Bash(git diff:*)", "Bash(git log:*)", "Bash(git show:*)",
      "Bash(git branch:*)", "Bash(git ls-files:*)", "Bash(git fetch:*)",
      "Bash(gh pr list:*)", "Bash(gh pr view:*)", "Bash(gh pr diff:*)", "Bash(gh pr checks:*)",
      "Bash(gh issue list:*)", "Bash(gh issue view:*)",
      "Bash(gh run list:*)", "Bash(gh run view:*)", "Bash(gh label list:*)"
    ]
  },
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume",
        "hooks": [
          { "type": "command",
            "command": "\"C:\\Program Files\\Git\\bin\\bash.exe\" .claude/scripts/git-sweep.sh" }
        ]
      }
    ]
  }
}
```

Путь к `bash.exe` взят от стандартной установки Git for Windows; стоит Git иначе —
правится там же, в этом фрагменте.

Пишущие команды (`git push`, `gh pr create`, `gh pr merge`, `gh issue create`,
`gh api ... -X POST`) в allow-лист намеренно не идут: промпт на них — последняя видимая
точка перед действием наружу.

## Антипаттерны

- Ревью своей работы «на глаз» вместо чистого агента. Знание замысла — это слепота.
- Бриф с пересказом задумки: ревьюер начнёт проверять намерение.
- Второй агент, чтобы перепроверить первого.
- Один агент на несколько шагов подряд: ревьюер, который уже чинил, находит меньше.
- Коммит-помойка в конце дня вместо серии по смыслу.
- `git add -A` при постороннем WIP в дереве.
- Мерж «CI ещё крутится, там же ничего страшного».
- Rerun красного прогона вместо разбора.
- Тег без вопроса.
