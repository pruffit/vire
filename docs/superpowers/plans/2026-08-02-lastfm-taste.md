# План — предложка по вкусу из Last.fm (02.08.2026)

Дизайн: `../specs/2026-08-01-party-mode-design.md` §«Предложка по вкусу». Последний
неотданный пункт спеки вечеринки. Решение заказчика от 01.08.2026: привязанный внешний
профиль даёт **только вкус и предложку**, никакого воспроизведения оттуда.

Last.fm выбран потому, что у него официальный публичный API, он работает в РФ и не требует
OAuth: пользователь просто вводит свой ник. Это не авторизация через иностранный сервис —
406-ФЗ тут ни при чём.

## 1. Данные

- Миграция 0048: `users.lastfm_username varchar(64)` (nullable). Схема —
  `packages/db/src/schema/` рядом с остальными полями пользователя.
- Репозиторий пользователя: чтение вместе с профилем (`getUserProfile`) и
  `updateUserLastfmUsername(userId, username | null)` рядом с существующими
  `updateUserName`/`updateUserDiscoverable`.

## 2. Адаптер

`apps/web/lib/external/lastfm.ts`:

```ts
export function createLastfmTaste(apiKey: string | undefined): {
  topTracks(username: string, limit: number): Promise<MetadataHint[]>;
}
```

- `user.getTopTracks`, `period=3month`, фиксированный хост `ws.audioscrobbler.com`
  (пользовательский ввод только в query — SSRF-поверхности нет, `safe-fetch` не нужен);
- таймаут 4с, любая ошибка/отсутствие ключа → `[]` (деградация, как у YouTube-резолвера);
- маппинг в `MetadataHint`: `name` → title, `artist.name` → artistName,
  обложка из `image` (последний размер) через `sanitizeCoverUrl` — у Last.fm свой хост,
  в белый список он **не входит**, так что обложки закономерно отпадут в `null`;
  это ожидаемо, не баг: карточка нарисует плейсхолдер;
- кэш в Redis `lastfm:top:{username}` на 6 часов (тот же `REDIS_URL`, отдельный клиент
  как в `lib/presence.ts`); Redis недоступен → просто ходим в API.

Ник валидировать до запроса: `^[a-zA-Z0-9_.-]{2,64}$`, иначе `[]`.

## 3. Где это видно

**`/profile`** — блок «Музыкальный вкус» рядом с существующими настройками: поле ника
Last.fm, кнопка сохранить, состояние «привязано / не привязано», кнопка отвязать
(пустая строка → `null`). Валидация формата на клиенте и в zod-схеме
`PATCH /api/v1/user/profile` (`lastfmUsername: z.string().regex(...).max(64).nullable().optional()`).
Текст под полем — честный: «Берём только список любимых треков для предложки. Ничего
не публикуем и не проигрываем оттуда.»

**Панель добавления вечеринки** — `GET /api/v1/party/suggest` без `q` (сейчас пустой `q`
даёт `{candidates: []}`) отдаёт вкусовые подсказки залогиненного пользователя.
`PartyAddPanel` дёргает его один раз при монтировании и показывает в простое **после**
лайков, заголовком «Из вашего вкуса». Ника нет / ключа нет / API молчит — блока просто
нет, никаких сообщений об ошибке.

Дедуп с лайками — по нормализованному «артист + название» (`normalizeQueryKey`,
уже есть в `packages/core/src/services/external-resolve.ts`).

## 4. Env

`LASTFM_API_KEY` — в `.env.example` с пояснением, что без него блок вкуса просто не
появляется. Ключ выдаётся мгновенно на last.fm/api, серверный, в браузер не уходит.

## 5. Тесты

- Адаптер: без ключа → `[]`; невалидный ник → `[]` (запроса нет); успешный ответ →
  маппинг в `MetadataHint`; сеть упала → `[]`; повторный вызов бьёт кэш, а не API.
- Роут `suggest` без `q`: аноним → `[]`; юзер без ника → `[]`; юзер с ником → подсказки;
  дедуп с лайками.
- `PATCH /api/v1/user/profile`: валидный ник сохраняется, мусорный → 400, `null` отвязывает.
- Панель: блок «Из вашего вкуса» появляется только при непустом ответе.

## 6. Гейты

`typecheck` (web/core/db) · `lint` · `check:routes` · `test` · **`audit:design`** · `build`.

## Ограничения

- Только Last.fm и только `user.getTopTracks` — ни истории прослушиваний, ни скробблинга.
- Обложки Last.fm не показываем (чужой CDN вне белого списка `cover-hosts.ts`).
- Ник хранится как есть, без проверки существования аккаунта: пустой ответ API
  неотличим от опечатки и трактуется одинаково — блока нет.
- Комментарии — только неочевидное «почему», 1–2 строки.
