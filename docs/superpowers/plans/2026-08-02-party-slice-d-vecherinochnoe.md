# План — вечеринка, срез D: голосование за скип и автодобор (02.08.2026)

Дизайн: `../specs/2026-08-01-party-mode-design.md` §«Вечериночное». Срезы A–C в main:
`kind: 'PARTY'`, полиморфная очередь, резолвер любого ввода, комната `/nrvz914/[code]`,
экран вечеринки, слой источников звука. Здесь — то, что держит вечер живым, когда хозяин
телефона отвлёкся.

Предложка по Last.fm — отдельным срезом (нужен ключ и привязка профиля), здесь её нет.

## 1. Голосование за пропуск

Правило: **больше половины присутствующих** — позиция уходит; **хост пропускает всегда**.
Присутствие берём из `listPresent` (тот же ZSET, что кормит `presentParticipantIds`), а не
из списка участников: ушедший спать гость не должен поднимать планку.

- `packages/core/src/services/jam-skip.ts` — чистая функция:
  ```ts
  export function resolveSkip(input: { votes: number; presentCount: number; isHost: boolean }):
    { skip: boolean; needed: number }
  ```
  `needed = floor(presentCount / 2) + 1` (минимум 1); `skip = isHost || votes >= needed`.
  Тесты на 1/2/3/4 присутствующих и на хоста.
- `IJamStateStore` (`packages/core/src/ports/jam-state.ts`) — два метода:
  `addSkipVote(jamId, itemId, participantKey): Promise<number>` (размер SET после добавления,
  идемпотентно на повторный голос) и `clearSkipVotes(jamId, itemId): Promise<void>`.
  Реализация в `apps/web/lib/jam/jam-state.ts`: Redis SET `jam:skip:{jamId}:{itemId}` с TTL
  как у остального состояния джема. Недоступный Redis → `0` (деградация не блокирует людей:
  голос не засчитан, но хост скипает).
- `JamService.voteSkip(jamId, identity, itemId)`:
  - участник (`findParticipant`) иначе `forbidden()`; сессия `LIVE`; `kind === 'PARTY'`
    иначе `ValidationError`;
  - `itemId` должен совпадать с текущей позицией (`getPlayback().itemId`) — голос за уже
    сменившийся трек молча превращается в no-op, иначе гонка «проголосовал в момент перехода»
    скипнет следующий трек;
  - `resolveSkip` → если скип: перейти на следующую позицию тем же путём, что
    `PlaybackIntent {kind:'track'}` (не дублировать логику — вынести общий приватный метод),
    очистить голоса; если следующей нет — пауза на месте (не завершать джем);
  - в обоих случаях broadcast `jam:skip` `{ itemId, votes, needed }`.
- `POST /api/v1/jam/[code]/skip` — body `{ itemId, sessionId? }`, rate-limit как у очереди
  (`jam-skip:{key}`, 20/мин). Коды: 400 не-PARTY/невалидный body, 401 без identity,
  403 не участник, 404 нет кода, 409 завершён.
- SSE: тип события добавить в общий union событий комнаты (`use-jam-room.ts` + серверный
  broadcaster), `useJamRoom` держит `skipVotes: { itemId, votes, needed } | null`,
  сбрасывается на смену `playback.itemId`.

**UI.** Кнопка «Пропустить» в комнате вечеринки (рядом с «Перемешать») и на экране
вечеринки. Подпись — счётчик `Пропустить · 2/3`, у хоста без счётчика. Свой голос
подсвечен и повторно не отправляется (локальный флаг, сбрасывается сменой позиции).
Оптимистики нет: счётчик — общее состояние, ждём эхо SSE.

## 2. Автодобор из волны

Очередь кончилась — вечеринка не должна замолкать.

- `JamService.refillFromWave(jamId, identity, limit = 5)`:
  - участник + `LIVE` + `kind === 'PARTY'`;
  - no-op (ok с текущей очередью), если после текущей позиции ещё есть треки —
    добор только на реально пустом хвосте;
  - якорь похожести — последняя каталожная (`source === 'VIRE'`) позиция очереди;
    внешние/локальные волне ничего не говорят;
  - вкус: `userId` одного из присутствующих залогиненных участников, ротацией по
    номеру добора (`servedIds` волны и так режут повторы) — честное упрощение вместо
    агрегированного профиля, записать в фичедок;
  - `sessionId` волны — стабильный `jam:{jamId}`, чтобы анти-повтор работал весь вечер;
  - добавляет треки в очередь **в хвост, без round-robin** (это не чей-то вклад) и
    броадкастит `jam:queue`.
- `POST /api/v1/jam/[code]/refill` — rate-limit `jam-refill:{jamId}` 5/мин (ключ по джему,
  не по участнику: добор общий).
- Триггер на клиенте — `handleTrackEnded` в `jam-session-provider.tsx`: когда следующей
  позиции нет и это PARTY, инициатор (тот же, что решает переход: хост в SYNCED,
  звуковое устройство в SPEAKER) дёргает refill и после успеха переходит на первую
  добранную позицию. Волна пуста / роут упал — просто тишина, как сейчас.
- `WaveService` инъектируется в `JamService` **опционально**: без него `refillFromWave`
  возвращает текущую очередь без изменений (юнит-тесты джема не тянут волну).

## 3. Тесты

- `jam-skip.test.ts` — пороги и хост.
- `jam.test.ts` — voteSkip: не участник → 403; не-PARTY → ValidationError; голос за
  чужую позицию → no-op; порог достигнут → переход на следующую и очистка голосов;
  порог не достигнут → только broadcast; хост скипает с первого раза.
- `jam.test.ts` — refill: непустой хвост → без изменений; пустой → треки волны в хвосте;
  волна не инъектирована → без изменений.
- Роуты `skip`/`refill` — права и валидация (как у остальных jam-роутов).
- UI: счётчик рисуется по событию, свой голос не уходит дважды, у хоста нет счётчика.

## Ограничения

- Голоса живут в Redis и умирают вместе с позицией — истории голосований нет.
- Автодобор берёт только каталожные треки: волна не знает про внешние источники.
- Комментарии — только неочевидное «почему», 1–2 строки.
