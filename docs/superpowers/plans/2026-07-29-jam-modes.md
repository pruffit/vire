# План: два режима джема (SYNCED / SPEAKER)

Спека: `docs/superpowers/specs/2026-07-29-jam-modes-design.md`.
Порядок строго снизу вверх: БД → core → API → клиент → UI → тесты/доки.

## 1. БД (`packages/db`)

`src/schema/jam.ts`:
- `jamModeEnum = pgEnum('jam_mode', ['SYNCED', 'SPEAKER'])`.
- `jamSessions.mode` — `notNull().default('SYNCED')`.
- `jamSessions.speakerParticipantId` — `uuid('speaker_participant_id')`, nullable,
  `references(() => jamParticipants.id, { onDelete: 'set null' })`. FK объявлять через
  ленивую ссылку (`jamParticipants` объявлен ниже — при циклической ссылке использовать
  `AnyPgColumn`-типизацию, как это делается в остальных схемах проекта; посмотреть, есть
  ли уже такой приём в `packages/db/src/schema`, и повторить его).
- Миграция: `pnpm --filter @vire/db db:generate` (следующий номер — 0045). Применить
  `db:migrate`, если локальная БД поднята; если нет — не блокироваться, просто отметить в отчёте.
- Репозиторий `jam.repository.ts`: маппер сессии + методы `setMode(jamId, mode)` и
  `setSpeaker(jamId, participantId | null)`.

## 2. Core (`packages/core`)

- `types/jam.ts`: `export type JamMode = 'SYNCED' | 'SPEAKER'`; в `JamSession` — `mode: JamMode`,
  `speakerParticipantId: string | null`.
- `repositories/jam.ts`: `setMode`, `setSpeaker` в `IJamRepository`; `CreateJamSessionInput.mode`.
- Новый `services/jam-mode.ts` — чистые функции (экспорт через индекс пакета):
  - `resolveSpeakerParticipantId(participants: JamParticipant[], speakerParticipantId: string | null): string | null`
    — указанный участник, если он ещё в списке, иначе participant с ролью HOST, иначе null.
  - `isAudioDevice(args: { mode, participantId, participants, speakerParticipantId }): boolean`
    — в `SYNCED` всегда true; в `SPEAKER` — сравнение с `resolveSpeakerParticipantId`.
- `services/jam.ts`:
  - `create(hostUserId, title, hostDisplayName, mode: JamMode = 'SYNCED')`.
  - `setMode(jamId, identity, mode)` — участник обязан быть HOST (`forbidden('Режим меняет только хост')`),
    сессия LIVE; пишет в репозиторий, бродкастит `{ type: 'jam:session', mode, speakerParticipantId }`.
  - `claimSpeaker(jamId, identity)` — любой участник; ставит себя колонкой, бродкастит то же событие.
  Оба возвращают `Result` с уже принятыми в файле типами ошибок.

## 3. API (`apps/web/app/api/v1/jam`)

- `route.ts` (создание): zod-схема принимает `mode: z.enum(['SYNCED','SPEAKER']).optional()`, прокидывает в сервис.
- Новый `[code]/mode/route.ts` — `POST`, тело `{ mode, sessionId? }`; идентичность через
  `resolveJamIdentity` (как в `playback/route.ts`), маппинг ошибок 403/404/409 по тому же образцу.
- Новый `[code]/speaker/route.ts` — `POST`, тело `{ sessionId? }`.
- Проверить `check:routes` — новые сегменты статические, конфликтов слагов нет.

## 4. Клиент (`apps/web/lib/jam`, `store`)

- `use-jam-room.ts`: в `JamRoomState` — `mode: JamMode`, `speakerParticipantId: string | null`;
  снапшот берёт их из `e.session`; новый обработчик `'jam:session'`.
- `use-playback-sync.ts`: проп `driftCorrection: boolean` — при `false` эффект периодической
  коррекции не запускается вовсе (интервал и visibilitychange не вешаются); реакция на смену
  трека/паузы остаётся.
- `store/player.ts`: `JamOverride.isRemote: boolean`.

## 5. Комната и UI

`app/(listener)/jam/[code]/jam-room.tsx`:
- `myParticipantId = membership.participantId`; `isAudioDevice(...)` из core.
- `audioEnabled` — только для звукового устройства (`setAudioEnabled(true)` при join оставить,
  но в `usePlaybackSync` передавать `audioEnabled && isAudioDevice && !ended`).
- `driftCorrection={mode === 'SYNCED'}`.
- `handleTrackEnded`: инициатор — звуковое устройство (SYNCED → HOST как сейчас, SPEAKER → колонка).
- `setPlayerJamOverride(... isRemote: !isAudioDevice)`.
- Шапка: индикатор режима; у хоста — переключатель «В наушниках / На колонке»
  (посмотреть готовый сегмент-контрол в `components/` — `action-select.tsx` или `ui-kit`;
  не плодить новый, если подходит существующий). На мобилке шапка уже двухстрочная — вписать,
  не ломая 320px.
- В `SPEAKER` у пульта — строка «Играет на устройстве {имя колонки}» + кнопка «Звук здесь»
  (`POST /speaker`), у колонки — пометка «Звук здесь» без кнопки.
- Оптимистично переключать локальный режим не нужно — broadcast приходит мгновенно.

`components/player/mini-bar.tsx`: в режиме `isRemote` бейдж «Пульт» вместо «Джем»
(транспорт и полоса остаются).

`app/(listener)/jam/page.tsx` + `create-jam-button.tsx`: выбор режима перед созданием,
передача в `POST /api/v1/jam`. Дефолт — «В наушниках».
