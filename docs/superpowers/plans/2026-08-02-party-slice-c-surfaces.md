# План — вечеринка, срез C: поверхности и звук (02.08.2026)

Дизайн: `../specs/2026-08-01-party-mode-design.md`. Срезы A (домен, `itemId`,
`addExternalItem`, круговая очередь) и B (резолвер, кэш, `POST /api/v1/jam/[code]/queue/external`,
`GET /api/v1/party/suggest`) — в main. Здесь появляется всё, что видит пользователь.

## 1. Секретный вход

- Константа `PARTY_PATH = '/nrvz914'` в `apps/web/lib/party.ts` — единственное место,
  где строка зашита в коде (кроме имени каталога роута).
- `app/(listener)/nrvz914/page.tsx` — «создать вечеринку» + «войти по коду»
  (переиспользовать `create-jam-button.tsx` / `jam-code-form.tsx`, создание шлёт
  `kind: 'PARTY'`; роут создания сессии из среза A уже принимает `kind`).
- `app/(listener)/nrvz914/layout.tsx` — `robots: { index: false, follow: false }`.
  В `app/sitemap.ts` не добавлять, в `robots.txt` **не упоминать** (Disallow выдал бы путь).
- Вход из футера: тройной клик по «© VireMusic» ведёт на `PARTY_PATH`. Клиентский
  компонент рядом с футером, окно 600мс, без визуальных подсказок и без тултипов.
  Место освободилось после удаления нотного дождя (коммит 51c400c).

Ссылка на комнату (`/nrvz914/[code]`) работает у любого, кому её дали — иначе гости
не войдут по QR. Секретен вход, не комната.

## 2. Комната вечеринки

`app/(listener)/nrvz914/[code]/page.tsx` + `party-room.tsx`. Не форк `JamRoom`:
общие куски (`jam-participants`, `jam-save-playlist`, строка очереди, join-экран)
переиспользуются; расходятся панель добавления, очередь и наличие экрана вечеринки.
Что не переиспользуется без изменений — выносить в общий компонент, не копировать.

**Панель добавления — одно поле на всё:**
- ввод → debounce 250мс → `GET /api/v1/party/suggest` → список: каталог первым,
  подсказки метаиндекса ниже, у каждой строки понятно, играет она из каталога или извне;
- Enter без выбора — отправить строку как есть в `POST …/queue/external`;
- вставка ссылки — сразу отправить, не дожидаясь подсказок;
- ответ `200 {candidates}` — показать выбор, не ошибку. Формулировки «не поддерживается»
  в UI быть не должно ни в одной ветке;
- оптимистично: позиция появляется в очереди сразу, при ошибке снимается с тостом.

**Очередь:** внешние позиции показываются наравне со своими, с бейджем источника
(YouTube/SoundCloud/файл) и снапшотом метаданных; кто добавил — как в джеме.
Сохранение в плейлист берёт только каталожные (гард из среза A) — в UI честно
сказать, сколько позиций пропущено.

## 3. Экран вечеринки

`party-screen.tsx` — режим отображения комнаты на устройстве-колонке (кнопка «Экран
вечеринки», состояние локальное, не в БД): full-bleed, большая обложка **или
видео-поверхность на её месте**, что играет и кто добавил, следующие 3–5 позиций, QR
для гостей. Никаких мелких контролов — это витрина, а не пульт.

Требование ToS YouTube: видео-поверхность ≥200×200 и ничем не перекрыта. На экране
вечеринки это выполняется по построению; на пультах гостей чужого плеера нет вовсе.

Инварианты app-shell соблюдать: **никаких `min-h-screen`/`h-screen`** (тест
`app/__tests__/layout-shell.test.ts`), высоту даёт скролл-область. Экран вечеринки —
не отдельный документ, а состояние страницы.

## 4. Звук: слой источников

`lib/jam/jam-audio.ts` становится диспетчером. Контракт `JamAudioEngine` остаётся тем же
(`load/play/pause/seek/currentTimeMs/isBuffering/onEnded/onPlaying/destroy`) — меняется
только аргумент загрузки:

```ts
type PlayableSource =
  | { kind: 'VIRE'; trackId: string }
  | { kind: 'YOUTUBE'; videoId: string }
  | { kind: 'LOCAL'; fileId: string };
```

- `lib/jam/sources/vire-source.ts` — нынешняя HLS-реализация, вынести как есть.
- `lib/jam/sources/youtube-source.ts` — IFrame API. Контейнер отдаёт экран вечеринки
  через модуль-регистр (как `setJamTransport`): `setPartyVideoContainer(el | null)`.
  **Контейнера нет — источник недоступен**, устройство не может быть колонкой для
  внешней позиции; в UI подсказка «откройте экран вечеринки на устройстве с колонкой».
  `onStateChange → ENDED` маппится в `onEnded`, `getCurrentTime()` — в `currentTimeMs`,
  дрейф правится `seekTo`. Скрипт IFrame API грузится лениво, один раз.
- `lib/jam/sources/local-source.ts` — `<audio>` над `URL.createObjectURL(file)`;
  реестр файлов `lib/party/local-files.ts` (Map в памяти; в Chromium — хэндлы File System
  Access в IndexedDB, в Safari честная пометка «только на эту сессию»). Локальный файл
  добавляет только устройство-колонка: на пультах кнопка не показывается, файл на сервер
  не уходит.

`usePlaybackSync` получает вместо `trackId: string | null` — `source: PlayableSource | null`;
ключ «сменилась позиция» остаётся `playback.itemId`. Провайдер резолвит источник из
активной позиции очереди. `null` (позиция ещё не доехала или источник недоступен на этом
устройстве) — движок простаивает, как сейчас.

Режим: PARTY создаётся в `SPEAKER` — звук на одном устройстве. Экран вечеринки клеймит
спикера при открытии (существующий `POST …/speaker`).

Автоплей на iOS может требовать тапа — на экране вечеринки показывать «нажмите, чтобы
продолжить», когда провайдер отказал в старте.

## 6. Тесты

- Панель добавления: ссылка отправляется сразу; текст идёт в suggest и выбор шлёт
  выбранного кандидата; ответ `candidates` рисует выбор, а не ошибку; ошибка снимает
  оптимистичную позицию.
- Очередь: внешняя позиция рендерится с бейджем и снапшотом метаданных.
- Диспетчер источников: по `source` выбирается нужный адаптер; YOUTUBE без контейнера
  не грузится и не роняет движок; LOCAL с неизвестным `fileId` деградирует молча.
- Экран вечеринки: рендер без активной позиции, подсказка при недоступном источнике.
- Футер: три клика за 600мс ведут на `PARTY_PATH`, два — нет.
- `robots: noindex` у входа; `app/sitemap.ts` не содержит `PARTY_PATH`.
- Инвариант app-shell (`layout-shell.test.ts`) остаётся зелёным.

## Ограничения

- Локальные файлы **в глобальном плеере** (вне вечеринки) — срез D, здесь только на
  экране вечеринки.
- Skip-vote, автодобор из волны, предложка Last.fm — срез D.
- Никакого извлечения аудиопотока: только официальные встраиваемые плееры.
- Комментарии — только неочевидное «почему», 1–2 строки.
