# План — десктоп-клиент, срез 4 (close-to-tray + глобальный хоткей)

Спека: `docs/superpowers/specs/2026-08-16-desktop-shell-slice-4-design.md`.
Продолжает срезы 0-3 (уже в `main`).

## Шаги

1. **Close-to-tray**: в `main.rs`, при создании окна (`WebviewWindowBuilder`) или через
   `window.on_window_event` после `.build()?` — обработать `WindowEvent::CloseRequested`:
   `api.prevent_close(); window.hide().ok();`. Свериться с актуальным API Tauri v2 для
   регистрации обработчика окна (может быть `.on_window_event(move |event| ...)` на билдере
   или на созданном `WebviewWindow` — на усмотрение реализации).
2. **Глобальный хоткей show/hide**: расширить существующий
   `tauri_plugin_global_shortcut::Builder` (срез 1, уже регистрирует медиа-клавиши) —
   добавить `Shortcut` для комбинации (предложение: `Ctrl+Alt+V`, но проверить эмпирически,
   что регистрация не падает из-за конфликта с системным хоткеем — если падает, попробовать
   другую комбинацию, не гадать заранее), в обработчике — `window.is_visible()` →
   `hide()`/`show()+set_focus()`.
3. Не трогать существующую логику пункта трея «Показать VireMusic» — она уже
   show+focus, отдельно от нового хоткея, оба пути должны продолжать работать.

## Проверка

`cargo tauri dev`: клик по крестику окна → окно прячется, процесс жив (проверить
`tasklist`/трей). Нажать хоткей → окно появляется. Повторно нажать хоткей → окно
прячется. Пункт трея «Выход» — процесс реально завершается (не остаётся в `tasklist`).
`cargo tauri build` — сборка не ломается.
