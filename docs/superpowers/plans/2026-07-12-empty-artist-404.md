# §3.4 — 404 пустого артиста: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Прямой заход на `/artists/[slug]` артиста без опубликованных треков отдаёт 404 всем, кроме участников профиля и модераторов/админов.

**Architecture:** Переиспользуем SQL-предикат `artistHasPublishedTrack` (тот же, что прячет из каталога/поиска/sitemap) новой функцией-запросом; решение «кому видно» — чистая функция в `apps/web/lib`; проверка вызывается и из `ArtistPage`, и из `generateMetadata`.

**Tech Stack:** Next.js 15 App Router (RSC), Drizzle, Vitest.

**Spec:** `docs/superpowers/specs/2026-07-12-empty-artist-404-design.md`

## Global Constraints

- Комментарии в коде — почти никогда; только неочевидное «почему» в 1–2 строки.
- Слои: страница не пишет SQL — запросы только в `packages/db/src/queries/*`.
- Никаких `min-h-screen`/`h-screen`; UI тут не меняется вообще.
- Гейты перед коммитом: `pnpm --filter @vire/web typecheck && pnpm --filter @vire/db typecheck && pnpm --filter @vire/web lint && pnpm --filter @vire/web test`.

```ts
export async function artistHasPublishedTrackById(artistProfileId: string): Promise<boolean> {
  const [row] = await db
    .select({ has: sql<boolean>`${artistHasPublishedTrack}` })
    .from(artistProfiles)
    .where(eq(artistProfiles.id, artistProfileId))
    .limit(1);
  return row?.has ?? false;
}

export async function isArtistMember(artistProfileId: string, userId: string): Promise<boolean> {
  const [row] = await db
    .select({ id: artistMembers.id })
    .from(artistMembers)
    .where(and(eq(artistMembers.artistProfileId, artistProfileId), eq(artistMembers.userId, userId)))
    .limit(1);
  return Boolean(row);
}
```

Предикат `artistHasPublishedTrack` переиспользуется как есть (внутри он ссылается на

- [ ] **Step 3: Реализация**

```ts
const PRIVILEGED_ROLES = new Set(['MODERATOR', 'ADMIN', 'SUPERADMIN']);

export function canViewEmptyArtist(opts: { isMember: boolean; role: string | null | undefined }): boolean {
  return opts.isMember || (opts.role != null && PRIVILEGED_ROLES.has(opts.role));
}
```

- [ ] **Step 1: Добавить хелпер видимости в page.tsx**

Импортировать `artistHasPublishedTrackById`, `isArtistMember` (добавить в существующий импорт из `@vire/db`) и `canViewEmptyArtist`. Рядом с `getArtistData`:

```ts
// пустой артист скрыт с витрины (каталог/поиск/sitemap) — прямой заход должен отвечать так же
async function assertArtistVisible(artistProfileId: string): Promise<void> {
  if (await artistHasPublishedTrackById(artistProfileId)) return;
  const session = await auth();
  const userId = session?.user?.id;
  const isMember = userId ? await isArtistMember(artistProfileId, userId) : false;
  if (!canViewEmptyArtist({ isMember, role: session?.user?.role })) notFound();
}
```

Если `session.user.role` не типизирован — посмотреть, как роль читается в других серверных
компонентах (`apps/web/components/nav.tsx`), и использовать тот же доступ; `canViewEmptyArtist`
принимает `string | null | undefined`, каст не нужен.

- [ ] **Step 2: Вызвать в обеих точках входа**

В `generateMetadata` после `if (!data) return { title: 'Не найдено' };`:
