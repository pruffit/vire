# План: P0 — доставка мобильного приложения

Основание: `docs/product/MOBILE_RECONSTRUCTION_ROADMAP.md` §P0.
Цель: APK, который устанавливается на чужой телефон, доходит до боевого бэкенда и не портит
данные пользователя. Продуктовых функций фаза не добавляет.

## Принятые решения

| Решение | Значение | Почему |
|---|---|---|
| `applicationId` | `com.virespace.viremusic` | Выбор владельца. Необратим после публикации |
| Крашрепортинг | Sentry (`@sentry/react-native`) | Один config-плагин, без нативного кода, не завязан на Firebase — переживает смену `applicationId` |
| Нативный проект | Остаётся вне git, генерируется `prebuild` | В `android/` нет ручных правок: `MainActivity`/`MainApplication`/`settings.gradle` — стоковые шаблоны, `modules/glass-lens` подключается автолинком |
| Подпись | Config-плагин + credentials из свойств Gradle | Ручная правка `build.gradle` не переживает `prebuild` — а `android/` не в git |
| Прод-URL | `app.json` → `extra`, не `.env` | `.env` вне git ⇒ сборка невоспроизводима. URL не секрет |
| Сборка | Локальная, скриптом; CI — P5 | Сборка в CI требует keystore в секретах GitHub — действие вне репозитория |

## Работы

### 1. Конфигурация окружения
`lib/env.ts` сегодня падает на `localhost:3000` последним фолбэком `[C]` — в release это
блокируется политикой cleartext, то есть приложение не работает вообще.

Новый порядок разрешения, вынесенный в **чистую функцию** (тестируемо):
1. `EXPO_PUBLIC_API_BASE_URL` — явный override;
2. только в `__DEV__` — LAN-автоопределение (`hostUri` → `scriptURL`) → `localhost`;
3. иначе — `extra.apiBaseUrl` из `app.json` (`https://viremusic.ru`).

Инвариант: **release-сборка не может получить localhost.**

### 2. Идентификатор, версия, ABI
- `app.json`: `android.package`, `android.versionCode`, `version`.
- Config-плагин пишет `reactNativeArchitectures=arm64-v8a,x86_64` — `armeabi-v7a`
  детерминированно ломает CMake на этой машине `[C]`, а на устройствах 2026 года не встречается.
- `newArchEnabled` берётся из `app.json` (сейчас папка рассинхронизирована: `true` в
  `gradle.properties` против `false` в `app.json` `[C]`) — лечится регенерацией.

### 3. Подпись release
Плагин `plugins/with-android-release-signing.js`:
- `withAppBuildGradle` — добавляет `signingConfigs.release`, читающий
  `VIRE_UPLOAD_*` из свойств Gradle, и переводит `buildTypes.release` на него;
- keystore остаётся вне git (`*.jks` в `.gitignore`), пароли — через
  `ORG_GRADLE_PROJECT_*` или `-P`, что готово к CI без изменений.

### 4. Крашрепортинг
Sentry инициализируется из `extra.sentryDsn`. **Без DSN SDK выключен и приложение работает
как раньше** — пустой DSN не должен ронять запуск.

### 5. Предохранитель: протухшая сессия (AU5)
Сейчас `performRefresh()` чистит токены, но UI остаётся в ошибке на каждом экране `[C]`.
`lib/api-client.ts` не должен знать про навигацию, поэтому — событие:
`lib/session-events.ts` (emitter) → `RootNavigator` подписывается → `reset` на `SignIn`.

### 6. Предохранитель: ключ E2EE (SO4)
`/api/v1/keys` хранит **один `ik_pub` на пользователя**; мобильный bootstrap публикует свой
на каждом старте и перетирает ключ веба `[C]`.

Правка минимальная и неразрушающая: перед публикацией прочитать текущий серверный ключ.
- ключа нет **или** он совпадает с ключом устройства → публикуем как раньше;
- ключ есть и **отличается** → **не публикуем**, помечаем чат недоступным на этом устройстве.

Это предотвращает будущий ущерб, но не чинит уже перетёртые ключи — сказать об этом прямо.

### 7. Преflight сборки
Скрипт валидирует перед сборкой: `google-services.json` соответствует `android.package`;
базовый URL — не localhost; подпись настроена. Падает с внятным сообщением, а не молча
собирает нерабочее.

## Что вне объёма

Любая продуктовая функция, редизайн, дизайн-система, экран артиста, отчёт о прослушивании,
обработчики пушей, CI-сборка мобилки, публикация в стор.

## Гейты

`pnpm --filter @vire/mobile typecheck` · `test` · корневой `pnpm test` · `pnpm turbo run typecheck`
+ фактическая сборка release APK и установка на устройство.

## Внешние действия владельца (не закрываются кодом)

1. Зарегистрировать `com.virespace.viremusic` в Firebase (проект `viremusicproject`) и
   заменить `google-services.json` — иначе пуш-токен не выдаётся.
2. Создать проект в Sentry и вписать DSN в `app.json` → `extra.sentryDsn`.
