# План — десктоп-клиент, срез 6 (сплэш-экран)

Спека: `docs/superpowers/specs/2026-08-16-desktop-shell-slice-6-design.md`.
Продолжает срезы 0-5 (уже в `main`, последний коммит 1eb14318).

## Шаги

1. **Сплэш-контент**: минимальный локальный HTML (`apps/desktop/src-tauri/splash/index.html`
   или похожее — не путать с `apps/desktop/frontend-stub/index.html`, который служит
   Tauri-required `frontendDist`-заглушкой для main-окна, не показывается пользователю).
   Тёмный фон (совпадает с платформенным `--background` из design-tokens — можно
   захардкодить значение, копировать пакет сюда избыточно), логотип/название «VireMusic»,
   простой CSS-спиннер. Без внешних сетевых запросов/шрифтов.
2. **`main.rs`**: в `setup()` — создать сплэш-окно первым (без рамки/заголовка, по центру,
   небольшой фиксированный размер), затем главное окно как сейчас, но с `.visible(false)`.
   На главном окне — `.on_page_load(...)`, `PageLoadEvent::Finished` → `window.show()` +
   закрыть/убрать сплэш-окно (`splash_window.close()`).
3. **Проверить эмпирически** взаимодействие с `tauri-plugin-window-state` (срез 5) — не
   засоряет ли сплэш `.window-state.json`; если плагин можно ограничить конкретным лейблом
   окна — сделать так, иначе задокументировать наблюдение в `docs/features/desktop-app.md`.
4. **Single-instance путь** (срез 5) — убедиться, что повторный запуск (фокус существующего
   окна через колбэк) не создаёт сплэш вообще — он живёт только в `setup()`, повторный
   запуск через `tauri_plugin_single_instance::init` туда не заходит, но подтвердить это
   явной проверкой, не только чтением кода.

## Проверка

Собранный `.exe`: холодный запуск — сплэш виден сразу, пропадает при реальной готовности
страницы (не по таймеру). Повторный запуск при уже открытом приложении — сплэш не
появляется. `cargo tauri build` — сборка чистая.
