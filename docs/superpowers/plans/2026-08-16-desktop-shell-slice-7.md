## Шаги

1. **Зависимости**: `cargo add tauri-plugin-updater tauri-plugin-process
   tauri-plugin-dialog` в `apps/desktop/src-tauri/Cargo.toml` (dialog — только если ещё
   не подключён; process — нужен для `app.restart()` после установки обновления).
2. **`tauri.conf.json`**: секция `plugins.updater` — `pubkey` (значение выше буквально),
   `endpoints: ["https://cdn.viremusic.ru/vire-stream/downloads/desktop/windows/latest.json"]`.
3. **`main.rs`**: подключить `tauri_plugin_updater::Builder::new().build()`,
   `tauri_plugin_process::init()`, `tauri_plugin_dialog::init()`. Тихая проверка обновлений
   при старте (не блокирует сплэш/основной поток — асинхронно, после того как главное окно
   уже показано) — если найдено, диалог подтверждения → скачать → установить → `app.restart()`.
   Пункт трей-меню «Проверить обновления» — та же проверка, но с явным результатом (диалог
   «У вас последняя версия», если ничего не найдено) — не дублировать логику проверки,
   вынести в общую функцию, вызываемую и при старте, и по клику.
4. **CI** (`.github/workflows/deploy.yml`, job `build-desktop`): перед `cargo tauri build`
   выставить `TAURI_SIGNING_PRIVATE_KEY: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY }}` в env —
   `cargo tauri build` сам подпишет NSIS-инсталлятор и положит `.sig`-файл рядом
   (стандартное поведение Tauri-апдейтера при наличии этой переменной, свериться по факту
   после сборки, что файл реально появился). Новый шаг после сборки — сгенерировать
   `latest.json` (версия из `github.ref_name`, `pub_date` — текущее время ISO, `notes` —
   можно оставить пустой строкой или ссылкой на GitHub Release, `signature` — содержимое
   `.sig`-файла, `url` — стабильный CDN URL инсталлятора) и залить рядом с инсталлятором
   в тот же `vire-stream`-бакет тем же способом, что уже загружает сам `.exe` (см.
   существующий шаг «Upload installer to MinIO» в том же job'е — расширить его или добавить
   соседний шаг, не дублируя логику подключения к S3).
5. **`docs/features/desktop-app.md`**: дополнить секцией про автообновление — включая
   явную пометку, что сквозная проверка (реальное обновление N→N+1) не тестировалась в
   этом заходе, только компоненты по отдельности (см. спеку).

## Проверка

- `pnpm`-часть не участвует, только Rust/CI.
- `cargo tauri build` локально (без реального `TAURI_SIGNING_PRIVATE_KEY` в окружении —
  просто убедиться, что сборка с новыми плагинами не ломается; подписывать по-настоящему
  будет только CI с секретом).
- Пункт трея «Проверить обновления» — кликается, не роняет приложение, при недоступном/
  фейковом endpoint показывает разумную ошибку (не панику).
- YAML-диф `deploy.yml` синтаксически валиден.
- **Явно задокументировать**, что реальный цикл обновления (скачивание+установка+рестарт
  на найденной новой версии) проверяется только по факту двух живых тегов — не в этом
  заходе, это ограничение, не недоделка.
