## Работы

### 1. Персист состояния
Очередь (усечённая окном), индекс, позиция, shuffle/repeat, контекст. Восстановление
помечает стор `restored`: плеер показывает трек, позицию и длительность, но к движку не
подключён — первый play догружает манифест и продолжает с сохранённой секунды. Ровно
модель веба, чтобы поведение платформ не разъезжалось.

Хранилище — адаптер `lib/storage/file-store.ts` из P1 (форма выбиралась под это).

### 2. Отчёт о прослушивании
Подсистема, а не вызов эндпоинта (`MOBILE_PARITY_MATRIX.md` §15):

```
POST /api/v1/session → подписанный sessionId → персист
проигрывание → накопление ФАКТИЧЕСКОГО времени (пауза не идёт в счёт)
смена трека / стоп / уход в фон → flush
   ├─ сеть есть → POST /tracks/{id}/play
   └─ сети нет  → локальная очередь → отправка при восстановлении
```

Ограничения, каждое из кода веба и воркера:
- `sessionId` только серверный и подписанный — клиентский обесценивает HMAC;
- флаш **в конце** проигрывания, не по нажатию Play;
- `durationPlayedSec` обязан быть фактическим: Волна делит его на длительность трека
  и получает качество дослушивания (`wave.ts:139,158`). Ошибка здесь портит
  рекомендации **всей платформы**, а не только мобильную статистику;
- `source` из перечня — значит стор обязан вести контекст запуска очереди.

Офлайн-очередь событий — требование, которого на вебе нет.

### 3. Аудиофокус
`autoHandleInterruptions` + обработка `Event.RemoteDuck`. Сейчас не настроено ничего:
поведение при звонке неизвестно, а для музыкального приложения это отказ.

### 4. Фуллскрин-плеер — центральная поверхность
Обложка доминирует (контент первичен), транспорт на стекле, три панели:

| Панель | Содержимое |
|---|---|
| Очередь | что дальше, переход по тапу |
| Текст | LRC с подсветкой строки, тап по строке — перемотка |
| Трек | волна по пикам, BPM/тональность, mood-теги, live-счётчик |

Панель «Трек» **заменяет отдельный экран трека** (архитектура §5.3): на телефоне уходить
от воспроизведения, чтобы почитать о том, что играет, — веб-логика. Диплинк на трек ведёт
в плеер.

### 5. Мини-плеер: жесты
Свайп вверх — фуллскрин, свайп вбок — следующий/предыдущий, тап — фуллскрин.
Прогресс rim'ом уже сделан в P1.

### 6. Лайк и шеринг из плеера
Лайк — существующий `LikeButton`. Шеринг — нативный `Share` (на мобилке сильнее веба).

## Вне объёма

экран артиста, перестройка главной.
