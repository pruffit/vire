# План — десктоп-клиент, срез 5 (единственный экземпляр + память окна)

Спека: `docs/superpowers/specs/2026-08-16-desktop-shell-slice-5-design.md`.
Продолжает срезы 0-4 (уже в `main`, последний коммит 84dfc4af).

## Шаги

1. **Зависимости**: `cargo add tauri-plugin-single-instance`, `cargo add
   tauri-plugin-window-state` в `apps/desktop/src-tauri/Cargo.toml`.
2. **`main.rs`**: подключить `tauri_plugin_single_instance::init(|app, _args, _cwd| {...})` —
   в колбэке повторного запуска показать+сфокусировать окно `main` (тот же паттерн, что
   уже есть у пункта трея «Показать» и хоткея среза 4 — не дублировать логику, вынести
   общую функцию show+focus, если её ещё нет, и переиспользовать во всех трёх местах:
   тут, в обработчике трея, в обработчике хоткея). Порядок `.plugin(...)` в цепочке
   builder'а — свериться с документацией плагина, обычно `single_instance` первым.
   `tauri_plugin_window_state::Builder::default().build()` — подключить рядом; проверить
   по факту, нужен ли доп. вызов на созданном окне для восстановления геометрии (актуальный
   API плагина — не полагаться на память, читать реальную документацию/примеры).
3. **Capabilities**: проверить, требуют ли новые плагины permission в
   `apps/desktop/src-tauri/capabilities/default.json` — добавить, если сборка укажет на это.

## Проверка

Два запуска подряд (`.exe` из `target/release` после `cargo tauri build`, не `cargo tauri
dev` — single-instance логичнее проверять на реальном собранном бинарнике, где процесс
запускается по-настоящему заново, а не пересобирается) — второй `tasklist`-процесс не
появляется, первое окно фокусируется (в т.ч. проверить случай, когда первое окно было
свёрнуто в трей). Двигать/ресайзить окно → закрыть через «Выход» → запустить заново →
геометрия восстановлена. `cargo tauri build` — сборка чистая.
