# План: P1 — фундамент мобильного клиента

Основание: `docs/product/MOBILE_RECONSTRUCTION_ROADMAP.md` §P1.
Цель: система, на которой экраны собираются один раз, а не переверстываются после.
Продуктовых поверхностей фаза не строит.

## Почему фундамент идёт до экранов

Дублирование измерено, а не предположено (grep по `screens/` и `components/`):

| Паттерн | В скольких файлах |
|---|---|
| Состояние ошибки (`retryButton`) | 8 |
| Центрированный контейнер (`centered`) | 9 |
| `ActivityIndicator` | 12 |
| Плейсхолдер обложки | 7 |
| Строка трека | 4 |

Плюс `lib/theme.ts` — две строки реэкспорта, из-за чего радиусы и поля разъехались с китом.
Строить артиста, главную и плеер до кита — значит верстать их дважды.

## Принятые решения

| Решение | Значение | Почему |
|---|---|---|
| Где живут шкалы | `apps/mobile/lib/design/`, цвет по-прежнему из `@vire/design-tokens` | В `design-tokens` один базовый `radius: 6`, из которого веб выводит `--radius`. Китовые радиусы (9–12 / 12–16 / 22–28) туда класть нельзя — поедет вся веб-вёрстка |
| Шрифты | `@expo-google-fonts/manrope` + `/jetbrains-mono` | OFL-1.1; кириллица **проверена в самих TTF** (А я Ё ё Ж Щ во всех 7 начертаниях); 0.68 МБ на APK |
| Начертания | Отдельное семейство на вес (`Manrope_700Bold`) | Android не синтезирует веса у кастомных шрифтов надёжно — `fontWeight` на них не работает как в вебе |
| Материал стекла | Только `VireGlassSurface` | Сейчас систем две: измеренное преломление на 4 кнопках таб-бара и плоский `BlurView` на мини-плеере, шитах, поиске, композере |
| Хранение настроек | `expo-file-system` + адаптер в форме `StateStorage` | Уже стоит, есть прецедент (офлайн-индекс). Новая нативная зависимость = новая пересборка и новый риск. P2 переиспользует адаптер для персиста плеера |

## Работы

### 1. Типографика
`lib/design/typography.ts` — семейства и готовые стили из кита: заголовок экрана 800·25–30,
название релиза 800·22, секция 700·14, строка трека 600·12.5, подпись 400·11–11.5@60 %,
мета mono 500·9–10.5. Загрузка через `expo-font` до первого кадра, иначе экран «прыгает».

### 2. Шкалы
`spacing.ts` (поля 20, списки 12, шаг 4/8/12/16/22), `radius.ts` (обложка 9–12,
карточка 12–16, стекло h/2 или 22–28, sheet 30), `motion.ts` (нажатие 120, панель 220,
sheet 280; при «приглушить движение» — 0).

### 3. Примитивы
`Screen`, `Section`, `LoadingState`, `ErrorState`, `EmptyState`, `OfflineBanner`,
`CoverImage`, `TrackRow`, `IconButton` (круглое стекло), `PillButton`, `Chip`, `Skeleton`.
Состав закрывает ровно ту дупликацию, что измерена выше, — не больше.

### 4. Один материал
Мини-плеер и шиты переезжают на `VireGlassSurface`. `components/glass.tsx` уходит из
продового пути (остаётся внутри фолбэка Android < 13 и режима «стекло выключено»).

### 5. Бюджет стеклянных поверхностей

Замер на устройстве: 1–6 поверхностей — 113–120 кадров/с, 7-я — 101. Сегодня инвариант
**нарушается**: поиск + мини-плеер + шит = 7.

Чинится тем, что предписывает сам кит: **пока открыт sheet, нижние поверхности гасят живой
бэкдроп** (они всё равно за скримом). Сценарий 7 → 3.

Два барьера:
- **тест** на объявленной модели (`GLASS_BUDGET` + перечисленные сценарии) — ни один
  достижимый сценарий не даёт > 6;
- **счётчик в рантайме** (`__DEV__`) — ловит расхождение объявленного с фактическим.

### 6. Настройки
Экран с двумя тумблерами кита: «Стеклянный интерфейс» (выключает бэкдроп во всём
приложении — ручной opt-out и аварийный выход для слабых устройств) и «Приглушить
движение» (обнуляет длительности). Оба персистятся.

### 7. Иконки
Добавить недостающие из кита: `share`, `queue`, `lyrics`, `flow`, `bell`, `settings`.

## Вне объёма

Экран артиста, перестройка главной и плеера, отчёт о прослушивании, обработчики пушей,
офлайн-состояния, i18n. Это P2–P5 — фаза даёт только основание под них.
