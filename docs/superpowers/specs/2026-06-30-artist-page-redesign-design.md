# Страница артиста: редизайн + IA (§2.7)

**Дата:** 2026-06-30
**Статус:** черновик на ревью
**Тип:** фронтенд-редизайн контентного экрана + точечный IA + один серверный запрос
**Источник:** `docs/roadmap/stage-2.md` §2.7 — единый дизайн-проход по контентным экранам.
Первый экран из декомпозиции (артист → релиз → трек → плеер).

## Контекст и цель

Три оболочки уже переработаны (админка, дашборд артиста, оболочка слушателя).
Контентные экраны (артист/релиз/трек/плеер) единого дизайн-прохода ещё не получали.
Берём первым **страницу артиста** (`app/(listener)/artists/[slug]/page.tsx`, 549 строк) —
она центральная и задаёт дизайн-язык, который релиз/трек унаследуют.

Цель: поднять визуал, плотность, движение и мобилку; закрыть главный продуктовый
пробел — **со страницы артиста нельзя начать слушать его музыку**; навести единый ритм
секций. Темизация (`--artist-bg/text/accent`) и **все существующие блоки сохраняются**.

**Глубина (закрыто с пользователем):** «Редизайн + право менять IA» — можно менять
порядок/структуру блоков, hero, добавлять аффордансы (play-all, ридаут), но без смелого
ре-концепта и без удаления блоков.

## Решения по продукту (закрыты с пользователем)

1. Глубина — редизайн с правом менять IA (не полиш, не смелый ре-концепт).
2. Темизация и все блоки (Скоро / Релизы / Площадки / Анонсы / Видео) сохраняются.
3. Главная IA-правка — **transport в hero**: запуск каталога артиста в глобальный плеер.

## Что меняем

### 1. Hero → «личность + transport + ридаут»

- Сохраняем темизированный full-bleed hero (аватар + радиальное свечение, grain, fade в контент).
- **Transport-строка:** `[▶ Слушать]` (play-all каталога) + `Follow`. Кнопка «Слушать»
  в темизированном регистре (как `ReleaseHeroPlay`: `bg color-mix(--artist-text 90%)`,
  `color var(--artist-bg)`), физический отклик `whileTap`.
- **Mono-ридаут** (Geist Mono, TE-принцип): `подписчиков · релизов · треков · Σ хронометраж`.
  LED «N слушают сейчас» — только когда >0 (переиспользуем существующий live-механизм
  присутствия, если он уже есть на уровне артиста; иначе пунктом ниже помечено как опц.).
- **Ссылки артиста:** сейчас разнородный ряд (белые брендовые пилюли вперемешку с
  icon+текст) — свести к **одному** консистентному визуальному типу (иконка площадки в
  единой «таблетке», подпись по `title`/`aria-label`). Бренд-варднмарки сохраняем, но в
  одном габарите.
- **Читабельность bio:** заменить `opacity-60` поверх цвета на `color-mix(in oklch,
  var(--artist-text) NN%, transparent)` — убрать «серый текст на цвете» (Impeccable).

### 2. Секции → единый ритм лейбленных модулей

- Сейчас заголовки неконсистентны: у «Площадок» есть `h2`, у «Релизов» — нет.
  Вводим единый паттерн заголовка секции: **mono-eyebrow + волосяная линия** (как
  `NumberedSection`/`Eyebrow` из `content-kit`, но в **темизированном** регистре через
  `--artist-*`, т.к. `content-kit` завязан на платформенные токены `--primary/--border`).
  Лейблы: `Релизы · Скоро · Площадки · Анонсы · Видео`.
- Порядок секций: `Скоро (если есть) → Релизы → Площадки → Анонсы → Видео` (как сейчас,
  но «Релизы» получает заголовок наравне с остальными).
- Переиспользуем без изменений: `ReleaseQuickLook`, `CountdownBadge`,
  `UpcomingPresaveButton`, `VideoPlayer`, `PlatformIcon`/`BrandIcon`.

### 3. Движение и мобилка

- Ревизия `Reveal`/`Stagger`-обёрток по секциям против scroll-jitter (память: дрожание
  от композит-слоёв на постоянных `transform`/`will-change`). Вход оставить, но не держать
  промоутер композита после анимации.
- Transport + ридаут адаптируются на узком вьюпорте (перенос, не горизонтальный скролл);
  тач-таргеты ≥44px; ряд ссылок переносится, не ломая слова.
- Инвариант app-shell: страница остаётся `min-h-full` (не `min-h-screen`/`h-screen`),
  единственный скроллер — `#main-content`. Тест `app/__tests__/layout-shell.test.ts`.

## Архитектура и слои

Работа во фронт-слое + **один новый репо-запрос** для play-all и ридаута.

### Серверный запрос (packages/db)

Новый запрос (например `getArtistPlayableTracks(artistProfileId)` в `queries/`):
возвращает **упорядоченные READY-треки** опубликованных релизов артиста с полями под
`PlayerTrack` (`id`, `title`, `artistName`, `coverUrl` релиза, `artistSlug`, `releaseId`)
плюс `durationSec` (для Σ хронометража) и `trackCount`. Один запрос вместо N клиентских
fetch'ей на релиз. Чистая функция-репозиторий, без бизнес-правил.

- Хендлер/страница (RSC) дёргает запрос → отдаёт `PlayerTrack[]` + агрегаты в hero.
- Кнопку play реализует клиентский компонент (`'use client'`), вызывая
  `controls.play(queue[0], queue, 0)` из `components/player/audio-engine` — как
  `ReleaseHeroPlay`. Никакой бизнес-логики в компоненте.

### Переиспользование (не плодить дубли)

- Play: паттерн `ReleaseHeroPlay` (готовый, темизированный) — расширяем/переиспользуем для
  каталога артиста; не копируем.
- Eyebrow/hairline-заголовок: перенять визуальный паттерн `content-kit`, но в
  темизированном варианте (новый локальный мелкий компонент-хелпер для секций артиста).
- Форматтеры: `apps/web/lib/format.ts` (`formatCount`, `formatDuration`, `totalDuration`,
  `pluralTracks`) — для ридаута. Если нужного нет — добавить туда (с тестом), не инлайнить.

## Краевые случаи

- **Нет READY-треков** (артист без играбельного каталога): кнопка «Слушать» не
  рендерится (как `ReleaseHeroPlay` при пустой очереди); ридаут показывает `треков 0`
  или скрывает Σ. Не показываем неактивную кнопку.
- **Нет аватара:** текущий фолбэк (моно-инициал в круге) сохраняется.
- **Нет bio / нет ссылок / пустые секции:** секции скрываются как сейчас.
- **Длинное имя:** сохранить текущую логику клампа кегля по длине самого длинного слова.
- **Гость:** «Слушать» работает (плеер публичный); Follow ведёт на sign-in (как сейчас).

## Тестирование

- Существующий инвариант `app/__tests__/layout-shell.test.ts` (нет `min-h-screen`) —
  держим зелёным.
- Новый репо-запрос: при наличии тестовой инфры для `queries/` — юнит на отбор только
  READY-треков и порядок; иначе покрыть форматтер-агрегаты (`totalDuration` и пр.) в `lib`.
- Гейты: `typecheck`, `lint`, `check:routes`, `test`, `audit:design` (трогаем UI), `build`.
- Самокритика — независимым сабагентом по VireMusic-чеклисту (мобилка, дубли, jitter, контраст).

## Вне scope (этот заход не делает)

- Релиз/трек/плеер — отдельные циклы §2.7.
- Прямой заход на пустого артиста → 404 (это §3.4, отдельно).
- Любые изменения backend бизнес-логики, схемы БД (кроме одного read-запроса), auth.
- «Популярные треки» как отдельный играбельный список в теле страницы — играбельность
  закрывается play-all в hero; отдельный трек-лист на странице артиста — возможный
  будущий пункт, не сейчас (YAGNI).
