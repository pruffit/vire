# Discovery через людей и вкус (stage-2 §7.4) — дизайн

Дата: 28.07.2026. Сейчас открытие нового держится на подборках (курируемые/личные/
популярные), волне и каталоге артистов. Нет ни одного сигнала «через людей»: похожесть
артистов нигде не считается, друзья влияют только на ленту событий.

## Продуктовые развилки (решены автономно — работа по команде 28.07)

| Развилка | Решение | Почему |
|---|---|---|
| Отдельная страница `/discover` | Нет: секция на главной + блок на странице артиста | `/feed` уже умер от пустоты; на нашем каталоге отдельная страница повторит судьбу |
| Что рекомендуем | **Артистов**, не треки | Треки уже закрыты волной и «Для тебя»; открытие нового имени — то, чего нет |
| Приватность | Друзья влияют агрегированно, без «Маша слушает X» | Персональные лайки уже гейтятся `social_visibility`; поимённая выдача прослушиваний — новый канал утечки, он тут не нужен |
| Прозрачность | Подпись-причина у каждой карточки | Тот же приём, что в ленте: «похоже на …», «слушают ваши друзья», «ваш жанр» |
| Холодный старт | Секция просто не рендерится при < 4 кандидатах | На главной уже есть общая секция «Артисты» — дубль-заглушка не нужна |

## Сигналы

**1. Co-listen (через людей).** Артисты похожи, если их слушают одни и те же люди.
Jaccard по множествам слушателей за 90 дней:

```
sim(A,B) = |listeners(A) ∩ listeners(B)| / |listeners(A) ∪ listeners(B)|
```

Порог: минимум **2 общих слушателя** — с одним пересечением на малой аудитории это шум,
а не сигнал. Само по себе co-listen на маленьком каталоге разрежено, поэтому оно не
единственный сигнал, а старший из трёх.

**2. Вкус (через контент).** Пересечение жанров и настроений артистов, с расширением
жанров до семейств (`GENRE_FAMILY`/`expandGenresToFamilies` уже есть) — иначе «phonk» и
«trap» считаются чужими.

**3. Друзья.** Сколько друзей слушали артиста за 90 дней (агрегат, без имён).

## Ранжирование — чистые функции (`packages/core/src/services/discovery-scoring.ts`)

```
score = coListen * 0.45 + tasteOverlap * 0.35 + friendSignal * 0.20
```

- `coListen` — Jaccard, уже в [0,1];
- `tasteOverlap` — доля совпавших жанров/настроений (после расширения до семейств);
- `friendSignal` = `min(1, друзей_слушавших / 3)` — трёх друзей достаточно для максимума,
  дальше сигнал не растёт (иначе один популярный у компании артист забьёт выдачу).

Причина карточки — по старшему сработавшему сигналу: `friends` → `similar` → `taste`.

Композиция: дедуп, исключение уже подписанных и уже слушанных пользователем артистов,
кап — не более 1 карточки на «источник похожести» (чтобы вся выдача не оказалась
«похоже на одного и того же артиста»), срез до лимита.

## Поверхности

1. **«Похожие артисты»** на `/artists/[slug]` — до 8 карточек, только co-listen + вкус
   (пользователь может быть аноним, друзей нет). Блок не рендерится, если кандидатов < 3.
2. **«Открытия для вас»** на главной, авторизованным — до 12 карточек с подписью-причиной,
   все три сигнала. Не рендерится при < 4 кандидатах.

Карточка — существующий `ArtistCard`, новый компонент не заводим.

## Данные (`packages/db/src/queries/similarity.ts`)

- `getSimilarArtists(artistProfileId, limit)` — co-listen Jaccard за 90 дней + пересечение
  жанров; окно и пороги в SQL, дата считается в SQL.
- `getDiscoveryCandidates(userId, limit)` — кандидаты для главной: похожие на топ-артистов
  вкуса, слушаемые друзьями, совпадающие по жанрам вкуса; исключая подписки и уже
  слушанное.
- Оба под TTL-кэшем (`createTtlCache` из `@vire/core`, 10 минут) — co-listen тяжелее
  обычных выборок, а данные меняются медленно.

## Что не делаем

Отдельную страницу discovery, рекомендации треков (есть волна), матричную факторизацию/ML,
поимённые «кто слушает», рекомендации людей (это §11 и уже есть поиск друзей),
материализованные таблицы похожести (рано: пересчёт по запросу с кэшем дешевле сопровождать).

## Риски

- **Разреженность.** На текущей аудитории co-listen часто пуст — поэтому вкус и друзья
  дают выдаче наполнение, а пороги (2 общих слушателя, 3 друга) не дают шуму выглядеть
  сигналом.
- **Стоимость.** Самопересечение `play_events` — самый тяжёлый запрос в проекте. Ограничен
  окном 90 дней, порогом общих слушателей и TTL-кэшем; секции стоят под `Suspense` с
  `.catch(() => [])`, как остальные, — сбой не роняет страницу.
- **Замкнутый круг.** Популярное рекомендуется чаще → становится популярнее. Смягчение:
  co-listen нормализован Jaccard'ом (а не абсолютом), плюс кап на источник похожести.
