# Страница артиста: редизайн v2 — две колонки + играбельный трек-лист

**Дата:** 2026-06-30
**Статус:** черновик на ревью
**Тип:** фронтенд-ре-концепт контентного экрана + один read-запрос (агрегат plays)
**Источник:** §2.7. Заменяет первый заход (`2026-06-30-artist-page-redesign-design.md`):
тот был сознательно «без смелого ре-концепта» — результат не зашёл (плотно,
центрировано в узкую колонку, не цепляет). Эта рамка снята.

## Проблема (что не так с текущим)

- Контент заперт в `max-w-6xl mx-auto` — на широком экране пустые поля по бокам,
  страница «висит по центру», а не заполняет контентную область.
- Плотно и однообразно: hero + вертикальная простыня секций одинакового ритма.
- Не цепляет: нет мгновенного входа в музыку (только play-all в hero), нет
  «лица» артиста, удерживаемого в поле зрения.

## Решения по продукту (закрыты с пользователем)

1. **Макет — две колонки во всю ширину.** Слева липкая «карточка артиста»
   (аватар, имя, ▶ Слушать, Follow, ссылки, ридаут) — всегда в поле зрения.
   Справа широкая лента контента. На мобилке схлопывается в стопку.
   Никакого узкого центрирования — контент занимает всю ширину области.
2. **Полная свобода контента + новый блок «Популярное»** — играбельный список
   треков артиста прямо на странице (раньше отложен по YAGNI). Можно менять
   порядок и подачу блоков.

## Целевой макет

```
FULL-WIDTH (без узкого max-w; safety-cap ~120rem на ультраширах)
┌──────────────── ambient banner: размытая обложка + accent, во всю ширину ───────────────┐
├─────────────────┬───────────────────────────────────────────────────────────────────────┤
│  (аватар)       │  СКОРО (если есть)   — countdown + presave                              │
│  ИМЯ ✓          │  ПОПУЛЯРНОЕ          — играбельный трек-лист (top-5 + «все треки»)        │
│  ▶ Слушать      │  РЕЛИЗЫ              — сетка обложек во всю ширину                        │
│  ♥ Follow       │  ПЛОЩАДКИ           — смартлинки                                          │
│  bio            │  АНОНСЫ                                                                  │
│  · · ссылки     │  ВИДЕО                                                                   │
│  ридаут (mono)  │                                                                          │
│  (sticky lg+)   │                                                                          │
└─────────────────┴───────────────────────────────────────────────────────────────────────┘
```

- **Сетка (lg+):** CSS grid `grid-cols-[clamp(300px,26%,360px)_1fr]`, gap крупный.
  Левая колонка — `lg:sticky lg:top-0 lg:self-start` внутри `#main-content`
  (единственный скроллер app-shell; sticky работает в нём штатно). Внешний
  контейнер `w-full px-6` без узкого центрирования (опц. `max-w-[120rem]` от
  абсурдной ширины на ультраширах — заполнение визуально полное).
- **Мобилка (<lg):** одна колонка. Левая «карточка» становится верхним блоком
  (аватар → имя → ▶/Follow → bio → ссылки → ридаут), ниже — секции. Тач-таргеты
  ≥44px, без горизонтального скролла (ряды переносятся).
- **Ambient banner:** полноширинная низкая полоса сверху — размытая обложка
  первого релиза + радиальный accent-градиент (как сейчас в hero), fade в `--artist-bg`.
  Grain-aware. Заполняет верх во всю ширину, даёт «лицо», но не давит высотой.

## Что меняем по блокам

### Левая колонка — «карточка артиста» (sticky)
Собирает то, что сейчас размазано по hero: аватар (крупный, accent-обводка/glow),
имя (клампим кегль по длине слова — сохранить текущую логику), `VerifiedBadge`,
bio (цвет через `color-mix(--artist-text …)`, не `opacity` — Impeccable),
`▶ Слушать` (=`ReleaseHeroPlay`, play-all каталога) + `Follow`/`GuestFollowButton`,
ряд ссылок (единый габарит таблеток, бренд-варднмарки на белой подложке — как сейчас),
mono-ридаут (`релизы · треки · Σ хронометраж`; подписчики живут на кнопке Follow).

### Правая колонка — лента, порядок под вовлечение
`Скоро → Популярное → Релизы → Площадки → Анонсы → Видео`. Пустые секции скрыты.
«Популярное» перед «Релизами» — мгновенный вход в музыку (паттерн Spotify-артиста),
затем визуальная витрина обложек.

### НОВОЕ: блок «Популярное» — играбельный трек-лист
- Топ треков артиста по числу прослушиваний. Показываем top-5, кнопка «Все треки»
  (N) раскрывает полный список (клиентский тоггл, без доп. запроса).
- Строка: ранг (mono) / play-индикатор эквалайзера для активного → название
  (+ explicit-бейдж) → длительность (mono tabular) → лайк (`PlayerLikeButton`).
  Клик по строке — играть; повторный по активной — pause/resume (как
  release `TrackRow`). Очередь блока = показанные треки в их порядке,
  `controls.play(queue[i], queue, i)`.
- Новый клиентский компонент `artist-popular-tracks.tsx` (`'use client'`). НЕ
  переиспользуем release `TrackList` — у него другая модель (trackNumber,
  processing/wip/exclusive, ссылка на трек). Переиспользуем мелкие части:
  `PlayerLikeButton`, `controls.play`, `ExplicitBadge`, `formatDuration`,
  индикатор эквалайзера (вынести `PlayingBars` в общий компонент, т.к. будет
  второй потребитель — устранить дубль).

### Сохраняем без изменений (переиспользование)
`ReleaseHeroPlay`, `ReleaseQuickLook`, `CountdownBadge`, `UpcomingPresaveButton`,
`VideoPlayer`, `PlatformIcon`/`BrandIcon`, `SectionHeader`, `GrainOverlay`,
`FadeUp`/`Stagger`, форматтеры (`pluralTracks/Releases`, `totalDuration`,
`formatDuration`), темизация `--artist-bg/text/accent`, шрифты/grain.
`ArtistCollapseBar` — оставляем для мобилки (где карточка уходит из вида);
на lg прячем (sticky-колонка делает её лишней).

## Архитектура и слои

Работа во фронт-слое + **один read-запрос обогащаем агрегатом**.

### Серверный запрос (packages/db)
`getArtistPlayableTracks(artistProfileId)` уже отдаёт READY-треки слышимых
релизов в порядке каталога (свежесть → номер) для play-all. **Расширяем**: добавить
поле `plays` (all-time) через `leftJoin(playEvents)` + `count(playEvents.id)` +
`groupBy(tracks.id, releases.id)`. Порядок выдачи (свежесть → номер) сохраняем —
он остаётся очередью play-all. На странице:
- `playQueue`/ридаут — как сейчас (порядок каталога).
- «Популярное» — копия массива, отсортированная по `plays desc` (tie → исходный
  порядок), top-5 + полный список. Один запрос, два представления. Никакой
  бизнес-логики в компоненте; сортировка отображения — на странице (RSC).

Тип `ArtistPlayableTrack` += `plays: number`. Чистая функция-репозиторий.

### FSD / слои
RSC-страница дёргает запросы (`packages/db`) и сервисы (`packages/core`),
передаёт `PlayerTrack[]` + агрегаты в компоненты. Play — клиентский компонент
через `controls.play`. `packages/core` не трогаем.

## Краевые случаи
- **Нет READY-треков:** «Слушать» не рендерится (как сейчас), блок «Популярное»
  скрыт, ридаут скрывает Σ/треки.
- **Все плейсы = 0 (новый артист):** «Популярное» = треки в порядке каталога
  (tie-order). Блок осмыслен и не пуст.
- **≤5 треков:** кнопка «Все треки» скрыта.
- **Нет аватара / bio / ссылок / пустые секции:** фолбэки и скрытие как сейчас.
- **Длинное имя:** сохранить кламп кегля по длине самого длинного слова.
- **Гость:** «Слушать» работает; Follow → sign-in (как сейчас).
- **Ультраширокий экран:** safety-cap контейнера, чтобы строки не растягивались
  нечитаемо; заполнение остаётся полным.

## Движение и app-shell
- Вход секций — CSS `animate-fade-up` / `Stagger` (де-промоут композита после
  анимации; без висящих `transform`/`will-change` — память про scroll-jitter).
- Инвариант app-shell: страница `min-h-full` (НЕ `min-h-screen`/`h-screen`),
  единственный скроллер — `#main-content`; sticky-колонка — внутри него.
  Тест `app/__tests__/layout-shell.test.ts` держим зелёным.

## Тестирование
- `app/__tests__/layout-shell.test.ts` — зелёный (нет `min-h-screen`).
- Агрегат `plays` и порядок play-all: при наличии тест-инфры для `queries/` —
  юнит на сортировку «Популярного» (plays desc, tie-order) и неизменность
  порядка play-all; иначе вынести сортировку «Популярного» в чистый хелпер
  (`lib/`) и покрыть его юнитом.
- Гейты: `typecheck`, `lint`, `check:routes`, `test`, `audit:design` (трогаем UI),
  `build`.
- Самокритика — независимым сабагентом по VireMusic-чеклисту (мобилка, дубли,
  jitter, контраст, sticky-поведение, тач-таргеты).

## Вне scope
- Релиз/трек/плеер — отдельные циклы §2.7.
- Изменения backend бизнес-логики/схемы БД (кроме обогащения одного read-запроса), auth.
- Серверный пагинированный трек-лист (раскрытие «все треки» — клиентский тоггл по
  уже загруженному каталогу, лимит запроса 300 сохраняем).
