# Spec — фиксы оболочки слушателя (layout)

Бранч: `feat/listener-dashboard-shell`. Источник — 5 багов от пользователя (скриншоты).

## Требования

1. **Сайдбар — collapse в рейл.** Кнопка-тоггл сворачивает сайдбар в узкую полосу
   (~72px) с одними миниатюрами/иконками и разворачивает обратно. Состояние помнится
   (cookie `vire_sidebar=rail|full`, читается на сервере → без вспышки гидрации).
2. **Шапка во всю ширину.** Убрать `max-w-5xl mx-auto`. Лого слева, остальное справа.
3. **Футер во всю ширину**, контент распределён по ширине (убрать центр-кап).
4. **Контент во всю ширину** — на главной, в профиле, поиске, у артиста, релиза, трека:
   расширить тесные `max-w-*` под доступную ширину панели (заполнить пустоту справа),
   добавить колонок в сетки на xl/2xl. Лонгрид/формы остаются читабельной ширины.
5. **Скролл наезжает (десктоп).** Причина: сайдбар был `sticky` внутри ОБЩЕЙ скролл-области
   `#main-content` — не благословлённый паттерн (CLAUDE.md эталон — `admin/layout.tsx`:
   сайдбар закреплён, скроллится только `<main>`). Перевести листенер-оболочку на тот же
   двухпанельный паттерн: на десктопе сайдбар закреплён (flex-панель), скролл — внутри
   `<main data-scroll-area overflow-y-auto>`. На мобиле поведение прежнее (внешний скролл).

## Инварианты / риски

- Никаких `min-h-screen`/`h-screen`. Высоту даёт `h-full` пайплайн (template `h-full`).
- `ScrollState` гасит hover на карточках во время скролла слушая `#main-content`. После
  переноса скролла в `<main>` — обобщить на любой `[data-scroll-area]` (capture-listener),
  иначе вернётся дрожание обложек. Правило `globals.css` — на `.is-scrolling *`.
- Full-bleed герои (артист/релиз/трек) живут вне внутреннего `max-w`-обёртки и тянутся на
  ширину панели — расширение внутренних обёрток их не ломает. У `<main>` НЕТ
  горизонтального паддинга (паддинг дают сами страницы), иначе герои перестанут быть bleed.
- `position: fixed` грейн не ломается: `overflow` не создаёт containing block для fixed;
  template анимирует только opacity (без transform/filter).
