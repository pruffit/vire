# Спека: доступ ко всем тегам «Потока» + ленты без мёртвой зоны

Дата: 14.07.2026. Триггер: фидбэк Danya — «хочу включить boombap, такой возможности нет»
и «зачем мне пустое пространство справа».

## Проблема (замерено на проде, viewport 1920, `main` = 1649px)

| Лента | Элементов | Ширина ряда | Занято | Мёртвая зона справа |
|---|---|---|---|---|
| Чипы «Потока» | 8 | 1545 | 1022 | **523 px** |
| Свежие релизы | 18 | 1593 | 3796 | — (переполняет) |
| Подборки | 6 | 1593 | 1060 | **533 px** |
| Артисты | 5 | 1593 | 640 | **953 px** |

1. **Регрессия доступа (v1.21.0).** `topWaveChips(cap = 8)` режет ряд до топ-8 по
   популярности. `getMoodCounts`/`getGenreCounts` уже возвращают **только теги, у которых
   есть треки в витрине** — то есть Boom Bap в каталоге присутствует, но недостижим с
   главной. Запустить волну по редкому жанру нельзя вообще.
2. **Мёртвая зона.** Карточки лент фиксированной ширины (`w-40`/`w-48`/`w-28`) рассчитаны
   на ~1280px. Каталог маленький (5 артистов, 6 подборок) → на широком экране ряд
   кончается, ширину никто не добирает. Cap=8 на чипах добавил ту же дыру в панель «Поток».

## Решение

### A. Все теги + шит «Все теги» с поиском

- `waveChips(moods, genres)` — **без cap**: все теги каталога, сортировка по `count desc`,
  дедуп по совпадающему лейблу (mood «Эмбиент» vs genre «Эмбиент») сохраняется.
  Ряд снова переполняет ширину → мёртвая зона в панели исчезает, `ScrollRow` листает.
- Первым элементом ряда — кнопка **«Все теги»** → открывает шит: поиск по подписи +
  группировка (**Настроения**, затем жанры по `GENRE_GROUPS`), у каждого тега — счётчик
  треков. Клик = `controls.startWave({ mood | genre })`, шит закрывается.
- **Данные новых запросов не требуют:** `FlowBlock` уже получает полные `getMoodCounts()` /
  `getGenreCounts()`; сейчас они просто отбрасываются после cap.
- Шелл шита — существующий `components/quick-look-sheet.tsx` (портал, Escape,
  drag-to-dismiss). Новый шит не пишем с нуля.
- Логика старта волны по seed (loading-ключ + toast на ошибку) сегодня живёт в
  `wave-chips.tsx`; шит её повторит → выносим в общий хук (`useWaveSeedStart`), оба
  потребителя на нём.

### B. Fluid-ленты: карточка растягивается, когда её соседей мало

Карточкам в `ScrollRow` вместо `shrink-0 w-N` даём `flex: 1 0 <basis>` + потолок `max-w`:
элементов мало → делят свободную ширину и заполняют ряд; элементов много → grow не
срабатывает (свободного места нет), `shrink: 0` держит basis → ряд переполняется и
листается как сейчас.

| Секция | Было | Стало | Проверка при текущем каталоге (1593px) |
|---|---|---|---|
| Артисты | `w-28` | `flex-[1_0_7rem] max-w-[18rem]` | 5 × 288 + 80 = 1520 → ряд заполнен |
| Подборки | `w-40` | `flex-[1_0_10rem] max-w-[16rem]` | 6 × 249 + 100 = 1593 → заполнен |
| Свежие релизы | `w-48` | `flex-[1_0_12rem] max-w-[18rem]` | 18 шт → переполняет, как сейчас |
| Скоро выйдет | `w-40` | `flex-[1_0_10rem] max-w-[16rem]` | — |
| Новое у подписок | `w-40` | `flex-[1_0_10rem] max-w-[16rem]` | — |
| Недавнее (`recent-rail`) | по факту | тот же приём | — |

Потолок обязателен: без него вырожденный ряд из 1–2 карточек растянул бы обложку на
пол-экрана. Остаточный хвост в вырожденных случаях (2 карточки) принимается.

**Скелетоны (`components/home/skeletons.tsx`) получают те же классы** — иначе замена
скелетона на контент при RSC-стриминге даст скачок ширины карточек.

## Границы

- Мобилка не меняется: basis сохраняется, grow срабатывает только при свободном месте.
- `ScrollRow` не трогаем — шаг прокрутки считается по `getBoundingClientRect` детей,
  к fluid-ширине безразличен.
- Скоринг волны, API `/api/v1/wave`, seed-контракт — не меняются.

## Тесты

- `waveChips`: все теги, сортировка по count, дедуп лейблов (обновить существующие на cap).
- Чистые функции шита: группировка тегов по `GENRE_GROUPS` + фильтр поиска.
- Компонентный (jsdom): открытие шита, фильтрация по вводу, клик по тегу → `startWave` с
  нужным seed.
- Гейты: typecheck / lint / test / **audit:design** / build.
