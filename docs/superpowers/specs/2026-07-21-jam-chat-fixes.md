# Спека: багфикс-пачка по фидбеку прода v1.30.x (джем, чат, лейауты, мобилка)

Дата: 2026-07-21. Источник: фидбек Дани после релиза v1.30.1 (скриншоты прода).

## Проблемы и решения

### 1. Джем не синхронизирован с глобальным плеером (P0)

**Симптомы:** нижний плеер показывает старый трек и позволяет запустить второй звук
поверх джема; после «Завершить джем» джем-звук продолжает играть и его нечем остановить.

**Причины:** `jam-audio` — отдельный `Audio` элемент; глобальный плеер ставится на паузу
один раз при join (`controls.pause()` в `jam-room.tsx`), дальше ничем не блокируется.
При `ended` `usePlaybackSync` не гасит движок (гаснет только при размонтировании).

**Решение — «jam takeover» глобального плеера:**
- В player store — поле `jamOverride: { code, track: {title, artistName, coverUrl}, isPlaying, } | null` + модульный регистр `jamControls: { toggle } | null`.
- Пока override активен: MiniBar рендерит джем-трек (бейдж «ДЖЕМ»), play/pause шлёт
  джем-команду; кнопки очереди/волны/шаффла глобального плеера скрыты; сам глобальный
  движок остановлен (и его `toggle` в режиме override роутится в джем).
- `jam-room` ставит override при активном звуке джема (audioEnabled) и чистит при
  ended/unmount/выключении звука.
- При `ended === true` `usePlaybackSync` получает `audioEnabled=false` → движок
  destroy() немедленно, звук стопается у всех.
- Запуск глобального воспроизведения из другого UI при активном джем-звуке на этой же
  странице невозможен (mini-bar в режиме джема); джем-аудио живёт только на странице
  джема — при уходе со страницы движок и так дестроится, override чистится.

### 2. Транспорт джема — всем участникам (продуктовое изменение)

Сейчас play/pause/seek/track — только HOST (`setPlayback`: `hostUserId !== userId → 403`).
Меняем: транспорт разрешён **любому участнику** (юзер или гость — та же идентичность,
что у мутаций очереди). Кик/завершение — по-прежнему только HOST. Автопереход по
`ended` трека — по-прежнему инициирует хост (анти-гонка).

Плюс кнопка **«Перемешать»** очередь: новая мутация `{ kind: 'shuffle' }` в
`applyQueueMutation` (сервер тасует Fisher-Yates, поднимает version, бродкастит) —
доступна любому участнику.

### 3. Участник не появляется без refresh

`join` не бродкастит `jam:participants`. Фикс: после успешного join (и leave, если
есть) сервис бродкастит свежий список участников в канал джема.

### 4. Лейаут джем-комнаты: центр → полная ширина

Убрать `mx-auto max-w-4xl`. Десктоп (lg+): грид `[1fr_360px]` —
слева now-playing бар + очередь, справа постоянная панель добавления (поиск + «Из
любимых», без кнопки-тоггла) и участники. Мобилка: одна колонка, кнопка «Добавить
трек» остаётся тогглом.

### 5. Мобильный джем-UX

- Строки очереди крупнее (min-h ≥ 56px), drag-handle — touch-target ≥ 44px,
  drag только за handle (activator), чтобы скролл не конфликтовал.
- Шапка комнаты на мобилке компактная: кнопки в один ряд иконками, без переноса
  «Сохранить в плейлист» в две строки.

### 6. «Любимые треки» (и плейлисты) — пустая ширина

`max-w-3xl` → full-bleed паттерн контентных страниц (фидбек: контент на всю ширину).
Хедер и список используют ширину области с адекватными паддингами.

### 7. Чат: разделители и активный диалог

Видимые разделители между диалогами (`divide-y` по `border/…`), активный диалог —
контрастнее (фон + акцентная полоса слева), непрочитанный — жирнее.

### 8. Чат: убрать плашку E2EE

Блок `<details>` «Сквозное шифрование — код безопасности» удалить из треда полностью
(вместе с вычислением safety-number, если больше нигде не используется). E2EE остаётся,
просто без UI-кода безопасности.

### 9. Чат: typing-индикатор

`POST /api/v1/chat/[conversationId]/typing` (throttle на клиенте ~2.5с при вводе) →
`publish(toUserId, { type: 'chat:typing', conversationId, userId })`. Тред показывает
«печатает…» в шапке 4с после последнего события (сбрасывается по приходу сообщения).
Без БД, чистый realtime; при недоступности Redis просто не работает.

### 10. Чат: статус «Прочитано»

- `markRead` дополнительно публикует второй стороне `{ type: 'chat:read', conversationId, readAt }`.
- История/мета треда отдаёт `otherLastReadAt` — под последним своим сообщением
  отправитель видит «Прочитано» (если `createdAt <= otherLastReadAt`), иначе
  «Отправлено». Live-обновление по событию.

### 11. Чат: получатель узнаёт о сообщении сразу

- В payload события `message` добавить `senderName`.
- Глобальный клиентский слушатель (в shell): событие `message` для диалога, который
  сейчас НЕ открыт → toast «Сообщение от {имя}» + live-обновление бейджей
  (сайдбар + мобильный таб-бар) через рефетч `GET /api/v1/chat/unread-count` (новый
  лёгкий роут). Открытие /messages сбрасывает как раньше (markRead).
- Web-push (закрытая вкладка) — вне скоупа, ждёт VAPID на VPS (см. память).

### 12. Мобильная навигация: 6 табов → 4

Оставить: Главная, Поиск, Медиатека, Сообщения (с бейджем). «Друзья» и «Джем» живут
внутри Медиатеки (строки уже есть в library; проверить мобильную страницу /library —
обе строки должны быть). Бейдж входящих заявок друзей переносится на таб «Медиатека»
(точка), чтобы сигнал не потерялся.

### 13. PWA

`display: standalone` уже есть. Добавить `appleWebApp` метаданные. Скрыть хром браузера
во вкладке невозможно — только установка на экран (донести в отчёте).

## Вне скоупа
- Web-push/VAPID.
- Дубли треков в очереди джема (осознанно разрешены).
- Группы/вложения в чате.
