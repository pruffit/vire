# Спека: багфикс-пачка чат/E2EE/профиль/push (2026-07-20)

Претензии пользователя (скрины прода v1.28.x): пустой чат-экран с футером под ним,
E2EE блокирует переписку («у собеседника не настроено шифрование», «подтвердите
устройство»), привязка устройства не срабатывает, карточки «Подписки» в профиле
ломаются, тумблер push падает с ошибкой.

## Root cause

| # | Симптом | Причина |
|---|---|---|
| 1 | Пустота в чате, футер под диалогом, композер за краем | На мобилке цепочка высот рвётся: `(listener)/layout.tsx` даёт `min-h-full` (не `h-full`) → `h-full` страницы диалога схлопывается. Футер рендерится под чатом на всех вьюпортах. Пустой тред — чёрный void без empty-state |
| 2 | «У собеседника ещё не настроено шифрование» | Личность E2EE бутстрапится только при заходе на `/messages` (useIdentity в чат-компонентах). Собеседник, не открывавший сообщения, не имеет ikPub — писать ему нельзя |
| 3 | «Привязать это устройство» не работает | Слушатель `link-request` (сторона A) живёт только в `DeviceLink` на странице списка `/messages`. Если на настроенном устройстве открыт диалог или любая другая страница — запрос никто не ловит; новое устройство молча поллит 3 мин и падает. Плюс нет никакого статуса ожидания на стороне B |
| 4 | «верифицирован» вылезает за карточку | `FollowedArtists` grid-cols-3 в колонке 360px → карточка ~104px; слово неразрывное, без truncate |
| 5 | «Не удалось изменить push-уведомления» | `subscribeToPush`: `serviceWorker.register` и `pushManager.subscribe` вне try/catch → любое исключение (недоступный push-сервис FCM, кривой VAPID из env с пробелом) валится в общий catch без диагностики |

## Требования

1. **Чат-экран app-like**: на `/messages/[id]` футер скрыт, тред занимает всю
   доступную высоту на мобилке и десктопе, композер прижат к низу и всегда виден.
   Пустой тред — дружелюбный empty-state. Инварианты app-shell не нарушать
   (без `h-screen`/`100vh`; скролл-область — не flex).
2. **E2EE не блокирует**: ключи публикуются при любом заходе залогиненного юзера
   (глобальный бутстрап-компонент в layout). На «у собеседника нет ключа» — поллинг
   ключа, композер оживает сам, копия текста объясняет ситуацию.
3. **needsLink — не тупик**: рядом с «Привязать это устройство» — fallback
   «Сбросить шифрование» (новая личность, ikPub перезаписывается) с явным
   предупреждением, что старая переписка станет нечитаемой у обеих сторон.
4. **Привязка работает откуда угодно**: A-сторона (approve UI + слушатель
   link-request) монтируется глобально в (listener) layout как оверлей;
   B-сторона показывает статус ожидания и кнопку отмены, а не молчит.
5. **Подписки в профиле**: карточки не ломаются на узкой колонке — адаптивный grid
   (auto-fill/minmax), «верифицирован» → иконка-чек (sr-only текст) или truncate.
6. **Push**: пошаговые catch с конкретными причинами в тостах (permission / SW /
   push-сервис недоступен / сервер), trim VAPID, guard на отсутствие Notification.

## Не делаем

- Не трогаем джем (`/jam` имеет ту же болячку высоты — отдельный фикс в ветке джема).
- Не меняем криптосхему (single identity key, deriveCK) — только UX вокруг.
- Оффлайн-очередь сообщений «до появления ключа» — нет.
