# Джем: пачка багфиксов (мобилка, добавление, реордер, единый плеер, качество звука)

Дата: 2026-07-29. Источник — репорт Danya со скриншотами (320px вьюпорт).

## Проблемы и решения

### 1. Шапка комнаты ломается на узком экране
`jam-room.tsx` header — одна строка `flex items-center gap-3`: слева `min-w-0 flex-1`
(статус/название/код), справа `shrink-0` группа из 5 кнопок (≈220px). На 320px левая
часть схлопывается: «В сети» переносится по слогам, `h1` в ноль, код уезжает.

**Решение:** на `<sm` шапка в две строки — сверху статус + название + код, снизу ряд
действий. С `sm` — прежний однострочный вид.

### 2. Нет индикатора «трек добавлен» → бесконечные дубли
`JamAddPanel` не знает про очередь; каждый тап по «+» шлёт новый `add`. Дубли в очереди
разрешены на уровне БД, но UI никак их не отражает, и `isActive`/`isPlaying` в строках
матчатся по `trackId` — при дублях подсвечиваются ВСЕ копии сразу («запустятся
одновременно» из репорта — это визуал, звук один).

**Решение:**
- `JamAddPanel` получает `addedTrackIds: ReadonlySet<string>`; строка уже добавленного
  трека — галочка вместо «+», кнопка `disabled`, приглушённая.
- `handleAdd` в комнате игнорирует повтор (защита от гонки двойного тапа).
- Серверный контракт не трогаем (дубли из старых джемов остаются валидными).
- Подсветка активной строки — по индексу первого совпадения `trackId`, а не по всем.

### 3. Панель поиска закрывается только повторным тапом по кнопке
На `<lg` панель рендерится инлайном под кнопкой (`{adding && …}`) — ни клика вне, ни Esc.

**Решение:** на мобилке — `components/sheet.tsx` (готовый: Esc, тап по подложке,
свайп вниз, портал в body). Десктопный `aside` с инлайновой панелью не меняется.

### 4. Лишние контролы перемещения
`SortableTrackRow` на `pointer-coarse` рисует drag-handle + пару шевронов вверх/вниз +
номер — три контрола на строку, каша (скриншот 3).

**Решение:** шевроны убрать из компонента целиком вместе с пропами
`onMoveUp/onMoveDown/canMoveUp/canMoveDown` и вызовами в трёх местах (джем, плейлисты,
трек-менеджер релиза). Перемещение — только drag-handle (TouchSensor delay 180ms уже
настроен, клавиатурный сенсор остаётся для a11y). Убираем везде, а не только в джеме —
компонент общий, иначе UI разъедется между экранами.

### 5. У джема два плеера
В комнате есть собственный бар «сейчас играет» (обложка/статус/play), и одновременно
глобальный мини-бар в режиме `jamOverride` (бейдж «Джем», одна кнопка). Дублирование.

**Решение:** внутрикомнатный бар удалить. Глобальный мини-бар в режиме джема становится
полноценным транспортом: обложка, название + бейдж «Джем», артист, prev/play-pause/next,
полоса прогресса с перемоткой, тайминги на `sm+`, громкость как обычно.

Механика: `lib/jam/jam-controls.ts` из одиночного `toggle` превращается в регистр
транспорта `{ toggle, next, prev, seek(ms), positionMs(), durationSec }`, который
регистрирует `jam-room`. Позиция читается мини-баром по rAF-тику (как `useAudioTime`),
а не гоняется через стор. `jamOverride` в сторе получает `durationSec`, `canPrev`,
`canNext`. Перемотка и переключение трека шлют обычные `POST playback` — права
позволяют любому участнику, все услышат синхронно.

Прогресс-полоса выносится из `mini-bar.tsx` в переиспользуемый компонент
(`position`/`duration`/`onSeek`) — общий для обычного режима и джема.

### 6. Заметно худшее качество звука в джеме
Источник тот же (единственный HLS-рендишен, тот же `manifest-cache`, тот же
`HLS_TUNING`). Отличие ровно одно: джем правит дрейф через `playbackRate` с
`preservesPitch: true` — браузер включает тайм-стретч, а `RATE_DELTA = 0.03` (±3%) даёт
слышимый «подводный»/металлический артефакт. Хуже того, коррекция держится, пока
`|drift| ≥ 50мс`: при систематическом смещении оценки часов клиент может ехать на 1.03
почти постоянно, т.е. вся сессия звучит через тайм-стретчер.

**Решение** (`packages/core/src/services/jam-sync.ts`):
- `RATE_DELTA` 0.03 → **0.01** (±1% — практически неслышимо).
- `RATE_CORRECT_MIN_MS` 150 → **200**, `CONVERGED_MS` 50 → **60** (мёртвая зона шире,
  гистерезис сохраняется).
- Новое: `RATE_STUCK_MS = 20000` — если коррекция rate идёт непрерывно дольше 20с и не
  сошлась, делаем жёсткий seek и возвращаем rate=1 (лечит систематическое смещение,
  из-за которого сессия жила на warped rate). В `DriftDamperState` добавляется
  `msInRateCorrection: number | null`, ведёт его `use-playback-sync`.

Плюс мелочь того же ряда: `createJamAudio` игнорирует громкость плеера — ползунок в
мини-баре в режиме джема ничего не делает. Движок берёт `volume` из `usePlayerStore` при
создании и подписывается на изменения.

## Риски

- Убранные шевроны — регресс доступности реордера на таче, если drag-handle окажется
  неудобным; сознательный размен по требованию.
- Ослабленная коррекция дрейфа: расхождение до ~200мс между устройствами считается
  допустимым (было 150мс), сходимость медленнее (1%/с). Порог жёсткого seek (2с) прежний.
