# 1-I: бандл/перфоманс — дизайн

Кусок 1-I из нарезки §1 (`2026-07-12-stage2-refactor-slicing-design.md`):
ревизия зависимостей, динамические импорты, LCP-проход. Поведение UI — 1:1,
меняется только момент загрузки некритичных ресурсов.

## Базлайн (Next 16.2.7, Turbopack, прод-сборка, главная `/`)

Измерено на standalone-сервере (`page-weight`-скрипт по HTML + Link-заголовку):

- **JS главной:** 18 файлов, **982 kB** (uncompressed), HTML 178 kB.
- **Шрифты:** Link-заголовок прелоадит **23 woff2, 491 kB — на каждой странице.**
  Это Geist Sans/Mono (нужны) + 8 шрифтов темы артиста с дефолтным `preload: true`
  (`inter, montserrat, unbounded, manrope, geologica, jetbrains-mono, fira-code,
  ibm-plex-mono` × сабсеты latin+cyrillic). Остальные 10 шрифтов каталога уже
  `preload: false`.

## Ревизия зависимостей — закрыта инвентаризацией, правок нет

Все 28 зависимостей apps/web используются; мёртвых нет. `hls.js` уже лениво
(`import()` в `lib/player/audio-engine.ts`), `Player` уже за `dynamic(ssr:false)`
(`player-wrapper.tsx`), S3/BullMQ/ioredis — server-only, в клиентский бандл не
попадают. `experimental.optimizePackageImports` для `motion` — рассмотрено и
**отвергнуто**: `motion/react` — ESM без баррель-проблемы, Turbopack tree-shaking
достаточно; экспериментальный флаг без измеренного выигрыша не берём.

## Изменение 1: шрифты темы артиста — `preload: false`

`lib/fonts.ts`: перенести 8 шрифтов (inter, montserrat, unbounded, manrope,
geologica, jetbrainsMono, firaCode, ibmPlexMono) в группу `preload: false` —
той же строкой конфига, что у существующих 10 опциональных. Geist Sans/Mono
(в `app/layout.tsx`) не трогать — это шрифты платформы.

Эффект: прелоад ~23 → ~5 файлов; ~400+ kB шрифтов уходят с критического пути
каждой страницы (они конкурировали за канал с LCP-обложкой). Поведение: шрифты
тем по-прежнему объявлены `@font-face` через CSS-переменные и грузятся при
использовании на странице артиста — ровно как остальные 10 опциональных.
Это и есть LCP-проход: `priority` на hero-изображениях уже расставлен
(главная, артист, релиз — проверено инвентаризацией), FeaturedRelease уже без
opacity-анимации.

## Изменение 2: некритичные root-layout виджеты — за `dynamic(ssr:false)`

`CommandPalette` (184 стр.), `Announcements` (220 стр.), `EasterEggs` (200 стр.),
`CookieBanner` — все монтируются в `app/layout.tsx` безусловно, но на первом
пейнте не рендерят ничего (hotkey/localStorage/konami-гейты; у CookieBanner
серверный снепшот `useSyncExternalStore` = false). Убрать их из критического JS
по паттерну `components/player/player-wrapper.tsx`:

- Новый `components/deferred-widgets.tsx` (`'use client'`): четыре
  `dynamic(() => import('./…').then(m => m.X), { ssr: false })` + один экспорт
  `DeferredWidgets`, рендерящий все четыре.
- В `app/layout.tsx` четыре импорта заменить на один `<DeferredWidgets />`
  (позиция в дереве — там же, после Toaster; Toaster не трогать — тосты могут
  быть нужны сразу).

Проверено: `OPEN_ANNOUNCEMENT_EVENT`/`PARTY_EVENT` используются только внутри
своих модулей — внешних статических импортов, которые вернули бы модули в
критический граф, нет. Допустимая разница: кука-баннер/консоль-пасхалка
появляются на долю секунды позже (после догрузки чанка) — принято; слушатели
событий/хоткеев вешаются после гидрации, как и раньше.

## Не трогаем (осознанно)

- `app/template.tsx` fade-in на переходах — продуктовое решение (живость UI),
  opacity-only, layout не дёргает.
- `Nav`/`NavSearch`/`MobileTabBar`/`Toaster` — видимый или мгновенно нужный UI.
- `modularizeImports` для `@aws-sdk` — server-only код, клиентский бандл не трогает.

## Отклонения при реализации (приняты)

1. **Порядок в дереве** — `<DeferredWidgets />` стоит в `app/layout.tsx` ДО
   `Toaster`, а не после, как планировалось в разделе «Изменение 2». Причина:
   единый узел `DeferredWidgets` рендерит все четыре виджета одним местом в
   дереве — сохранить точную позицию каждого из четырёх исходных импортов
   (часть до Toaster, часть после) невозможно без разбиения на несколько
   вставок. Порядок DOM-соседей на стекинг не влияет — у всех четырёх
   виджетов явный `z-index` в диапазоне 60–100.
2. **`AnnouncementReopenLink`** — компонент по-прежнему рендерит ссылку без
   проверки существования id в `ANNOUNCEMENTS` (не возвращает `null` для
   неизвестного id, как было в исходном плане на уровне рефакторинга данных).
   Массив `ANNOUNCEMENTS` остался в тяжёлом модуле `announcements.tsx`, а
   подпись кнопки переехала в `footer.tsx` как `children` — так футер не
   импортирует тяжёлый модуль напрямую. Оба используемых id (`fnf`, ...из
   футера) существуют в `ANNOUNCEMENTS` на момент правки; риск рассинхрона
   id между футером и данными латентный и принят — при появлении нового
   анонса с кнопкой в футере проверять id руками.

## Итоги реализации

**Коммиты:** `cef38fe` (шрифты + deferred-widgets + layout.tsx),
`8721808` (фикс `footer.tsx` — вынос триггеров/констант в
`components/widget-triggers.tsx`).

**Шрифты:** прелоад 23 файла/491 kB → 3 файла/67 kB (−424 kB критического
пути на каждой странице) — остался только Geist Sans/Mono. Шрифты темы
артиста грузятся как раньше при использовании на странице артиста.

**JS главной:** критический JS 982 → 962 kB. Тела всех четырёх виджетов
подтверждены грепом по чанкам как отложенные (в критическом HTML не
встречаются).

**Находка при реализации:** инвентаризация перед I1 грепала импорты
`CommandPalette`/`Announcements`/`EasterEggs`/`CookieBanner` только по
алиасному пути (`@/components/...`) и не нашла обратных ссылок из
`footer.tsx`. Файл на деле статически импортировал
`AnnouncementReopenLink`/`PartyText` **относительным** путём
(`./announcements`, `./easter-eggs`) — эти импорты тянули тела обоих модулей
обратно в критический граф через footer, несмотря на то что сами виджеты
были уже за `dynamic(ssr:false)`. Обнаружено на измерении после I1 (чанки
не отделились), исправлено в `8721808` выносом триггеров/констант событий в
лёгкий `components/widget-triggers.tsx`. **Урок:** греп статических
импортов перед вынесением модуля за `dynamic` вести по обоим видам путей —
алиасному и относительному, — а не только по одному.

**Гейты:** typecheck×3, lint, check:routes, 668 тестов, build — все зелёные.

**Самокритика:** 2 MINOR-находки (см. «Отклонения» выше), обе приняты без
правок кода.
