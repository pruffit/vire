# QA-батч v1.12 — спека

Дата: 2026-07-05. Источник: QA-скриншоты Дани (ПК).

## 1. Чипы «Поток» не листаются на ПК (баг)

`components/home/wave-chips.tsx` — ряды mood/genre-чипов: `overflow-x-auto no-scrollbar`.
На таче свайп работает, на десктопе листать нечем (только shift+wheel, неочевидно).

**Решение:** переиспользуемый клиентский компонент `ScrollRow` (стрелки-шевроны по
краям, только desktop/hover-устройства, видны когда есть переполнение, disabled на
краях, `scrollBy` ±80% ширины, smooth). Применить к обоим рядам чипов и к рейлу
«Новое у подписок» на главной (тот же паттерн no-scrollbar).

## 2. /releases — «очень много» (UX)

Страница грузит и рендерит 60 релизов одной сеткой.

**Решение:** прогрессивный показ — первые 24, кнопка «Показать ещё» (+24, клиентский
слайс уже загруженных данных). Серверный лимит 60 не трогаем.

## 3. «Дыра» — горизонтальный сдвиг всего документа (баг)

Скриншот: логотип обрезан до «RE», от свёрнутого сайдбара виден огрызок с бордером —
весь UI сдвинут влево на ~44px. Root cause: `body { overflow: hidden }` остаётся
программно скроллируемым контейнером (scrollIntoView/фокус элемента за правым краем —
например transform-анимация въезда справа создаёт scrollable overflow). Скроллбара
нет → юзер не может вернуть. Воспроизводится редко, но залипает намертво.

**Решение:** `overflow-clip` вместо `overflow-hidden` на body (clip не создаёт
скролл-контейнер — программный скролл невозможен в принципе); дополнительно
`overflow-x-clip` на `[data-scroll-area]` и `#main-content` (вертикальный скролл
сохраняется). Обновить инвариант `app/__tests__/layout-shell.test.ts`.

## 4+5. Анализ жанра по требованию (дашборд артиста + админка)

Пайплайн auto-genre уже сохраняет топ-5 в `track_audio.genre_suggestions` при
транскодинге (за флагом `AUTO_GENRE`). Но треки, залитые до фичи/без флага, без
предсказаний, и перезапустить анализ нельзя.

**Решение:**
- Новая BullMQ-очередь `analyze-genre` (job `{ trackId }`, jobId-дедуп
  `analyze-genre:{trackId}`): воркер скачивает source из S3 во временный файл,
  гоняет `classifyTrackGenre`, сохраняет топ-5 в `genre_suggestions`, применяет
  `decideAutoApplyGenres` (та же политика: только если жанров нет). Флаг
  `AUTO_GENRE` НЕ проверяется (явный запрос юзера); нет модели → ошибка в лог,
  джоб падает штатно.
- API артиста: `POST /api/v1/dashboard/tracks/[id]/analyze-genre` (ownership,
  202 + enqueue), `GET .../genre-suggestions` (для поллинга).
- API админа: `POST /api/v1/admin/tracks/[id]/analyze-genre`, `GET` аналогично
  (MODERATOR+). Имена динамических сегментов — как у соседей!
- UI дашборда: в `GenrePicker` кнопка «Определить жанр» (когда предсказаний нет)
  / иконка повторного анализа (когда есть); поллинг до появления результата,
  таймаут ~2 мин с тостом.
- UI админки: в редакторе трека блок «Предложено моделью» — пилюли топ-5 с % 
  уверенности, клик добавляет жанр (лимит 3), кнопка «Проанализировать».
- Общий код поллинга/кнопки — один хук, не копипаста между дашбордом и админкой.
- Обновить `docs/features/auto-genre.md`.

## 7. Алгоритмические подборки — перепроверка + рефакторинг

Найденные проблемы механики (по коду и скриншоту):
- Дубль настроений: общая MOOD-подборка «Для дороги» и личная «Для дороги — для
  тебя» сосуществуют на главной — одно настроение двумя карточками.
- Мусорные личные подборки по 3 трека («Для дороги — для тебя», 3 трека).
- Логика выбора треков по mood/genre + ранжирования размазана дублями внутри
  `editorial.ts` (`moodTrackIds`/`personalMixTrackIds`).

**Решение:**
- Личные mood-подборки пропускают настроения, уже занятые общими MOOD-подборками
  текущего прогона (берём следующие из профиля вкуса).
- Личная подборка не создаётся, если < 5 треков.
- Извлечь чистую политику (какие mood брать, порог размера) в отдельный модуль
  с юнит-тестами; консолидировать выбор треков по mood/genre в одну функцию.
- Обновить `docs/features/curated-playlists.md`.
