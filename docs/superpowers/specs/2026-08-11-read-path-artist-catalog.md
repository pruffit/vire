# Спека: read-path каталога артистов (волна 2, шаг 2.4)

**Основание:** `docs/migration-plan.md` §волна 2 · клон механики шага 2.3 (каталог релизов).

## Проблема

`/artists` (`app/[locale]/(listener)/artists/(catalog)/page.tsx`) зовёт `listActiveArtists()`
из `@vire/db` напрямую и отдаёт весь список в `ArtistCatalog`, который фильтрует по жанрам на
клиенте. HTTP-эндпоинта каталога артистов нет — у мобильного клиента нет входа в витрину
артистов, хотя детальный экран (`/v1/artists/{slug}/page`) уже есть с шага 2.1.

## Решение

Одна реализация, два входа:

1. `ArtistCatalogService` в `@vire/core` за портом `IArtistCatalogRepository`.
2. Страница `/artists` вызывает сервис в процессе.
3. Новый `GET /api/v1/artists` вызывает тот же сервис.
4. Контракт запроса и ответа в `@vire/api-contracts` + contract-тест.

Тип карточки — `ArtistCard` в core (зеркало `ArtistListItem` из db, который становится его
алиасом), схема `artistCardSchema` в общем `catalog.ts` контрактов.

**Пагинация и поиск.** Порт принимает `{ query, limit, offset }`; `listActiveArtists` получает
`limit`/`offset` и уникальный тайбрейкер `artistProfiles.id` (сегодня сортировка только по
`lower(name)` — тёзки при листании дублировались бы и терялись). Сервис просит `limit + 1` и
отдаёт `{ items, hasMore }`.

**Потолки.** У HTTP-входа `limit` 1…60 (выход за границы — 400), у сервиса кламп 1…200.
Разные потолки намеренные: роут — постраничная выдача, страница — витрина с клиентской
фильтрацией по жанрам, ей нужен весь список сразу. Страница запрашивает 200 и это её
фактический предел: при росте каталога сверх 200 она должна переехать на серверную
фильтрацию/подгрузку, отрисовка 200+ карточек и сегодня не бесплатна.

## Границы

- Видимость (`isActive` + «есть трек в опубликованном релизе») уже внутри `listActiveArtists` —
  новых правил не вводим и существующие не дублируем.
- Разметка и клиентский фильтр по жанрам не меняются. Счётчик в шапке показывает `N+`, когда
  каталог упёрся в потолок, — иначе он врал бы ровно в тот момент, когда потолок начнёт резать.
- `listActiveArtists` не удаляется: её зовёт главная (`home-sections.tsx`).
- Поиск людей и `/search` не трогаем — другой ресурс.

## Проверка

Гейты core/db/web + contract-тест роута. Сверка «до/после»: `/artists` даёт тот же состав,
порядок и счётчик; фильтр по жанрам работает как раньше.

## Откат

Один revert: страница возвращается к `listActiveArtists`, роут удаляется.
