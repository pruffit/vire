# VireGlass Material v1 + Material Lab — спека и дизайн

**Дата:** 29.08.2026 · **Фаза:** VireGlass Phase 3
**Вход:** ADR-001 (KEEP CURRENT IMPLEMENTATION), `docs/vireglass/architecture.md`,
замер `benchmarks/2026-08-28-scaling-device-release.md`.

---

## 1. Что решаем

Сегодня VireGlass — набор эффектов с константами, разбросанными по трём местам (SKSL-униформы,
пропы нативной вьюхи, JS-константы). Единого понятия «материал» нет, включить или выключить
отдельное оптическое явление нельзя, сравнить два состояния нечем.

Задача фазы: собрать **модель материала** (что стекло есть) отдельно от **рендерера**
(как Android это рисует), построить стенд, где каждое явление включается и крутится
независимо, и по результатам выбрать дефолт — **VireGlass Material v1**.

Не решаем: HardwareBuffer, замена dimezis, iOS/веб, вынос в пакет. Архитектура рендеринга
из ADR-001 сохраняется целиком.

## 2. Находка инспекции — преломления в проде нет

`components/liquid-glass.tsx` передаёт нативной вьюхе пропы `lensRadius` и `edgeReach`.
`GlassLensModule.kt` объявляет `glassWidth`, `glassHeight`, `cornerRadius`, `edgePush`.
Неизвестные пропы Expo молча игнорирует, `glassWidth` остаётся `0`, и `applyEffect()`
выходит по проверке `glassWidth <= 0f` **до** `setRenderEffect`.

Следствия:
- AGSL-линза не применяется ни в одном сценарии прода. Под поверхностью лежит
  прямоугольный BlurView размером `OVERSCAN`, а не преломлённый круг.
- Замер Phase 2.1 (0.2–0.3 мс на поверхность) мерил конвейер **без** RenderEffect.
  Цифры остаются верны для того, что мерили, но baseline для Material v1 — другой.
  Это фиксируется в бенчмарке, старые выводы не переписываются задним числом.

Починка входит в фазу: JS переходит на фактические имена пропов, а расхождение
закрывается тестом-паритетом (§6).

## 3. Модель материала

Платформо-нейтральный объект. Публичное API описывает оптические понятия, не униформы.

```
VireGlassMaterial
  blur             размытие бэкдропа, 0..100
  refraction       общая сила преломления, 0..1
  refractionScale  увеличение в плоской середине (оптическая толщина среды), 1..1.6
  thickness        доля полуразмера под фаской — где живёт вся краевая оптика, 0.02..0.5
  fresnel          сила краевого отклика, 0..1
  fresnelPower     резкость нарастания к касательному углу, 1..8
  specular         блик, 0..1
  specularPower    узость блика, 8..160
  dispersion       хроматическое расхождение на кромке, 0..1
  tint             цвет стекла (rgb)
  tintStrength     плотность тинта, 0..1
  edgeStrength     яркость световой кромки, 0..1
  edgeWidth        ширина кромки в долях фаски, 0..1
  opacity          общая непрозрачность материала, 0..1
  environment      отклик на ориентацию устройства, 0..1
```

**Геометрия** отделена от материала: `{ width, height, cornerRadius }` в dp. Круг и капсула —
частные случаи скруглённого прямоугольника (`cornerRadius >= min(w,h)/2`), отдельных форм нет.

**Тумблеры стенда — не ветки в шейдере, а обнуление параметров.** `refraction: false` →
`refraction = 0, refractionScale = 1`. Единственные исключения — `backdrop` (BlurView просто
не монтируется) и `blur` (интенсивность 0). Это даёт сравнение ON/OFF без вариантов шейдера.

## 4. Единая геометрия для всех стадий

Сейчас SDF считается дважды и по-разному: AGSL умеет скруглённый прямоугольник, SKSL —
только круг через `length(q)`, константа `BEVEL` синхронизируется вручную
(`architecture.md` §3, Расхождение 1).

Решение: **один текст SDF на оба шейдера.** AGSL и SKSL — один язык (SkSL), поэтому
исходник AGSL строится в TypeScript из общего сниппета и передаётся в нативную вьюху
пропом `shaderSource`. Kotlin компилирует полученную строку и кэширует по её значению;
при отсутствии пропа остаётся встроенный дефолт, поэтому модуль не ломается сам по себе.

Из общей геометрии выводятся **все** краевые величины, каждая ровно один раз:

```
sd = sdRect(p)                  знаковое расстояние
t  = (sd + bevel) / bevel       0 в плоской середине, 1 у самой кромки
n  = grad(sd)                   внешняя нормаль (радиальная на скруглении, осевая на прямых)
N  = normalize(n * slope(t), 1) 3D-нормаль поверхности фаски
```

`t` питает маску, толщину, преломление, аберрации и ширину кромки; `N` — Френель и блик;
`n` — направление кромочных дуг. Ни одна стадия не считает эквивалентную геометрию заново.

## 5. Раскладка слоёв (без изменений в архитектуре)

```
Skia Canvas (SKSL)      поверхность: тень, фаска, Френель, блик, кромка, тинт, дисперсия, иконка
GlassLensView (AGSL)    RenderEffect: преломление + сферическая и хроматическая аберрация
  BlurView (dimezis)    бэкдроп: живой размытый контент экрана
host View               позиционирование, жесты
```

Новое: `components/vireglass/glass-surface.tsx` — общая поверхность на произвольном
скруглённом прямоугольнике. `LiquidGlassButton` сохраняет публичный API и строится на ней;
панели получают ту же оптику, что и кнопки (закрывает Расхождение 2).
