# Вечеринка — секретный режим джема с внешними треками (дизайн, 01.08.2026)

## Задача

Секретная неиндексируемая страница «как джем, но с расширенным функционалом»: гости кидают
трек из нашего каталога **или ссылку с любого стриминга**, и он бесшовно попадает в общую
очередь. Плюс предложка по вкусу от привязанных внешних профилей. Планка — «ахуенно удобно
для вечеринок».

## Главное решение: экран вечеринки — это и есть плеер

Стороннее аудио нельзя воспроизвести своим плеером легально: Spotify Web Playback SDK в РФ
нерабочий (нет Premium), у Яндекс.Музыки и VK нет публичного SDK, извлечение потока —
пиратство. Единственный законный путь — официальный встраиваемый плеер провайдера, а он
обязан быть видимым (ToS YouTube: ≥200×200, не перекрыт). «Второй плеер» на экране
пользователя — то, что заказчик отверг, и правильно.

Разрешается разделением устройств, которое на вечеринке и так есть:

| Устройство | Что это | Звук | UI |
|---|---|---|---|
| Колонка (ноут/ТВ/телефон у колонки) | «экран вечеринки» | да | полноэкранный дисплей: большая обложка, очередь, QR |
| Телефоны гостей | пульты | нет | обычный UI VireMusic, никаких чужих плееров |

На экране вечеринки **видео-поверхность занимает место обложки**: клип на экране — плюс
вечеринки, а не паразитное окно. Транспорт один, наш. Гости чужого плеера не видят вовсе,
поэтому и ToS-вопроса на их устройствах нет.

Правовая рамка: играем только через официальные встраиваемые плееры (YouTube IFrame API,
SoundCloud Widget), ничего не скачиваем, не перезаливаем и не проксируем. Каталог VireMusic —
всегда первый источник.

## Главный сценарий — «вспомнил трек и он играет»

Требование заказчика (01.08.2026): добавить **любой трек, который человек вспомнил**, должно
быть до неприличия просто. Значит основной путь — не «вставь ссылку», а **одна строка
поиска**, и в ней сразу всё. Ссылка — вспомогательный путь, не главный.

Прямо искать на YouTube на каждое нажатие клавиши нельзя: `search` Data API стоит 100 юнитов
из 10 000 в сутки — сотня запросов на всю площадку. Развязка в разделении двух разных задач:

| Задача | Чем решаем | Цена |
|---|---|---|
| Подсказки при наборе («что вообще есть») | каталог VireMusic + бесплатный музыкальный индекс (iTunes Search / Deezer — без ключа, мгновенные, содержат практически всё) | 0 |
| Сделать выбранное играбельным | матч в каталоге VireMusic, иначе один резолв в YouTube | 100 юнитов, **только на первый в истории площадки резолв этого трека** |

Резолвы копятся в общей таблице: ключ — нормализованные «артист + название» и
нормализованный url. Второй и все последующие разы трек играется бесплатно и мгновенно, у
кого угодно. Прямые ссылки на YouTube/SoundCloud квоту не тратят вовсе (oEmbed без ключа).
Сотня *новых* треков в сутки на старте — с запасом, а квоту при росте можно поднять
запросом в Google.

Порядок источников при добавлении всегда один и тот же и пользователю не показывается:
**свой каталог → локальный файл (если это устройство-колонка) → внешний плеер**.

Оговорки по площадкам: у SoundCloud регистрация новых API-приложений закрыта — поэтому он
живёт только как ссылка/embed, в поиске его нет. Spotify, Apple, Яндекс, VK дают метаданные
через og-теги страницы, но играть из них нельзя — они резолвятся в YouTube.

### Одно поле на всё, включая любые ссылки

Строка добавления принимает **что угодно** и разбирается сама, без переключателей режима:

1. **Ссылка известного сервиса** — YouTube (в т.ч. `youtu.be`, `music.youtube`, shorts,
   с таймкодом и мусорными utm-параметрами), SoundCloud, Spotify (в т.ч. короткие
   `spotify.link`), Apple Music, Яндекс.Музыка, VK, Deezer, Bandcamp.
2. **Ссылка неизвестного сервиса** — не гадаем: тянем страницу и читаем oEmbed, а если его
   нет — og/twitter/JSON-LD теги. Название с артистом оттуда достаются почти всегда, дальше
   обычный резолв. Короткие ссылки и редиректы разворачиваются до конечного URL.
3. **Ссылка на нашу же страницу** (`viremusic.ru/artists/.../tracks/...`, смартлинк,
   плейлист) — распознаётся своим роутером, идёт в очередь напрямую как трек каталога.
4. **Просто текст** — «Кино Группа крови», строка из мессенджера с эмодзи и лишними словами:
   чистим и отправляем поисковым запросом. Это же спасает случай, когда ссылку разобрать
   не вышло: последний шаг деградации — искать по её заголовку, а не сказать «не понял».

Ошибка в этой цепочке никогда не заканчивается тупиком: непонятый ввод превращается в
поисковый запрос и показывает варианты. Ответ «не поддерживается» пользователь увидеть
не должен.

Риски, принятые осознанно: YouTube в РФ замедляют (заказчик 01.08.2026: аудитория секретной
страницы и так с VPN) — источник за портом `ExternalSourceProvider` и меняется без
переписывания фичи; на iOS каждый старт видео может требовать тапа — экран вечеринки
рекомендует десктоп/ТВ и показывает «нажмите, чтобы продолжить», когда провайдер отказал
в автоплее.

## Локальные файлы — полноценный источник общего плеера

Не только для вечеринки: пользователь добавляет свои файлы с устройства, и они играют нашим
же плеером, одной очередью с треками каталога. Это лучший по качеству и надёжности источник
из всех — своя копия, своё устройство, ничего не проходит через наш сервер и работает без
интернета.

Для этого движок плеера получает слой источников с общим контрактом
(`load/play/pause/seek/positionMs/onEnded`): `VIRE` (HLS), `LOCAL` (`<audio>` поверх
`File`), `YOUTUBE` (IFrame API). Транспорт, очередь, скраб и хоткеи остаются одни на всё —
«безумно удобное манипулирование с одного плеера» и есть требование.

Хранение между сессиями: в Chromium — хэндлы File System Access в IndexedDB (файлы
переживают перезагрузку), в Safari — только на сессию, с честной пометкой в списке.

На вечеринке локальный файл добавляет только то устройство, на котором он лежит (то есть
колонка). Заливку файла гостем **на сервер** пока не делаем — это единственное место, где
копия прошла бы через нас; решение отложено до отдельной команды.

## Что переиспользуем, а что вводим

Вечеринка — **не вторая копия джема**, а его режим: `jam_sessions.kind = 'JAM' | 'PARTY'`.
Даром достаются очередь, SSE, presence, роли, лимиты, DnD, сохранение в плейлист, режимы
SPEAKER/SYNCED и подъём сессии в app-shell (сделан 01.08.2026).

Новое:
1. **Полиморфная позиция очереди.** `jam_queue_items.track_id` становится nullable, рядом —
   `source` (`VIRE` | `YOUTUBE` | `SOUNDCLOUD`), `external_id`, `external_url`, и снапшот
   метаданных (`title`, `artist_name`, `cover_url`, `duration_sec`) — внешний трек обязан
   переживать недоступность провайдера в списке очереди.
2. **Playback ссылается на позицию очереди, а не на трек.** `JamPlaybackState.trackId` →
   `itemId`. Заодно чинится существующая двусмысленность: один и тот же трек, добавленный
   дважды (на вечеринке — норма), сейчас всегда резолвится в первое вхождение.
3. **Порт `ExternalSourceProvider`** в `packages/core` (resolve/search/описание playable) +
   адаптеры в `apps/web/lib/external/*`. Ключ `YOUTUBE_API_KEY` нужен только поиску: без него
   прямые YT/SC-ссылки работают, чужие — нет (честная деградация, не падение).
4. **Секретный вход** — путь **неугадываемый**, в духе уже существующего `/fwqa688`:
   вход `/nrvz914`, комната `/nrvz914/[code]`. `/party` и любое другое говорящее слово
   отпадает: такой адрес подбирается с первой попытки. `noindex`, нет в навигации, нет
   в sitemap; в `robots.txt` не упоминаем — `Disallow` выдал бы путь целиком.
   Попасть на вход можно только жестом: тройной клик по «© VireMusic» в футере (место
   освободилось после удаления нотного дождя 01.08.2026). Запоминать адрес не нужно.
   Ссылка на комнату при этом обычная и работает у любого, кому её дали, — иначе гости
   не войдут по QR. Секретен вход, не комната.
   Строка пути лежит в одной константе (`apps/web/lib/party.ts`) — сменить её означает
   поменять имя каталога роута и константу, больше нигде она не зашита.
5. **Экран вечеринки** — режим отображения комнаты на устройстве-колонке.

## Вечериночная механика (то, ради чего это не «джем с ютубом»)

- **Круговая очередь.** Порядок не FIFO, а по кругу гостей: накидавший десять треков подряд
  не забивает вечер. Чистая функция переупорядочивания при вставке, только для `PARTY`.
- **Голосование за пропуск.** Больше половины присутствующих — трек уходит; хост пропускает
  всегда.
- **Автодобор.** Очередь опустела — подкладываем из нашей волны по профилю вечеринки
  (общий вкус присутствующих), музыка не встаёт.
- **Предложка по вкусу.** Привязка внешнего профиля (Last.fm — официальный API и работает
  в РФ) даёт топ-артистов → предложка в панели добавления. Только вкус и поиск; никакого
  воспроизведения из привязанного сервиса (решение заказчика 01.08.2026).
