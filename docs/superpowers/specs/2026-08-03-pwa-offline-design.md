# PWA: установка, офлайн-оболочка и офлайн-медиатека — дизайн

Дата: 03.08.2026. Скоуп задан Danya: фундамент + офлайн-прослушивание в одном срезе
(§10.1 `docs/roadmap/stage-2.md`).

## Зачем

1. **Установка приложения.** Единственная возможность спрятать браузерный хром на мобилке
   (ограничение, зафиксированное в `docs/features/mobile-patterns.md`). Сейчас установка
   невозможна: Chrome требует service worker с `fetch`-обработчиком, а наш `public/sw.js`
   умеет только пуши и регистрируется лишь при подписке на уведомления.
2. **Офлайн-устойчивость.** Без сети сейчас — страница-динозавр.
3. **Офлайн-медиатека.** Слушать скачанное без сети; заодно снимает часть нагрузки с VPS
   (потолок 15–20 одновременных слушателей по k6, `docs/ops/load-testing.md`).

## Что такое «скачать» здесь

Сегменты HLS кладутся в **Cache Storage браузера**, не в файловую систему. Файл у
пользователя не появляется, играет только наш плеер, чистится вместе с данными сайта.
Выдача настоящего файла — по-прежнему только покупка FLAC по presigned URL (Этап 2).
DRM нет и не вводится: те же сегменты и так летят по сети при обычном прослушивании.

## Решения

### SW — рукописный vanilla-файл, без бандлера

`apps/web/public/sw.js` остаётся классическим скриптом (никаких `import`), но получает
`fetch`-обработчик. Причина отказа от сборки TS→SW: новый билд-шаг ради одного файла не
окупается, а тестируемость достигается иначе — файл синтаксически валиден как ES-модуль,
поэтому Vitest импортирует его с подменённым `globalThis.self` и дёргает чистые функции
через `self.__test`.

Версии кэшей — константы в файле, бампаются при смене стратегий (редко: HTML не кэшируем,
статика иммутабельна по хэшу — устаревания шелла нет). `/sw.js` отдаётся с
`Cache-Control: no-cache` (заголовок в `next.config.ts`), регистрация — `updateViaCache: 'none'`.

### Стратегии по типу запроса

| Запрос | Стратегия | Кэш |
|---|---|---|
| навигация (`mode === 'navigate'`) | network-only → при сбое `/offline` | precache |
| `/_next/static/**`, `/icons/**`, шрифты | cache-first | `vire-static` |
| картинки (S3-обложки, `/_next/image`) | stale-while-revalidate, лимит записей | `vire-img` |
| `/api/v1/tracks/{id}/manifest` | сеть → при сбое кэш | `vire-offline` |
| HLS (`.m3u8`, `.ts`) | cache-first **только по попаданию**, промах → сеть без записи | `vire-offline` |
| всё остальное (`/api/**`, не-GET) | network-only | — |

**HTML не кэшируется намеренно.** На устройстве может смениться аккаунт, а закэшированный
документ приватной страницы — это утечка чужих данных между сессиями. Цена: офлайн не
показывает ранее открытые страницы, любая навигация без сети ведёт на `/offline`. Это
осознанный размен приватности против удобства в пользу приватности.

Аудио-сегменты **не кэшируются попутно при прослушивании** — только по явной команде
«сохранить офлайн». Иначе хранилище растёт бесконтрольно и пользователь не понимает, за
что заплатил местом.

### Реестр скачанного — IndexedDB, тонкий свой враппер

Store `tracks`: метаданные для офлайн-UI и сборки `PlayerTrack` (`id`, `title`,
`artistName`, `coverUrl`, `artistSlug`, `releaseId`, `isExplicit`, `version`, `durationSec`),
плюс `hlsUrl`, `segmentUrls`, `bytes`, `addedAt`, `status`. Библиотеку не тянем — нужен один
объектный стор с четырьмя операциями.

Скачивание идёт **из страницы**, не из SW: нужен прогресс, отмена и понятная ошибка.
Страница пишет ответы в Cache Storage напрямую (`caches.open(...).put(...)`), SW потом
только отдаёт. Так SW остаётся тупым и не нуждается в собственной очереди задач.

Незавершённая загрузка не теряется: уже уложенные сегменты остаются в кэше, запись в
реестре помечена `partial`, повторный запуск докачивает недостающее.

### Плеер не трогаем

`audio-engine.ts` фетчит `/api/v1/tracks/{id}/manifest`, затем hls.js тянет `index.m3u8` и
`chunk_*.ts` — все три вида запросов идут через SW, поэтому офлайн-воспроизведение работает
без единой правки движка. Единственный обход: нативный HLS-стек iOS Safari
(`audio.canPlayType('application/vnd.apple.mpegurl')`-ветка) может ходить мимо SW — офлайн
там не гарантирован, идёт в «Ограничения» фичедока.

### Поверхности

- `/offline` — статическая client-only страница: список скачанного, занятое место, удаление,
  запуск воспроизведения. Она же — фолбэк навигации без сети, поэтому не может зависеть от
  авторизации и серверных данных.
- «Сохранить офлайн» / «Удалить из офлайна» — пункт в существующем `TrackQueueMenu`
  (`AdaptiveMenu`: sheet на таче, поповер на десктопе), новых меню не заводим.
- «Скачать плейлист» — на `/playlists/[id]`.
- Плитка «Скачанное» в медиатеке; кнопка «Установить приложение» по `beforeinstallprompt`.
- Kill-switch: на `/offline` — «сбросить кэш приложения» (unregister SW + очистка кэшей), на
  случай если SW начнёт отдавать сломанное.

### Манифест

Добавить `id`, `scope`, `orientation`, `categories`, `shortcuts` (Поиск / Медиатека /
Скачанное) и **maskable**-иконку (генерируем padded-версию из `icon-512.png` через `sharp`,
он уже в зависимостях — иначе Android обрежет лого в круге). `screenshots` не делаем:
требуют реальных снимков и влияют только на богатый install-UI.

## Границы

- Background Fetch не используем: поддержка узкая, а выигрыш — только докачка при уходе со
  страницы, которую закрывает механика `partial`.
- Автоочистка по возрасту/лимиту не вводится: пользователь сам решает, что удалить.
- Офлайн-очередь play-событий не делаем — статистика прослушиваний офлайн теряется.
- Установка в Яндекс Браузере по-прежнему недоступна (нет WebAPK) — фича для Chrome/Edge/
  Safari, ограничение из `mobile-patterns.md` снимается частично.

## Проверяемость

Чистые и потому тестируемые куски: выбор стратегии по URL (`self.__test.strategyFor`),
парсер сегментов `.m3u8` (относительные/абсолютные URL), планирование докачки
(`planDownload`: что осталось), подрезка кэша картинок по лимиту, подсчёт занятого места.
IndexedDB-обёртка и сама раздача SW проверяются вручную в браузере (DevTools → Application),
юнит-тестами не покрываются.
