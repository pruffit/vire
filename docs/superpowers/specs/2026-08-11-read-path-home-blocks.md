# Спека: read-path блоков главной (волна 2, шаг 2.7)

**Основание:** `docs/migration-plan.md` §волна 2 (последний шаг) · предусловие волны 8 (SDUI).

## Проблема

`apps/web/app/[locale]/(listener)/(home)/home-sections.tsx` — 196 строк, где каждый блок
главной сам ходит в `@vire/db` (13 query-функций) и сам держит правила композиции: чем добить
недельную свежесть на тонком каталоге, как смешать редакционные/личные/публичные плейлисты
и добрать популярными, как дедуплицировать личные подборки против недавно игравшего.
HTTP-входа нет ни у одного блока — SDUI без этого бессмыслен: протокол компоновки нечем
наполнять.

## Решение

Каждый блок — сервис в core за портом + свой эндпоинт. Правила композиции переезжают
в сервис как есть; UI и порядок секций не меняются.

**Новые блоки (6):**

| Блок | Эндпоинт | Правило, которое переезжает |
|---|---|---|
| Свежие релизы | `GET /v1/home/fresh-releases` | featured из последних + добор общим свежим, когда неделя пуста |
| Скоро выйдет | `GET /v1/home/upcoming` | тонкий, но входит в состав экрана |
| Горячие треки | `GET /v1/home/hot-tracks` | окно 30 дней, 20 позиций |
| Плейлисты | `GET /v1/home/playlists` | 4 редакционных + 4 личных с добором популярными + публичные, дедуп, отметка лайков |
| Личное | `GET /v1/home/personal` | недавнее + личные подборки минус пересечение; 401 без сессии |
| Активность друзей | `GET /v1/home/friends-activity` | слияние лайков/подписок/плейлистов (`mergeFriendsActivity`); 401 без сессии |

**Переиспользуем, новых эндпоинтов не заводим:**

- артисты главной — это `GET /v1/artists?limit=12` (шаг 2.4);
- «слушают сейчас» — существующий `GET /v1/listening-now`;
- лента — `GET /v1/feed` (шаг 2.6).

Композицию главной (какие блоки и в каком порядке) **этот шаг не описывает** — это волна 8.
Здесь только источники данных для будущих блоков.

## Границы

- Разметка, порядок секций, скелетоны, `Suspense`-границы не меняются.
- `cache()`-обёртки на общих чтениях (последние релизы, upcoming, артисты — их использует
  и `CatalogEmptyNotice`) сохраняются: блоки не должны начать читать одно и то же дважды.
- Деградация `.catch(() => [])` у каждого блока сохраняется — падение одного блока не
  роняет главную. В HTTP-входе это НЕ повторяется: там ошибка должна быть видна (500),
  иначе клиент не отличит пустой блок от сломанного.
- Персональные блоки по HTTP требуют сессии; `userId` только из сессии.

## Проверка

Гейты core/db/web + contract-тесты роутов. Сверка «до/после» на главной: тот же набор и
порядок секций, те же значения счётчиков, пустые блоки по-прежнему скрываются.

## Откат

Поблочно: каждый блок возвращается к прямому вызову query-функции независимо от остальных.
