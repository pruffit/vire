# Срез 5 — Соц / app-screen (Джем / Сообщения / Друзья): дизайн

**Дата:** 2026-07-26
**Цикл:** vire-loop, срез 5 программы мобайл-фёрст (`2026-07-22-mobile-first-program.md`).
**Модель фазы:** Opus (дизайн) → Sonnet (реализация + самокритика).

## Контекст

Рекон (Explore) показал: инфраструктура соц-экранов образцовая — app-shell/скролл без
нарушений (`min-h-screen`/`h-screen` нет), master-detail чата уже с `md:`-переключением,
SSE/бейджи/safe-area/`dnd-kit`+`TouchSensor` сделаны аккуратно. Переписывать нечего.
Реальная работа среза — **точечная тач-полировка + заметнее плитка Джема**.

## Продуктовое решение (закрыто с Danya, 2026-07-26)

Обнаружимость Джема — вариант **«Полировка + заметная плитка»**: Джем остаётся
контекстной сессией (запуск с плитки в «Медиатеке»), **в таб-бар не добавляем** (закрытое
решение Среза 0: 5 пунктов, Джем ≠ раздел). Фичу «запуск джема из плеера» НЕ берём.
Плитку в «Медиатеке» делаем заметнее.

## Рамки

**В срезе:**
1. `ProfileMoreMenu` (голый `Popover`) → `AdaptiveMenu` (sheet на таче / popover на десктопе).
2. Новый примитив `AdaptivePopover` (контентный аналог `AdaptiveMenu`: произвольное
   содержимое, Sheet на таче / Popover на десктопе) — вынос общего для двух потребителей ниже.
3. `JamParticipants` (variant `popover`) → `AdaptivePopover` (список участников в шите на таче).
4. `JamInvite` → `AdaptivePopover` (список друзей + действие «Пригласить» в шите на таче).
5. `IncomingRequests` — ряд заявки `flex-wrap`: на 320–360px кнопки переносятся под имя,
   имя не схлопывается.
6. Кнопка «назад» в шапке диалога (`messages/[conversationId]`) 36→44px на таче.
7. Плитка «Джем» в «Медиатеке» — заметнее (акцентная, крупнее, аффорданс навигации).
8. `JamAddPanel` — тач-таргет строки результата (`pointer-coarse:min-h-11`).

**НЕ в срезе (зафиксировать как будущее, не строить):**
- Вложения в чате (composer только текст) — отдельная фича.
- iOS-Safari виртуальная клавиатура + `h-full` — риск-зона под ручной QA, не подтверждён баг.
- Джем в таб-баре / запуск из плеера — отклонено продуктовым решением.

## Принципы применения

- **Тач-таргеты — через `pointer-coarse:`**, десктоп-плотность не трогаем ([[mobile-patterns]]).
- **Меню действий → `AdaptiveMenu`; контентные поповеры → `AdaptivePopover`.** Не заводить
  новые голые desktop-поповеры для тач-контента.
- **`AdaptivePopover` — новый общий примитив**, а не третья инлайн-ветка `useIsDesktopPointer`
  (в проекте уже есть инлайн-ветвление в `add-to-playlist-button`; больше не плодить —
  этот примитив закрывает контентный кейс переиспользуемо).
- Плитка Джема — акцент (не pure-gray, иначе `audit:design`), но в рамках нейтральной
  оболочки платформы; Impeccable по умолчанию.
- App-shell неизменен; `Sheet` — портал в body (уже так в примитиве).

## Критерии готовности

- На таче `ProfileMoreMenu`/`JamParticipants`/`JamInvite` открываются нижним шитом; на
  десктопе — поповером (визуально/поведенчески как раньше).
- Ряд входящей заявки на 320px не схлопывает имя.
- Кнопка «назад» в чате ≥44px на таче.
- Плитка Джема читается как заметная точка входа «Слушать вместе».
- Все 6 гейтов зелёные; десктоп-вид этих экранов не изменился (кроме заметности плитки,
  которая mobile-only `md:hidden`).
