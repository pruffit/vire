# Редизайн главной ленты — дизайн

**Дата:** 2026-07-02
**Ветка:** feat/artist-page-redesign (продолжение серии full-width редизайнов)
**Скоуп:** только лента главной `apps/web/app/(listener)/page.tsx` и её модули.
Шапка (`Nav`), футер, глобальный плеер, дашборд — **не трогаем**.

## Проблема

Текущая лента — 10 секций стопкой (`space-y-16`), где ~7 из них визуально
идентичные «ряды квадратов»:

1. Featured hero (размытая обложка + текст слева + резкая обложка справа)
2. Новое у подписок — сетка `ReleaseQuickLook` (вошедшим)
3. Поток — тонкая полоска `border-y`
4. По настроению — пилюли
5. Сейчас слушают — live-строки
6. Подборки — карточки-веера
7. Плейлисты слушателей — **те же** карточки-веера
8. Скоро выйдет — сетка `ReleaseQuickLook`
9. Свежие релизы — **та же** сетка `ReleaseQuickLook`
10. Артисты — круги

Боли:
- **Монотонный ритм** — после героя 7 почти неотличимых сеток.
- **Дубли-секции** — 3 релизных сетки подряд, 2 плейлистных подряд.
- **Дискавери разбросан** — Поток / Настроения / Live как отдельные виджеты.
- **Ни одного играбельного трека на главной** — вся лента из карточек
  релизов/плейлистов/артистов; до трека можно добраться только открыв релиз.
- **Featured hero затасканный** — «блюр-фон + текст + обложка», не цепляет.

## Цели

Переработать ленту **функционально и по дизайну** в редакционный ритм: чередование
*форм* модулей, играбельные треки прямо на главной, персональный верх для вошедших,
устранение дублей. Каждый персональный модуль **самоскрывается** при нехватке данных —
лента всегда цельная и для гостя, и для нового юзера.

## Не-цели (YAGNI)

- Рекомендательная ML. «Для тебя» — прагматичная выборка по лайкам/подпискам.
- Бесконечная лента / пагинация.
- Вкладки-переключатели (рассматривали, отклонили: прячут контент и усложняют SEO).
- Извлечение доминантного цвета из картинки на лету (используем готовый accent из темы).
- Новые route-хендлеры: SSR-данные тянет серверная `page.tsx` — текущий паттерн.

## Новая структура ленты

Зоны сверху вниз. Форма каждого модуля намеренно отличается от соседей.

### Зона 1 — Витрина (всем)

**1. Featured hero — «иммерсивный акцент»** (редизайн)
Акцентный цвет релиза заливает герой (градиент/свечение), обложка — плакатный
арт-объект, крупная болд-типографика, заметный play.
- **Источник цвета:** `artist_profiles.theme_tokens->>'accent'` артиста релиза
  (у каждого артиста есть, дефолт нейтральный `#4a5568`). Добавляем `accentColor` в
  `DiscoveryRelease` / `getLatestReleases` (тривиально, по образцу `getTracksByIds`).
  Никакого извлечения из картинки.
- **Фолбэк:** если accent — дефолтный нейтральный, подмешиваем лёгкое свечение
  из блюр-обложки, чтобы герой не был серым.
- **Вёрстка:** цветная подложка (radial/linear из accent) + резкая обложка справа как
  объект (тень, ring). Текст поверх подложки с гарантией контраста (accent приглушаем/
  затемняем под текст). LCP-осторожность: обложка `priority` + `fetchPriority=high`,
  без opacity-анимации на самом изображении (как в текущем — задержка LCP).
- **Мобилка:** обложка сверху/по центру, текст под ней; свечение на всю карточку.

### Зона 2 — Персональный верх (вошедшим, каждый модуль самоскрывается)

**2. Продолжить слушать** — горизонтальный рейл обложек недавних треков, play по клику.
- Данные: новый `getRecentlyPlayed(userId, limit)` — distinct trackId по `max(started_at)`
  из `play_events` (индекс `play_events_user_id_idx` уже есть). Только READY / слышимые.
- Форма: scroll-x рейл компактных обложек (snap). Отличается от всех сеток.
- Скрыт, если истории нет.

**3. Для тебя** — персональный микс играбельных треков.
- Данные: новый `getPersonalTrackPicks(userId, limit)` — READY-треки артистов, которых
  юзер лайкал (через лайкнутые треки → их артисты) и/или на кого подписан, упорядоченные
  по свежести релиза + прослушиваниям; dedup против «Продолжить слушать». **Без ML.**
- Cold-start (нет сигнала) → модуль скрыт (Горячие треки в зоне 3 закрывают гостя).
- Форма: играбельный список (`PlayableTrackList`, вариант с ридаутом артиста).

**4. Новое у подписок** — существующий `getFeed(userId)`, компактнее.
- Форма: рейл релизов (`ReleaseQuickLook` в scroll-x), не крупная сетка — чтобы не
  дублировать «Свежие релизы» в зоне 4.

### Зона 3 — Открытия (всем)

**5. Горячие треки** — маркетный модуль: **нумерованный чарт**, играбельно с главной.
- Данные: новый публичный `getPopularTracks(days, limit)` по образцу `getAdminTopTracks`
  (агрегат `play_events` за N дней), возвращает play-shape: id, title, artistName,
  artistSlug, releaseId, coverUrl, isExplicit, plays. Только READY / слышимые.
- Форма: 2 колонки, ранг-номера, счётчик прослушиваний, play по клику
  (`PlayableTrackList`, вариант `ranked`). Единая очередь плеера из всего чарта.

**6. Поток** — Волна + Настроения объединены в один дискавери-блок «включи и слушай».
- Композиция готовых `WaveStartButton` + `MoodWaveChips` в одну выразительную секцию/карту.
- Данные без изменений (`getMoodCounts`, `/api/v1/wave`).

### Зона 4 — Каталог (всем)

**7. Свежие релизы** — крупная сетка (как сейчас, `ReleaseQuickLook`).
**Скоро выйдет** — компактная полоска/подсекция рядом (не отдельная крупная сетка).

**8. Сейчас слушают** — live, как есть (`ListeningNow`, условный).

**9. Подборки** — редакционные + слушателей **в одной секции**, бейдж различает тип.
- Данные: `getEditorialPlaylists` + `getPersonalPlaylists`/`getPopularPlaylists` +
  `getPublicUserPlaylists` собираются в один список (текущая логика доборки сохраняется).
- Форма: сетка `EditorialPlaylistCard` (веера) — одна секция вместо двух.

**10. Артисты** — круги, как есть (`ArtistHoverChip`).

### Что видит гость

Featured → Горячие треки → Поток → Свежие релизы / Скоро → Live → Подборки → Артисты.
Персональная зона 2 скрыта целиком. Лента цельная.

## Переиспользование и извлечение

Правило Vire: искать готовое, выносить общее, не плодить дубли.

- **Извлечь `PlayableTrackList`** из `components/search-tracks-section.tsx` в общий
  компонент (напр. `components/track-list.tsx`): играбельная строка трека + управление
  очередью плеера. Варианты: `plain` (как в поиске) и `ranked` (ранг-номер + плейс).
  Потребители: Горячие треки, Для тебя, и **поиск переезжает на него** (убираем дубль).
  Тип входа — общий `PlayableTrackItem` (супертип `SearchTrack` / `DiscoveryTrack`).
- **Поток** — новый компонент-обёртка, композиция `WaveStartButton` + `MoodWaveChips`.
- **Продолжить слушать / Новое у подписок** — scroll-x рейл; переиспользуют
  `ReleaseQuickLook` (релизы) и мини-строки треков; общий контейнер-рейл выносим, если
  форма повторяется.
- **Featured hero** — переписываем `components/featured-release.tsx` (иммерсивный акцент).
- **Section** — заголовки секций через существующий `components/listener/section.tsx`
  (максимум лёгкий рестайл, без форка).
- Без изменений: `ListeningNow`, `ArtistHoverChip`, `EditorialPlaylistCard`, `ReleaseQuickLook`.

## Слои и поток данных (архитектура)

Соблюдаем слои Vire. Read-запросы живут в `packages/db` (queries), экспортируются через
`@vire/db`, вызываются **прямо в серверной** `page.tsx` — это уже действующий паттерн
(страница импортирует `getLatestReleases`, `getFeed` и т.д. напрямую). Новые
играбельные модули — client-компоненты, получают данные пропсами из RSC. Новых HTTP-
роутов не требуется (плеер и лайки используют существующие эндпоинты).

Новые запросы в `packages/db/src/queries/discovery.ts` (+ реэкспорт из `@vire/db`):
- `getPopularTracks(days = 30, limit = 20)` — публичный чарт.
- `getRecentlyPlayed(userId, limit = 12)` — «Продолжить слушать».
- `getPersonalTrackPicks(userId, limit = 12)` — «Для тебя».
- `accentColor` добавляется в `releaseCardColumns` (для героя и, при желании, карточек).

Готчи Drizzle соблюдаем: даты — в SQL (`now() - interval …` / `make_interval`), колонки
в `.select()` не интерполировать (внешнюю таблицу — литералом), см. `getTracksByIds`.
Все секции обёрнуты в `.catch(() => [])` в `Promise.all` — главная не падает из-за одной.

## Мобилка

- Рейлы (Продолжить / Подписки) — `overflow-x-auto` + snap, влезают в узкий вьюпорт.
- Чарт «Горячие треки» — 1 колонка на мобилке, 2 на десктопе.
- Hero — вертикальная раскладка (обложка сверху, текст под).
- Сетки — текущие брейкпоинты (`grid-cols-2 … 2xl:grid-cols-6`).
- app-shell инвариант: никаких `min-h-screen`/`h-screen`; высоту даёт скролл-область.

## Тесты и гейты

- Чистые хелперы (если появятся: формат ранга/плейса, сбор персонального микса без БД) —
  покрыть Vitest.
- Запросы к БД тестами не покрываем (бьют в базу) — согласуется с текущим подходом.
- Инвариант app-shell (`layout-shell.test.ts`) не должен сломаться.
- Гейты перед «готово»: `typecheck`, `lint`, `check:routes`, `test`, `audit:design`
  (трогаем UI — обязателен), `build`.

## Риски / открытые вопросы

- **`getPersonalTrackPicks` — качество выборки.** Прагматичная эвристика; на маленьком
  каталоге может быть скудной → cold-start-скрытие и dedup обязательны. Приемлемо для 1.0.
- **Контраст текста на accent-героях.** Accent бывает светлым → затемнять подложку под
  текстом, проверить `audit:design` (детектор низкого контраста).
- **Порядок зон 3–4** может тюниться на глаз после сборки — не блокер.

- Файл фичи в `docs/features/` — обновить/создать (лента главной).
