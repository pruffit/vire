# §3.4 — 404 при прямом заходе на пустого артиста

> Stage-2 §3.4, хвост. Каталог/поиск/sitemap уже прячут артистов без опубликованных
> треков (предикат `artistHasPublishedTrack`). Осталась дыра: прямой заход на
> `/artists/[slug]` открывает страницу любому.

## Требования

- Артист «пустой» = нет ни одного трека в PUBLISHED-релизе — **ровно тот же предикат**,
  что в каталоге/поиске/sitemap (`packages/db/src/queries/artists.ts:21`), иначе
  рассинхрон витрин.
- Пустой артист при прямом заходе → `notFound()` для всех, КРОМЕ:
  - участника профиля (`artist_members`, роль OWNER или MEMBER — оба видят свою страницу);
  - модератора/админа (`MODERATOR` | `ADMIN` | `SUPERADMIN` — те же роли, что пускают в `/admin`).
- 404 обязан отдаваться и из `generateMetadata` (та же ветка), иначе title/OG пустого
  артиста утекают в превью и сниппеты.
- Непустые артисты, анонимы на непустых — поведение не меняется.

## Дизайн

Минимальное вмешательство, слои не нарушаем:

1. **`packages/db/src/queries/artists.ts`** — экспортировать новую функцию
   `artistHasPublishedTrackById(artistProfileId: string): Promise<boolean>` на базе
   существующего SQL-фрагмента (не дублировать текст предиката — переиспользовать
   `artistHasPublishedTrack`, параметризовав ссылку на профиль, либо отдельный
   `exists`-запрос с тем же телом и комментарием-ссылкой не нужен — единый источник).
2. **`packages/db/src/queries/artists.ts` (или рядом)** — лёгкий
   `isArtistMember(artistProfileId, userId): Promise<boolean>` через `artist_members`
   (repository `findByIdForUser` тянет весь профиль — тут достаточно exists).
3. **Чистая функция решения** `canViewEmptyArtist({ isMember, role }): boolean` в
   `apps/web/lib/artist-visibility.ts` — тривиальна, но тестируется без БД и фиксирует
   список ролей одним местом.
4. **`apps/web/app/(listener)/artists/[slug]/page.tsx`** — общий хелпер
   `assertArtistVisible(data)` вызывается и из `ArtistPage`, и из `generateMetadata`:
   - `hasPublished` → показать;
   - иначе `auth()` → аноним → `notFound()`;
   - роль в списке админских → показать;
   - `isArtistMember` → показать; иначе `notFound()`.
   Порядок проверок: сперва дешёвый `hasPublished` (один exists), сессию и membership
   дёргаем только для пустых артистов — на горячем пути ничего не добавляется.

## Ошибки/краевые случаи

- SCHEDULED-релиз с наступившей датой считается PUBLISHED в публичных запросах? — нет:
  предикат каталога смотрит `r.status = 'PUBLISHED'`; поведение прямого захода делаем
  идентичным каталогу (единый предикат = единый ответ).
- Профиль скрыт админом (`isActive = false`) — не трогаем, отдельный механизм.
- Владелец без релизов видит страницу (пустые секции) — как сейчас.

## Тесты

- Unit: `canViewEmptyArtist` — матрица (аноним / LISTENER / участник / MODERATOR /
  ADMIN / SUPERADMIN).
- Существующие тесты страниц/queries не ломаем; интеграционный тест страницы не
  заводим (нет паттерна в репо), решение покрыто чистой функцией + ручная проверка dev.

## Вне скоупа

- Скрытие смартлинков/постов пустого артиста по прямым URL.
- `isActive`-логика, темизация, редиректы.
