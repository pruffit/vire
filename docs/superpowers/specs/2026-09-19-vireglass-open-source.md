# Вынос VireGlass в open source

Ядро стекломорфизма уезжает из монорепо в публичный репозиторий `pruffit/vireglass`,
пакет npm `vireglass`, лицензия Apache-2.0, всё на английском. Публичный репозиторий
становится источником правды; монорепо переходит на зависимость с npm отдельным шагом.

Решение о продуктах (Danya, 19.09): **VireGlass** — ядро стекломорфизма, самостоятельный
мультиплатформенный open-source продукт. **VireKit** (атомы UI + фон как технология) и
**VireCore** — отдельные продукты, в этот пакет не едут.

## База выноса

`origin/fix/vireglass-reference-gaps` (PR #119), а не `main` и не `feat/vireglass-kit`.

- `main` держит VireGlass от 07.09: без сверки с первоисточниками, без `concentric`,
  `glass-scale`, `scroll-edge`, `accessibility`. Это позапрошлое состояние.
- `feat/vireglass-kit` (161 коммит) тащит `kit/` и `medium/` — они по плану от 14.09
  в полёте (фон — шаг 1 из 4) и уезжают в VireKit. Брать их базой значит вырезать
  точки интеграции среды из рендерера.
- #119 — последнее состояние, где пакет и есть ядро: `kit/` и `medium/` в нём нет,
  а годовая сверка с первоисточниками закрыта (issues #113–#118).
- PR #110 базу не двигает: его единственный коммит правит потребителя в `apps/mobile`,
  а `materialForInk` в #119 уже есть.

## Состав пакета

| Едет | Не едет |
|---|---|
| `src/*.ts` — материал, оптика, геометрия, SDF, оба шейдера, обе цели, адаптация, доступность, `concentric`, `glass-scale`, `scroll-edge`, `touch-response`, `group-model`, `adapters`, `reference-scene` | `src/kit/**` → VireKit |
| `src/web/**` — WebGL2-рендерер, зонд, отрисовка сверочных полотен | `src/medium/**` → VireKit |
| `scripts/check-glsl.mjs`, `check-optics.mjs`, `measure-reference.mjs` | стенд `/rnd` (живёт в `apps/web`) |
| Android: `modules/glass-lens` — 4 файла Kotlin, expo-module.config, JS-обёртка | продуктовые компоненты VireMusic |
| RN: `glass-surface.tsx`, `glass-group.tsx`, `glass-ink.tsx`, `environment.ts` | |

Проверено графом импортов на базе: **ни одного импорта из продуктового кода VireMusic**
ни в ядре, ни в вебе, ни в нативе. Внешние зависимости ядра — ноль; `react` нужен одному
хуку, RN-часть тянет `react-native`, `@shopify/react-native-skia`,
`react-native-reanimated`, `expo`, `expo-blur`, `expo-sensors` — все в peer, все
опциональные.

## Форма пакета

Один пакет `vireglass` с тремя точками входа:

| Подпуть | Что | Зависимости | Как поставляется |
|---|---|---|---|
| `vireglass` | ядро: причины → следствия, SDF, текст шейдеров, обе цели | нет | сборка ESM + CJS + `.d.ts` |
| `vireglass/web` | WebGL2-рендерер и зонд | нет | сборка ESM + CJS + `.d.ts` |
| `vireglass/native` | RN-компоненты + нативная линза | peer, опциональные | **исходником** |

`native` идёт исходником намеренно: `useDerivedValue` в `glass-surface.tsx` —
ворклет, и его воркетизирует babel-плагин Reanimated на сборке приложения.
Пребандл эту фазу съедает, и ворклет уходит на JS-поток.

`expo-module.config.json` лежит в корне пакета: автолинковка Expo подхватывает Kotlin
у приложений на Expo и молчит у всех остальных.

## Переименования публичного API

Кириллица в API (не в комментариях) — 6 мест. Таблица нужна и для монорепо: на ней
переезд потребителей становится механическим.

**Пресеты** (`MATERIAL_PRESETS`, `material.ts`): `Вода`→`water`, `Стекло`→`glass`,
`Кристалл`→`crystal`, `Матовое`→`frosted`, `Толстое`→`thick`, `Плёнка`→`thin`,
`Бензин`→`iridescent`.

`Плёнка`→`thin`, а не `film`: `film` в модели уже занят причиной (толщина плёнки в нм),
и одноимённый пресет читался бы как «пресет этой причины».

**Прочее:** `LEGACY_OPTICS['v3 вручную']`→`'v3-manual'`; `DEBUG_MODES` `'зонд'`→`'probe'`;
`VireGlassRefLayer.kind` `заливка|полосы|шахматка|ступень|черта|сетка|градиент` →
`flat|stripes|checker|step|bar|grid|gradient`; имена полотен `reference-scene`
`ровное|полосы|пёстрое|черта|ступени|граница|градиент|сетка` →
`flat|stripes|busy|bar|steps|edge|gradient|grid`; `reference-draw` `fit`
`'полотно'|'во весь кадр'` → `'band'|'frame'`.

## Язык

2116 строк кириллицы из 9722 в пакете (22%) — комментарии, имена тестов, вывод гейтов.
Всё на английский. Оптическая теория из длинных блоков в шейдерах (`lens-shader.ts`)
переезжает в `docs/optics.md` пакета, в коде остаются ссылки — ровно то, что
`docs/virespace.md` §3 называл условием публикации.

## Что обязано попасть в README, иначе SDK обманет

- **Веб не видит DOM.** `createVireGlassRenderer` преломляет только то, что нарисовал
  сам: потребитель отдаёт `VireGlassSceneDrawer`, который растеризует фон в 2D-канвас.
  Стекла поверх живой вёрстки в v0.1.0 нет.
- **Преломление требует Android 13+** (`RenderEffect`). Ниже — аффинная лупа.
- **iOS не поддержан:** нет публичного API доступа к фону.
- **Бюджет** ≈ 0.8 мс GPU на поверхность; три поверхности подтверждены замером на
  устройстве, семь не проверены. Эмулятор завышает стоимость GPU примерно в 20 раз.
- **Настоящее стекло — только вне экранов.** Положить стекло внутрь его же цели
  захвата нельзя: дерево RenderNode замыкается и рантайм падает (ADR-001 §2).
- **Интерференция (`film`) видимых переливов пока не даёт** — величина выводится,
  на кромке незаметна, не разобрано.

## Гейты нового репозитория

Те же, что в монорепо, плюс сборка: `typecheck`, `test` (180 тестов), `check:glsl`
(компиляция обоих шейдеров в GLSL ES 3.0 через Playwright), `check:optics`
(поведенческий: стекло остаётся и окном, и предметом на всём диапазоне), `build`.
Все — в CI на push и PR.

## Границы задачи

Публикация в npm **не входит**: нужен токен владельца. Релизный workflow готовится
и ждёт секрет `NPM_TOKEN`.

Переезд монорепо на зависимость с npm — отдельный шаг после публикации: он невозможен,
пока пакета нет в реестре. До него `packages/vireglass` живёт как есть.

`.reference/` (3 ГБ видео WWDC) в публичный репозиторий не попадает ни при каких
условиях. В монорепо он исключён только через `.git/info/exclude` — файл локальный
и в клон не едет; в новом репозитории запись идёт в настоящий `.gitignore`.
