## Требования (по пачкам)

### Пачка A — перф БД
- **A1. Волновой скоринг** (`packages/db/src/queries/wave.ts`). Узкое место №1:
  `qualityScore` усредняет `duration_played_sec` из `play_events` — колонки нет в
  индексе `(track_id, started_at)`, поэтому index-only scan невозможен, планировщик
  берёт `Seq Scan … loops=N`.
  - **Решение с наименьшим риском:** покрывающий индекс
    `(track_id, started_at) INCLUDE (duration_played_sec)`. Не меняет выдачу волны,
    только даёт index-only scan для `qualityScore`. Миграция `0033`.
  - **Замер обязателен** (тем же харнессом, что в прошлый раз: синтетика ~1500 треков /
    220k `play_events` за 60 дней). Медиана 10 прогонов `getWaveTracks` до/после.
  - **Top-N сужение кандидатов — только если покрывающего индекса мало.** Оно меняет
    выдачу волны (продуктовый риск) → без замера не трогаем.
- **A2. Админ-счётчики** (`packages/db/src/queries/admin.ts:236-277`,
  `listArtistsAdmin`). 4 коррелированных подзапроса × 50 строк, дороже всех `plays30d`.
  Свести к меньшему числу проходов (агрегатные `LEFT JOIN … GROUP BY` или `LATERAL`).
  Выдача (числа) обязана совпадать; сохранить приём с литералом внешней таблицы
  (grep-gotcha про неквалифицированную колонку в `.select()`).

### Пачка B — фронт-механика
- **B1. `player-like-button.tsx` (+ `store/likes.ts`)** — шестой дубль тоггла БЕЗ
  guard'а. Два быстрых клика шлют POST и DELETE, ответы могут прийти в обратном
  порядке → стор рассинхронизирован с БД. Направление: guard по `trackId` в сторе
  (in-flight set) + сетевой вызов через `likeTrack` из `@vire/api-client`.
- **B2. Sitemap N+1** (`app/sitemap.ts:40-60`) — последовательный `await
  getWithTracks(r.id)` по каждому релизу. Свести к пакетной выборке id треков по
  всем релизам артиста (или по всем сразу).
- **B3. XHR abort** (`batch-track-upload.tsx`) — загрузка не абортится при анмаунте.
  Хранить активные XHR, `abort()` в cleanup эффекта/при анмаунте.
- **B4. a11y `TrackRow`** — в ветке `clickableRow` статичный `aria-label="Воспроизвести
  …"` не переключается на «Пауза» при активном воспроизведении (в кнопочной ветке уже
  переключается — `playAriaLabel`). Плюс `playlist-track-row.tsx`:
  `durationSec && (...)` рендерит текстовый «0» при `durationSec === 0`.
- **B5. Кадр 0:00 `currentTime` после F5** — `duration` уже персистится, но
  `currentTime` на первом кадре после регидрации мелькает нулём. Направление:
  выставлять `hasAudio:true` в колбэке `MANIFEST_PARSED` ПОСЛЕ установки `currentTime`
  при `isResume`. **НЕ через `isLoading`** в fallback-ветке — регрессирует buffer-stalls.

### Пачка C — безопасность
- **C1. Guest-пресейв double opt-in** — продуктовое решение принято: **IP-лимит +
  отписка** (не полный double opt-in). В `presave/route.ts` добавить rate limit по IP
  в дополнение к email-лимиту. В письмо о выходе релиза (воркер
  `fulfill-presave.worker.ts`) добавить ссылку «отписаться».
- **C2. `sessionId` присутствия не подписан** (`lib/presence.ts` + `presence/route.ts`
  + listening-роут) — счётчики накручиваемы. Подписать HMAC (секрет из env), проверять
  подпись на входе. Деградация при отсутствии секрета — как принятый риск (косметика).
- **C3. CSP `'unsafe-inline'` в `script-src`** (`next.config.ts:46`) — **рискованный**.
  Перевод инлайн-скриптов Next на nonce. Обязательна рантайм-проверка (dev + `curl`
  ключевых страниц, виджеты Telegram/Метрика/YouTube/VK не должны отвалиться).
  Если nonce ломает сторонние встраивания без чистого решения — откатить и
  задокументировать как осознанный долг, не ломать прод.

### Пачка D — гигиена
- **D1. typecheck core/db** — свои `tsc --noEmit` скрипты в `packages/core` и
  `packages/db` + подключить в CI-гейты.
- **D2. Single-flight TTL-кэша вкуса** (`packages/core/src/util/ttl-cache.ts`) —
  дедупликация конкурентных промахов на один ключ в один in-flight промис.

## Не-цели
- Этап 2 (purchase/webhook) — не трогаем.
- Observability/Sentry — отложено (RAM VPS).
- Контент-SEO (уникализация описаний) — ручной контент, не код.
- Тег/push/деплой — по явной команде пользователя.

## Продуктовые решения (закрыты)
- Guest-пресейв → IP-лимит + ссылка отписки (не полный double opt-in). Причина:
  double opt-in не убирает нежелательное письмо (лишь переносит его на момент
  пресейва) и режет конверсию.
