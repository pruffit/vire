# Десктоп-клиент, срез 0 — оболочка — дизайн

**Статус:** реализуется · **Основание:** `docs/multiplatform.md` §3.2, §12 (пункт 7)

## Что это

Первый срез десктопного клиента VireMusic: `apps/desktop` на Tauri v2, минимальная
нативная оболочка вокруг **уже готового веб-фронта** — без нового UI. Цель среза не
«десктоп-приложение со всеми фичами», а проверка связки Tauri + существующий веб на
реальной не-браузерной платформе, дешевле и раньше мобильного (см. `multiplatform.md`
§12 п.7: «ошибки в границах вылезут здесь, чинить дешевле, чем в мобильном»).

## Скоуп среза 0 (входит)

- `apps/desktop/src-tauri` — Rust-шелл Tauri v2, окно грузит веб-фронт через webview
  (`WebviewWindow`) по URL, настраиваемому конфигом сборки: dev — `http://localhost:3000`,
  prod-сборка — `https://viremusic.ru` (тот же паттерн, что `NEXT_PUBLIC_SITE_URL`/`AUTH_URL`
  в вебе — см. `apps/web/lib/site.ts`).
  Название окна — «VireMusic», иконка — плейсхолдер (взять существующий `apps/web/public/icon-512.png`
  или аналог, конвертировать под требования Tauri — `.ico`/`.icns`/PNG-набор).
- Сборка проверена локально: `cargo tauri dev` поднимает окно и грузит страницу,
  `cargo tauri build` собирает установочный пакет для текущей платформы (Windows —
  раз разработка идёт на Windows-машине; macOS-сборка недостижима с этой машины,
  не пытаться).
- `docs/features/desktop-app.md` — новый файл: что делает, где код, как собрать/запустить,
  ограничения среза.

## Скоуп НЕ входит в срез 0 (сознательно, следующие срезы)

Список — прямо из `multiplatform.md` §3.2 «Что даёт десктоп поверх PWA практически»,
ни один пункт не реализуется сейчас:
- Медиа-клавиши ОС / управление с гарнитуры
- Глобальные хоткеи при свёрнутом окне
- Системный трей + мини-плеер поверх окон
- Автозапуск при входе в систему
- Доступ к локальной библиотеке файлов сверх того, что уже даёт веб (плеер уже умеет
  локальные файлы через веб-API — нативный доступ к ФС не нужен в этом срезе)
- Код-сайнинг, автообновление, полировка инсталлятора
- Bearer-токены/device-auth для десктопа — в этом срезе webview использует ту же
  cookie-сессию, что и обычный браузер (Auth.js JWT в httpOnly cookie уже работает
  для любого клиента, рендерящего веб-страницу как есть); отдельный API-клиент для
  desktop (минуя webview, напрямую по Bearer) понадобится, когда появится нативный
  UI вне webview (трей-мини-плеер и т.п.) — не раньше

Разработка ведётся на Windows — Tauri v2 официально поддерживает Windows/macOS/Linux
из одной кодовой базы, но верифицировать можно только то, что реально собирается и
запускается здесь.

## Зависимости окружения

Rust/Cargo не установлены на машине — часть работы: поставить toolchain (`rustup`,
стабильный канал) + `@tauri-apps/cli` (dev-зависимость воркспейса или через `cargo install
tauri-cli`, что стандартнее для Tauri v2 — на усмотрение реализации, задокументировать
выбор в `docs/features/desktop-app.md`). Первая сборка Rust-тулчейна и первая компиляция
Tauri — заведомо долгие (десятки минут), не повод сокращать проверку.

## Риски / где решать по ходу

- Если `cargo tauri build` не соберёт установщик Windows без дополнительных системных
  зависимостей (WebView2 runtime, MSVC build tools) — задокументировать в
  `docs/features/desktop-app.md`, какие системные пререквизиты нужны, а не тихо пропустить
  шаг.
- Иконка — плейсхолдер, финальный брендинг не тема этого среза.
