# Десктоп-клиент, срез 7 — автообновление — дизайн

**Статус:** реализуется · **Основание:** продолжение срезов 0-6, докладка к CI-публикации
(`docs/superpowers/specs/2026-08-16-desktop-download-distribution-design.md`)

## Проблема

Установщик публикуется на CDN при каждом теге (уже сделано), но у пользователя нет
способа получить новую версию, кроме как вручную зайти на `/download` и перекачать
`.exe` заново. Официальный путь Tauri v2 — `tauri-plugin-updater`: проверяет манифест
(`latest.json`) на сервере, скачивает и ставит подписанное обновление, перезапускает
приложение.

## Криптография — ключ подписи

Tauri-апдейтер требует, чтобы каждый артефакт был подписан приватным ключом; публичный
ключ зашит в `tauri.conf.json` (не секрет, коммитится). Ключ — **новый**, генерируется
с нуля в этом заходе (`cargo tauri signer generate`), не берётся ниоткуда извне —
никакого «как мне это забрать с прода» вопроса нет, в отличие от S3-креденшлов ранее в
этой сессии.

- Публичный ключ → `apps/desktop/src-tauri/tauri.conf.json`,
  `plugins.updater.pubkey` (закоммитить как есть).
- Приватный ключ + пароль (если сгенерирован с паролем — на усмотрение реализации,
  без пароля проще для headless CI, с паролем безопаснее при утечке файла; решить и
  задокументировать выбор) → **GitHub Secrets**, не выводить в чат, не коммитить.
  Имена секретов: `TAURI_SIGNING_PRIVATE_KEY`, и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`
  если ключ с паролем. Ставятся через `gh secret set` напрямую из локально
  сгенерированного файла (тот же паттерн, что S3-секреты ранее — значение никогда не
  печатается).
- Локальный файл с приватным ключом после того, как секрет установлен в GitHub — удалить
  с диска (он не нужен локально дальше, сборки идут через CI).

## Манифест обновлений

`tauri-plugin-updater` ожидает JSON (`latest.json`) с полями `version`, `notes`,
`pub_date`, `platforms.windows-x86_64.{signature, url}`. CI (`build-desktop` job,
`.github/workflows/deploy.yml`) после сборки и подписи генерирует этот файл (значения —
из тега `github.ref_name`, содержимого `.sig`-файла рядом с NSIS-инсталлятором, который
`cargo tauri build` создаёт автоматически при наличии переменных окружения
`TAURI_SIGNING_PRIVATE_KEY`) и заливает его **рядом с установщиком** на тот же стабильный
CDN-путь: `https://cdn.viremusic.ru/vire-stream/downloads/desktop/windows/latest.json`
(перезаписывается каждым релизом, как и сам `.exe`).

`tauri.conf.json` → `plugins.updater.endpoints` — этот же URL.

## Клиент — main.rs

- `tauri-plugin-updater` + `tauri-plugin-process` (нужен для перезапуска после установки
  — `app.restart()`) как зависимости.
- Проверка при старте (не блокирующая, не мешает сплэшу/основному потоку) — тихая, без
  диалога, если обновлений нет. Если найдено — минимальный native-диалог (`tauri-plugin-
  dialog`, если ещё не подключён — добавить) с вопросом «Установить обновление и
  перезапустить?», да/нет. Полноценный UI прогресса скачивания — избыточно для этого
  среза (окно грузит внешнюю страницу, лишнего чрома для этого нет).
- Пункт в трей-меню «Проверить обновления» — ручной триггер той же проверки, с явным
  результатом (диалог «У вас последняя версия» если обновлений нет, чтобы клик не выглядел
  как ничего-не-произошло).

## Явно НЕ в этом срезе

- Автоматическая тихая установка без подтверждения пользователя — всегда спрашивать
- Дельта-обновления/прогресс-бар скачивания — простой блокирующий (для апдейтера, не для
  UI приложения) даунлоад достаточен
- Каналы обновлений (stable/beta) — один канал, последняя опубликованная версия

## Проверка

**Это первый срез, который нельзя полностью проверить локально** — реальная проверка
скачивания обновления требует опубликованной версии N и попытки обновиться с версии
N-1, то есть реального тега и живого CI. В этом заходе — проверить:
- `cargo tauri build` с локально сгенерированным (тестовым, не тем что уйдёт в secrets)
  ключом подписи — сборка производит `.sig`-файл рядом с инсталлятором, апдейтер-плагин
  собирается и стартует без паники (можно проверить, что проверка при старте не роняет
  приложение, направив `endpoints` на заведомо несуществующий/локальный URL — ожидаемая
  ошибка сети, не паника).
- Пункт трея «Проверить обновления» — кликается, диалог «последняя версия» появляется
  (раз реального сервера с новой версией нет).
- YAML нового шага в `deploy.yml` — синтаксически валиден.
- Секреты `TAURI_SIGNING_PRIVATE_KEY`(`_PASSWORD`) реально стоят в GitHub (через `gh
  secret set`, значения не печатать).

Полная сквозная проверка (реальное обновление с версии на версию) — только по факту
двух последовательных тегов, вне скоупа этого захода; задокументировать это ограничение
явно, не выдавать частичную проверку за полную.
