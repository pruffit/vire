# Мобильное приложение — инкремент 3: воспроизведение звука

**Контекст:** `docs/features/mobile-app.md` (инкременты 1–2 — auth, каталог, устройства).
Последний блокер, чтобы приложение не было немым каталогом. Порт
`packages/core/src/music/playback/ports/audio-engine.ts` (`IAudioEngine`) уже заведён
(17.08.2026) — цель этого среза: первая реальная реализация под RN.

## Ключевое отклонение от `docs/multiplatform.md` §3.1 — библиотека аудио

Доку рекомендовал `react-native-track-player` (RNTP). **В этом инкременте — НЕ RNTP.**
Причина: RNTP не работает в обычном Expo Go — нужен кастомный dev-client (EAS build или
локальный prebuild с Android SDK). На машине разработки нет Android SDK/эмулятора и нет
настроенного EAS — с RNTP код был бы вообще непроверяем, даже на уровне «бандлится ли»
(нет веб-шима, `expo start --web` не подхватит нативный модуль). Решение: **`expo-audio`**
(официальный Expo-модуль, работает в обычном Expo Go, есть веб-реализация через
`HTMLAudioElement` — значит проверяем тем же способом, что и предыдущие инкременты).
Компромисс сознательный: `expo-audio` слабее RNTP в тонкой настройке lock-screen/очереди
на iOS/Android, но реального выбора нет без прод-пайплайна сборки. RNTP — кандидат на
переход, когда появится dev-client (не в этом срезе).

**Перед стартом:** `npx expo install expo-audio` (в `apps/mobile`) — резолвит версию под
установленный Expo SDK 57 автоматически, не проставлять версию руками. Если `expo-audio`
почему-то несовместим (проверить реально, не гадать) — echo `expo-av` как fallback
(legacy, но точно работает на SDK 57) и явно описать это отклонение в отчёте.

## Компоненты

### 1. Драйвер `IAudioEngine` под RN

`apps/mobile/lib/audio-engine.ts` — implements `IAudioEngine` из `@vire/core`
(`load/play/pause/seek/on`) поверх `expo-audio`. HLS-манифест (`.m3u8`) — `expo-audio`
использует нативные плееры (AVPlayer/ExoPlayer), которые HLS понимают из коробки, отдельной
настройки не требуется. Фоновое воспроизведение — `app.json` (`expo-audio` config plugin,
`staysActiveInBackground`/аналог, проверить актуальное имя опции у установленной версии, не
угадывать по памяти).

### 2. Плеер-стор

`apps/mobile/lib/player-store.ts` — zustand (уже есть в вебе как паттерн, ставится как
обычная RN-зависимость): `queue: Track[]`, `queueIndex`, `isPlaying`, `positionSec`,
`durationSec`. Транспорт (`next`/`prev`) — через уже существующие чистые функции
`nextQueueIndex`/`sliceWindowAroundIndex` и т.п. из `@vire/core`
(`music/playback/services/queue.ts`) — **не писать свою логику очереди**, они уже
обобщены по `T extends {id:string}` и покрыты тестами в core. Стор дергает
`audio-engine.ts` (load нового трека при смене `queueIndex`, play/pause проксируются).
Трек играется по манифесту с `GET /api/v1/tracks/{id}/manifest` (`hlsUrl`,
`@vire/api-contracts` → `track-media.ts` → `trackManifestResponseSchema`) — этот роут
публичный (не требует Bearer), вызывать через обычный `request()` из `@vire/api-client`.

### 3. Экран релиза + вложенная навигация Home-таба

Сейчас Главная (`apps/mobile/screens/home-screen.tsx`) показывает список релизов без
перехода никуда. Нужно: `apps/mobile/screens/release-screen.tsx` — трек-лист релиза
(`GET /api/v1/releases/{id}`, контракт `release.ts` → `tracks: TrackDTO[]`), тап по треку
запускает воспроизведение **всего трек-листа релиза как очереди** (queueIndex = позиция
тапнутого трека) через плеер-стор. Навигация: Home-таб оборачивается в свой
`createNativeStackNavigator` (вложенный стек **внутри** таба «Главная» —
`HomeStack: [HomeList, ReleaseDetail]`), таб-бар при этом не пропадает (стандартный RN-
паттерн вложенных навигаторов, не городить самодельную замену). `navigation/main-tabs.tsx`
меняется точечно: `Tab.Screen name="Home" component={HomeStackNavigator}`, не переписывать
остальные вкладки.

### 4. Мини-плеер + полноэкранный плеер

- Мини-бар: рендерится над таб-баром, когда `queue.length > 0` (обёртка вокруг
  `MainTabs` в `navigation/root-navigator.tsx` или сосед таб-навигатора — на усмотрение
  реализации, но таб-бар не должен уезжать/дублироваться). Обложка текущего трека,
  название/артист, play/pause, тап открывает полный плеер.
- Полный плеер — модальный экран (`Stack.Screen` с `presentation:'modal'` в корневом
  стеке или отдельный модальный стек) — крупная обложка, транспорт (prev/play-pause/next),
  ползунок позиции (перемотка через `seek()` — в отличие от веб-мини-плеера desktop, здесь
  перемотка **есть**, RN даёт полноценный слайдер).

## Что сознательно вне скоупа (не делать, не блокировать этим срез)

- Shuffle/repeat — UI-кнопки не добавлять (сами функции в core уже есть на будущее).
- Оффлайн-скачивание, лайки/добавление в плейлист из мобилки.
- Lock-screen/Control Center richer controls, Android Auto — то, что специфично для RNTP;
  `expo-audio` даёт базовый `MediaSession`/`Now Playing`, глубже не копать в этом срезе.
- Реальная проверка на Android/iOS устройстве — недоступна на этой машине (см. ниже).

## Проверка

- `apps/mobile` typecheck — чисто.
- `npx expo start --web`: бандл собирается без ошибок, grep по бандлу подтверждает
  реальные строки нового кода (`/api/v1/tracks/`, `/api/v1/releases/`, тексты плеера).
  **Честно указать**, играет ли реально звук в вебе через `expo-audio`'s web-реализацию —
  проверить фактом (открыть в браузере, послушать), не предполагать.
- Юнит-тесты (vitest, `apps/mobile/lib/__tests__/`) на всё, что не требует RN-рендеринга:
  переходы `queueIndex` при `next`/`prev` через стор (мокая `audio-engine.ts`), сборка URL
  манифеста.
- **Явно, честно в отчёте:** воспроизведение на реальном Android/iOS устройстве, фоновое
  воспроизведение при свёрнутом приложении, lock-screen контролы — не проверялись (нет
  устройства/эмулятора на машине разработки). Это первая настоящая проверка при следующем
  прогоне через Expo Go на телефоне.
- Гейты: `apps/mobile` typecheck+test, `apps/web`/`packages/core` typecheck (порт уже
  добавлен и зелёный, эта работа их не трогает, но убедиться что ничего не задето).
