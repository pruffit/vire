# Джем: два режима — «в наушниках» и «на колонке»

Дата: 2026-07-29. Запрос Danya: у джема должно быть два сценария —
(1) идём вдвоём в наушниках, звук на каждом устройстве синхронно;
(2) вечеринка, звук с одного устройства в колонку, остальные — пульт.
Во втором сценарии задержек не должно быть даже гипотетически.

Решения (подтверждены): режим выбирается при создании и переключается хостом на лету;
источник звука — хост, но любой участник может забрать роль колонки себе; остальные в
режиме колонки — чистый пульт без звука.

## Модель

`jam_sessions.mode`: `SYNCED` (текущее поведение, дефолт) | `SPEAKER`.
`jam_sessions.speaker_participant_id` — участник-колонка; `null` = хост (дефолт, переживает
перезаход хоста, у которого participant тот же).

Звуковое устройство:

```
SYNCED  → звук у всех участников (как сейчас)
SPEAKER → звук только у participantId === speakerParticipantId ?? hostParticipantId
```

Чистая функция в `packages/core/src/services/jam-mode.ts`:
`resolveSpeakerParticipantId(participants, speakerParticipantId)` и
`isAudioDevice({ mode, participantId, participants, speakerParticipantId })`.

## Поведение

**SYNCED** — без изменений: серверные часы, дрейф-коррекция, всё как есть.

**SPEAKER, устройство-колонка** — играет как обычный плеер: команды сервера
(play/pause/track/seek) исполняет, но **периодической коррекции дрейфа нет вообще**
(ни rate-warp, ни seek). Синхронизировать не с кем — источник звука один, задержка
физически невозможна. `usePlaybackSync` получает флаг `driftCorrection`.

**SPEAKER, пульт** — `audioEnabled = false`: движок джема не создаётся, HLS не грузится,
серверные часы нужны только чтобы рисовать позицию. Очередь, поиск, транспорт
(play/pause/prev/next/перемотка) работают как раньше — команды уходят на сервер и
исполняет их колонка. Глобальный плеер по-прежнему заглушен гардом (пульт не должен
параллельно включить свою музыку).

**Автопереход по `ended`** инициирует звуковое устройство: в SYNCED — хост (как сейчас,
анти-гонка), в SPEAKER — колонка (у пультов события `ended` нет в принципе).

**Расхождение позиции у пультов.** Колонка не корректируется по серверным часам, поэтому
её реальная позиция может медленно уезжать от `startedAtMs`. Для пультов это только
косметика полосы прогресса (доли секунды за трек) — отдельный канал синхронизации
позиции в v1 не вводим.

## UI

- Экран создания (`/jam`): выбор «В наушниках» / «На колонке» перед созданием.
- Шапка комнаты: индикатор текущего режима; у хоста — переключатель (на лету).
- SPEAKER у пульта: строка «Играет на устройстве {имя}» + кнопка «Звук здесь»
  (перехват роли колонки; у прежней колонки звук гаснет сразу по broadcast).
- Мини-бар в режиме пульта: бейдж «Пульт» вместо «Джем», транспорт остаётся.

## API

- `POST /api/v1/jam` — принимает `mode`.
- `POST /api/v1/jam/[code]/mode` — только HOST.
- `POST /api/v1/jam/[code]/speaker` — любой участник, забирает роль себе.
- Обе мутации бродкастят `jam:session { mode, speakerParticipantId }`; `jam:snapshot`
  уже отдаёт `session` целиком — новые поля приезжают в нём автоматически.

## Риски / ограничения

- Колонка ушла со страницы (закрыла вкладку) — звук в комнате пропадает, пока кто-то не
  нажмёт «Звук здесь». Presence это не лечит автоматически в v1.
- Переключение SYNCED→SPEAKER на лету: у всех, кроме колонки, звук гаснет по
  broadcast — это и есть ожидаемое поведение.
- Гость без аккаунта может быть колонкой (он полноценный участник).
