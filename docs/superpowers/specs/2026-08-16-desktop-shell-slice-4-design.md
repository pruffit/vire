# Десктоп-клиент, срез 4 — сворачивание в трей и глобальный хоткей — дизайн

**Статус:** реализуется · **Основание:** продолжение срезов 0-3

## Что это

Два небольших, независимых, чисто нативных улучшения поведения окна — ни одно не требует
канала веб→Rust:

1. **Крестик сворачивает в трей, а не закрывает приложение.** Ожидаемое поведение для
   музыкального плеера с треем (Spotify, Discord, Telegram — тот же паттерн): пользователь
   не хочет обрывать воспроизведение, случайно закрыв окно. Полный выход — только через
   пункт «Выход» в трее (уже есть с среза 1).
2. **Глобальный хоткей показать/скрыть окно** (например `Ctrl+Alt+V` — конкретную
   комбинацию зафиксировать в реализации, проверив, что не конфликтует с типичными
   системными/браузерными хоткеями). Работает даже когда окно свёрнуто в трей — быстрый
   доступ без похода мышью.

## Решение

1. **Close-to-tray**: обработчик события `WindowEvent::CloseRequested` в `main.rs` —
   `api.prevent_close()` + `window.hide()` вместо реального закрытия. Полный выход остаётся
   только через `app.exit(0)` в пункте меню «Выход» (уже реализовано).
2. **Глобальный хоткей show/hide**: `tauri-plugin-global-shortcut` уже подключён (срез 1,
   для медиа-клавиш) — добавить в тот же `with_shortcuts`/`with_handler` ещё один шорткат
   (обычная комбинация клавиш, не медиа-клавиша) на toggle видимости окна (`window.show()`+
   `set_focus()` если скрыто, `window.hide()` если видимо).

## Явно НЕ в этом срезе

- Полноценные пользовательские настройки хоткеев (менять комбинацию) — хардкод одной
  комбинации достаточно для этого среза
- Уведомление/тост при первом сворачивании в трей («приложение продолжает работать в
  трее») — красиво, но не обязательно для функциональности; если реализация сочтёт это
  дешёвым — можно добавить, не обязательно

## Проверка

`cargo tauri dev`: нажать крестик окна → окно прячется, но процесс `vire-desktop.exe`
остаётся в списке процессов и трее (не завершился) → нажать хоткей → окно снова
показывается → выход только через пункт трея «Выход» реально завершает процесс.
Эмпирически подтвердить каждый шаг (как в предыдущих срезах — не полагаться на
«скомпилировалось»).
