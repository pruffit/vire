# Джем как глобальная сессия — дизайн (01.08.2026)

## Проблема

Джем-сессия целиком живёт внутри страницы `app/(listener)/jam/[code]/jam-room.tsx`:
membership, SSE-комната (`useJamRoom`), аудио-движок (`usePlaybackSync`), регистрация
транспорта (`setJamTransport`) и выставление `jamOverride`. Уход с `/jam/[code]` (клик на
«Главную») размонтирует компонент → SSE закрывается, движок уничтожается, override
чистится cleanup-эффектом. Пользователь молча вылетает из джема.

«Глобальным» плеер был только на самой странице: мини-бар показывал джем, пока ты на ней стоишь.

## Решение

Поднять сессию в app-shell — рядом с плеером, а не внутри страницы. Страница становится
**view** поверх живущей выше сессии.

| Слой | Кто владеет | Что держит |
|---|---|---|
| `store/jam.ts` (zustand, persist) | app-shell | активный джем: code, participantId, role, sessionId |
| `components/jam/jam-session-provider.tsx` | корневой layout | SSE-комната, серверные часы, аудио-движок, транспорт, `jamOverride` |
| `jam-room.tsx` | страница | очередь (DnD), панели добавления/участников, join-экран |

### Решения по развилкам

- **Персист.** `code/participantId/role/sessionId` — в localStorage (`vire-jam`), как у плеера.
  Джем переживает F5. `audioEnabled` **не** персистится: после перезагрузки браузер блокирует
  автоплей, звук включается первым жестом.
- **Мини-бар без звука.** `jamOverride` выставляется при активном джеме независимо от
  `audioEnabled` — иначе после F5 нет ни бара, ни пути назад в комнату. Новое поле
  `needsAudioGesture`: play в мини-баре сперва включает локальный звук, и только если джем
  на паузе — шлёт `toggle`.
- **Выход.** Явная кнопка в мини-баре (`leave()` — чистит стор, SSE закрывается, presence
  истекает сам). Отдельного API не нужно: выход ≠ завершение джема (`end` остаётся у хоста).
- **Одна SSE-подписка.** Страница больше не зовёт `useJamRoom` — только читает контекст.
  `useRealtime` дедуплицирует по URL, но два набора хендлеров = два состояния.
- **Смена джема.** Вход в другой код замещает активный (стор — одиночка).
- **Завершение.** `jam:ended` → чистим стор + тост; страница показывает экран «Джем завершён».

### Что не меняется

Серверная часть (роуты, сервисы, presence по живому SSE), протокол событий, `jam-audio`,
`use-playback-sync`, `jam-controls`, оптимистичный playback, guard `jamOverrideActive()`
в `audio-engine` (два аудио одновременно по-прежнему недопустимы — теперь у пользователя
есть явная кнопка выйти).

## Побочный баг: отступы кнопки джема в свёрнутом сайдбаре

`library-sidebar.tsx:53` — строка «Джем» лежит в своём контейнере с `pt-2`, а список ниже
добавляет ещё `pt-2`: между джемом и «Любимыми» 16px против 2px (`gap-0.5`) у остальных.
Свести к общему ритму рельса.

## Регресс-тест

Ключевой: смонтировать провайдер, войти в джем, размонтировать страницу — `jamOverride`
и зарегистрированный транспорт живы. Именно это ломалось.
