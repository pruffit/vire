# Переработка подсистемы воспроизведения и рекомендаций

Дата: 2026-07-03. Статус: утверждено (продуктовые развилки закрыты с владельцем).

## Зачем

Подсистема «слушания» (плеер, Волна/Поток, рекомендации, подборки) выросла
инкрементально и суммарно работает плохо:

- **Поток**: пауза между треками (очередь пополняется по 1 треку синхронно в момент
  `ended`), повторы (анти-повтор — 30 id в памяти вкладки), первый трек не
  персонализирован (`ORDER BY random()`), тональность сравнивается равенством строк,
  жанр скорится дважды двумя противоречащими механизмами.
- **Рекомендации**: mood-подборки и «Для тебя» собираются без `ORDER BY`
  (произвольные 25 треков, почти не обновляются); четыре независимых механизма
  персонализации с разными окнами; нет дедупликации треков между секциями главной;
  жанровый вкус собирается, но нигде не используется; «включения по жанру» нет.
- **Плеер**: два несвязанных «шаффла» (один — некорректный `.sort(random)`), `prev`
  несовместим с шаффлом, ~18 точек запуска вручную строят очередь и почти все теряют
  `accentColor`/`isExplicit`, состояние не переживает перезагрузку, `source`
  play-событий всегда `'direct'`, ререндер всего дерева плеера 4 раза/сек, дубли
  (waveform-скраббер ×2, `getSessionId` ×2, `WaveApiTrack` ×3).
- **Безопасность**: `/api/v1/tracks/[id]/manifest` отдаёт HLS любого трека без
  проверки статуса/публикации и без rate-limit.

## Продуктовые решения (зафиксированы)

1. Приоритет: всё в работе — Поток → Рекомендации → Поведение плеера → Дизайн.
2. UI плеера — **полный редизайн** (мини-бар + фуллскрин + блок «Поток»).
3. Персист: **трек + очередь + позиция** переживают перезагрузку (плюс громкость/режимы).
4. Жанры: **чипы жанров в Потоке + жанр как полноценный сигнал алгоритма**
   (без отдельных жанровых страниц — YAGNI).

## Рассмотренные подходы

**A. Точечные фиксы поверх текущего кода.** Минимальный риск, но не убирает
структурные причины (18 ручных точек запуска, логика мимо стора, разрозненные
сигналы вкуса) — баги будут возвращаться. Отклонено.

**B. Переписать «слушание» целиком, включая замену Zustand и отдельный
плеер-микросервис.** Слишком дорого, ломает 200 зелёных тестов и рабочие паттерны
(Zustand + HLS.js сами по себе адекватны). Отклонено.

**C (выбран). Реструктуризация вокруг четырёх опорных абстракций** с сохранением
стека: единый **PlayContext** (кто и откуда запустил), единая **очередь с
корректной семантикой** (шаффл/история/персист), **Волна v2** (пачки + серверный
анти-повтор + нормализованные сигналы), **единый профиль вкуса** для всех
рекомендательных механизмов. UI редизайнится поверх новой модели.

## Архитектура

### 1. Плеер: модель и движок

Слои: `store/player.ts` (Zustand, состояние + persist) ← `components/player/audio-engine.ts`
(императивный синглтон: audio/HLS/heartbeat/события) ← `lib/player/use-play.ts`
(единственный публичный вход для UI).

**PlayerTrack** дополняется обязательной сквозной прокачкой `accentColor` и
`isExplicit` (типы уже есть — чинится маппинг). Единый маппер
`lib/player/to-player-track.ts` из серверных шейпов (`PlayableChartTrack`,
треки релиза/плейлиста, wave DTO) — вместо 18 ручных построений.

**PlayContext** — новый объект в сторе:
```ts
{ source: 'wave'|'release'|'playlist'|'artist'|'home'|'feed'|'search'|'liked'|'purchased'|'direct',
  sourceId?: string }
```
Задаётся при запуске очереди, уходит в play-события (`source` оживает).
`VALID_SOURCES` на API расширяется этим набором (включая `wave`).

**Единый вход `usePlay()`** (хук) и `playQueue(tracks, { startIndex, context, shuffle? })`:
- toggle-if-current паттерн внутри;
- инициализация движка внутри (устраняет гонку «клик до маунта Player» — интент
  откладывается до готовности);
- все ~18 точек запуска мигрируют на него; ленивые quick-look-фетчи релиза/плейлиста
  выносятся в общий хук `useLazyQueue(kind, id)`.

**Очередь и шаффл** — одна семантика вместо двух:
- shuffle ON: `originalQueue` сохраняется, остаток после текущего перемешивается
  Фишером–Йетсом, `queue = [current, ...shuffled]`;
- shuffle OFF: восстановление `originalQueue`, индекс = позиция текущего;
- `next`/`prev` просто ходят по `queue` — «назад» всегда возвращает к реально
  игравшему треку;
- «Перемешать» в плейлисте = `playQueue(tracks, { shuffle: true })` — та же механика.

**Персист** (`zustand/persist`, localStorage, versioned):
`track, queue(≤100), queueIndex, volume, waveMode, shuffle, context, положение
(currentTime, throttle 5с)`. После рестора: пауза, манифест не грузится до первого
пользовательского play (autoplay-политики), затем resume-seek. `waveformPeaks` не
персистится (приходит с манифестом).

**Производительность**: `currentTime` уходит из store-подписок. Движок даёт
`getAudioTime()`; листовые компоненты (тайм-лейблы, прогресс, waveform-прогресс,
LRC-подсветка) используют локальный хук `useAudioTime(fps)` (rAF/interval) — играющий
трек больше не ререндерит всё дерево плеера. В store `currentTime` обновляется только
на seek/смене трека/персист-тике. Waveform-бары считаются один раз на peaks
(`useMemo`), прогресс — маской/overlay, не пересчётом баров.

**Дедупликация**: `lib/session-id.ts` (один `getSessionId`); один компонент
`components/player/waveform-scrubber.tsx` (props: peaks, barCount, markers?,
variant) для плеера и страницы трека; тип volны — из `packages/api-contracts`
(zod, один источник); кэш манифестов (LRU ~10) + префетч манифеста следующего
трека при остатке <15с — быстрые переходы. LRC в фуллскрине: если текст уже есть
в очереди/пропах — не перефетчивать (кэш по trackId в сторе лирики).

### 2. Волна v2 (сервер)

Файл остаётся в `packages/db/src/queries/wave.ts` (SQL-репозиторий — принятый в
кодовой базе паттерн), но **чистые сигналы выносятся в `packages/core`**
(тестируемые функции без БД): нормализация тональности, веса скоринга.
Документация `wave.md` приводится к реальности.

**API**: `GET /api/v1/wave?sessionId&trackId?&mood?&genre?&count=3` →
`{ tracks: WaveTrack[] }` (zod-схема в api-contracts).
- **Пачки + буфер**: клиент держит ≥2 непроигранных трека впереди; дозапрос при
  остатке ≤2 (не в момент `ended`) → пауз между треками нет.
- **Серверный анти-повтор**: Redis SET `wave:served:{sessionId}` (SADD + EXPIRE 6ч)
  всех выданных id; деградация при недоступном Redis — к клиентскому `played`
  (шлётся как и раньше, уже без среза в 30, но с потолком запроса ~100).
- **Разнообразие артистов**: штраф кандидатам, чей артист среди последних ~5
  выданных (артисты выводятся join'ом по served-ids).

**Сигналы**:
- `keyScore`: свободный `musicalKey` парсится в pitch-class+mode
  (`packages/core/src/services/camelot.ts`: «Am», «C#m», «8A», «F♯ minor» → Camelot);
  та же = 1, соседняя/параллельная по кругу = 0.6, иначе 0 (вес 0.5). Не парсится → 0.
- `genreScore` — один: приоритет `track_genres` (доля совпавших), фолбэк на
  `releases.genre` только когда у трека нет жанров. Двойной учёт устраняется.
- Веса — именованные константы в `packages/core` с юнит-тестами на монотонность.
- `tasteMoodScore` берёт данные из единого профиля вкуса (см. §3) — moods И genres.

**Seed v2** (первый трек):
- вошедший: скоринг кандидатов по профилю вкуса (moods+genres) + качество
  (дослушивание) + шум `random()*0.3`, `ORDER BY score DESC LIMIT 1` — тот же
  запрос, что основной, без компоненты похожести;
- аноним: популярность-взвешенный случайный — `ORDER BY log(plays30+1) * random() DESC`;
- `mood=`/`genre=` — жёсткий фильтр seed'а И мягкий сигнал (буст) для всех
  последующих треков волны этой сессии (mood/genre сессии хранится рядом в Redis).

**Жанровые чипы**: `getGenreCounts()` (аналог `getMoodCounts`), волна принимает
`genre=` — вход с главной.

### 3. Единый профиль вкуса

`packages/db/src/queries/taste.ts`: `getTasteProfile(userId)` →
`{ topMoods, topGenres, topArtistIds }` (лайки ∪ прослушивания, окно 90 дней).
Потребители: волна (замена ad-hoc tasteMoodRows), генерация личных подборок,
`getPersonalTrackPicks`. Один источник правды вместо четырёх.

### 4. Рекомендации и главная

- **Ранжирование подборок**: `moodTrackIds`/`mixRows` получают
  `ORDER BY plays30d DESC, releaseDate DESC` + шумовая ротация на прогон —
  конец «произвольных 25 треков». Общий билдер `topTracksByPlays(days, limit)`
  переиспользуется discovery (Горячие) и editorial (TRENDING).
- **Личные подборки**: сигнал = профиль вкуса (moods + genres); внутри одного
  прогона треки не дублируются между «Для тебя» и mood-подборками (exclusion set).
- **`getPersonalTrackPicks`**: исключает лайкнутые и недавно игранные
  (это «открой новое», а не «ты это уже слушал»); артисты — из профиля вкуса.
- **Дедуп секций главной**: «Для тебя» исключает id из «Продолжить слушать»;
  «Горячие треки» остаются каноничным чартом (не фильтруются). Каталожные
  секции (релизы) не трогаем.
- `/feed` остаётся хронологией (осознанно, вне скоупа).

### 5. Безопасность и API-гигиена

- `/api/v1/tracks/[id]/manifest`: отдаётся только если трек `READY` и релиз
  опубликован (`PUBLISHED`/`SCHEDULED` с прошедшей датой) и артист активен;
  владелец-артист и MODERATOR+ — без ограничения (предпрослушка). Иначе 404.
- Rate-limit (существующая утилита wave): manifest, play, listening, presence.
- `source` в play-событиях — реальный контекст из PlayContext.

### 6. Редизайн UI (Impeccable по умолчанию)

Полный редизайн при сохранении функционала и жестов:
- **Мини-бар**: прогресс тонкой линией по верхней кромке, обложка со скруглением,
  заголовок/артист-ссылки, лайк, индикатор волны, кнопка очереди; акцент артиста
  работает всегда (теперь цвет доезжает из всех входов).
- **Фуллскрин**: cover-forward, фон — глубокий градиент от акцента артиста
  (OKLCH-затемнение, не серость), waveform-скраббер, LRC-панель, очередь
  «Дальше» с видимым буфером волны; swipe-down сохраняется;
  `prefers-reduced-motion` уважается.
- **Блок «Поток» на главной**: редизайн с двумя рядами чипов — настроения и жанры
  (единый скроллируемый рейл с подписями), состояние «волна играет» (Остановить).
- Очередь: reorder не строим (YAGNI), но «Дальше» показывает и треки волны.
- Мобилка проверяется на каждом экране (узкий вьюпорт, жесты, отсутствие
  громкости на тач-устройствах — текущее правило сохраняется).

## Миграции БД

Не требуются: `musicalKey` остаётся text (нормализация на чтении), анти-повтор — в
Redis, `source` — уже text. Это осознанно: минимизируем риск.

## Ошибки и деградация

- Redis недоступен → волна работает на клиентском `played` (как сейчас), presence
  → 0 (как сейчас).
- Ошибка фетча волны при старте → toast (унифицировать: сейчас есть только в чипах).
- Ошибка загрузки трека в потоке → skip к следующему из буфера (не вечный спиннер);
  watchdog 20с сохраняется.
- Рестор из localStorage: битые/устаревшие данные → чистый старт (versioned persist).

## Тестирование

- `packages/core`: camelot-парсер/дистанция, веса скоринга (чистые функции).
- `packages/db` — запросы не юнит-тестируются (паттерн кодовой базы), логика
  вынесена в core максимально.
- `apps/web`: route-тесты wave (валидация параметров, count-потолок, rate-limit),
  manifest (доступ: READY/unpublished/owner/admin), play (реальные source);
  юнит-тесты queue-хелперов (Фишер–Йетс, shuffle on/off, next/prev, персист-рестор),
  `to-player-track`; существующие 200 тестов остаются зелёными.
- Гейты: typecheck, lint, check:routes, test, audit:design, build.

## Критерии успеха

1. В потоке нет слышимой паузы между треками (буфер ≥2, префетч манифеста).
2. Треки не повторяются в рамках wave-сессии (6ч, сервер).
3. Плеер после F5: тот же трек/очередь/позиция на паузе.
4. Шаффл честный, prev возвращает к реально игравшему треку, «перемешать» в
   плейлисте включает режим шаффла.
5. Акцент артиста в плеере — со всех входов.
6. `play_events.source` отражает реальный источник.
7. Подборки ранжированы и ротируются; «Для тебя» не показывает уже лайкнутое.
8. Чипы жанров запускают жанровую волну.
9. Манифест недоступен для неопубликованных треков посторонним.
10. Все гейты зелёные; доки фич соответствуют коду.

## Вне скоупа

Жанровые страницы-радио, reorder очереди, gapless через второй audio-элемент,
ML-эмбеддинги, автоанализ BPM/key (роадмап), rollup-агрегаты play_events
(отдельная задача при росте), ранжирование /feed.
