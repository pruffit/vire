# Десктоп-клиент, срез 1 — трей и медиа-клавиши — дизайн

**Статус:** реализуется · **Основание:** `docs/multiplatform.md` §3.2, продолжение среза 0
(`docs/features/desktop-app.md`, `docs/superpowers/specs/2026-08-16-desktop-shell-slice-0-design.md`)

## Что это

Второй срез: то, что десктоп реально даёт поверх PWA — системный трей и OS-медиа-клавиши.
Мини-плеер поверх окон, глобальные хоткеи при свёрнутом окне, автозапуск — следующие срезы,
не этот.

## Скоуп среза 1

- **Трей-иконка**: левый клик — показать/сфокусировать главное окно. Правый клик — меню:
  «Показать VireMusic», разделитель, «Play/Pause», «Следующий трек», «Предыдущий трек»,
  разделитель, «Выход». Пункты меню — статичные команды (fire-and-forget), без синхронизации
  подписи с реальным состоянием воспроизведения (не «Пауза» ⇄ «Играть» по факту) — это
  требует канала веб→Rust, отдельный срез.
- **OS-медиа-клавиши**: Play/Pause/Next/Previous с клавиатуры перехватываются, даже когда
  окно не в фокусе — через `tauri-plugin-global-shortcut` (официальный плагин Tauri v2).
  **Не гарантировано заранее**: захват именно медиа-клавиш (`VK_MEDIA_PLAY_PAUSE` и т.п.,
  не обычные комбинации) через этот плагин на Windows нужно проверить эмпирически — плагин
  в первую очередь рассчитан на обычные хоткеи (`Ctrl+Shift+P`), поддержка нативных
  multimedia-клавиш может быть неполной. Если плагин их не ловит — задокументировать как
  известное ограничение среза, не блокироваться и не городить обходной путь через сырой
  WinAPI (`RegisterHotKey`/raw input) — это отдельная, более рискованная работа, не в этом
  срезе. Трей в любом случае даёт управление без медиа-клавиш.

## Мост Rust → веб-страница (главное архитектурное решение)

Проблема: команды (toggle/next/prev) нужно передать в уже загруженную веб-страницу и
вызвать реальное управление плеером.

**Плеер уже даёт готовую точку входа**: `apps/web/lib/player/audio-engine.ts` экспортирует
синглтон `controls` с методами `controls.togglePlay()`, `controls.next()`, `controls.prev()`
— именно это использует существующий UI плеера (см. `use-play.ts` и компоненты плеера).

**Решение — `WebviewWindow::eval(js)`, НЕ Tauri IPC/events.** Срез 0 грузит webview как
`WebviewUrl::External` (`https://viremusic.ru` / `localhost:3000`) — обычный удалённый
origin, не Tauri-бандленная локальная страница. Tauri по умолчанию НЕ инжектит
`window.__TAURI__`/IPC-мост в произвольный удалённый origin (это защита от того, чтобы
любой JS сайта мог дёргать Tauri-команды) — включать это специально
(`dangerousRemoteDomainIpcAccess`) означает выдавать продовому JS права на IPC-канал,
несоразмерный риск ради fire-and-forget команд плеера. `eval()` — другой, более узкий
канал: Rust напрямую просит вебвью (WebView2 на Windows) выполнить произвольный JS-текст
в контексте уже загруженной страницы, это часть оконного API Tauri, а не IPC-протокола,
работает независимо от origin страницы и не даёт странице встречных прав.

**Со стороны веба**: новый маленький модуль `apps/web/lib/desktop-bridge.ts` — при загрузке
клиентского бандла плеера (там же, где инициализируется `usePlayerStore`/`audio-engine`)
выставляет `window.__vireDesktopBridge = { togglePlay: controls.togglePlay, next:
controls.next, prev: controls.prev }`. Это обычный глобальный объект: в браузере он просто
не используется — не требует детекции «я внутри Tauri», ничего не скрывает и не открывает
дополнительных прав (те же функции и так вызываются кликами по кнопкам плеера).
Rust дергает `window_handle.eval("window.__vireDesktopBridge?.togglePlay()")` и т.п.

## Явно НЕ в этом срезе

- Синхронизация состояния (подпись «Play»/«Пауза» в трее и на медиа-клавишах по факту)
- Мини-плеер поверх других окон (отдельное окно/оверлей)
- Глобальные хоткеи произвольных сочетаний (`Ctrl+Shift+P` и т.п.) — только сами медиа-клавиши
- Автозапуск при входе в систему
- `dangerousRemoteDomainIpcAccess` / любой Tauri IPC-доступ веб-странице — сознательно не
  открываем, весь мост в одну сторону через `eval`

## Проверка

`cargo tauri dev` с поднятым `pnpm --filter @vire/web dev`: клик по пунктам трея реально
переключает воспроизведение уже играющего трека (запустить трек через обычный UI плеера
в открытом окне, затем проверить команды из трея) — не только «код скомпилировался».
Медиа-клавиши — задокументировать факт (сработали/не сработали на этой машине), не более
того: аппаратная зависимость (клавиатура без спец-клавиш) не повод считать фичу нерабочей,
но плагин должен как минимум зарегистрироваться без ошибки.
