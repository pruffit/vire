# Пачка «Отложенное из критики главной» — дизайн

Дата: 2026-07-13. Источник: `docs/roadmap/TODO.md` → «Отложенное из критики главной (13.07.2026)».
Пять независимых пунктов, один релиз.

## 1. CoverFan fallback на тонком каталоге

**Проблема.** `getEditorialPlaylists` (`packages/db/src/queries/playlists.ts`) собирает
`covers` из обложек релизов треков плейлиста: дедуп есть только против обложки самого
плейлиста, но не между обложками треков. Несколько треков одного релиза → один и тот же
URL повторяется → `CoverFan` (`editorial-playlist-card.tsx`) рисует веер из трёх
одинаковых картинок.

**Решение (два слоя):**
- Данные: в цикле сборки `coversByPlaylist` не пушить URL, уже лежащий в списке
  (`!list.includes(url)` — список ≤4, линейный поиск дешевле Set на строках).
- UI: `buildFan` дедуплицирует вход перед раскладкой (защита от любых будущих
  источников). После дедупа 1 уникальная обложка → уже существующая ветка «одна
  плоская обложка», 2 → ветка двух. Новых визуальных состояний не появляется.

## 2. Skeleton-состояния секций главной (стриминг)

**Проблема.** `app/(listener)/page.tsx` — один async-компонент, `Promise.all` из ~15
запросов: страница ждёт самый медленный, потом всё появляется разом; плейсхолдеров нет.

**Решение.** Перевести главную на React-стриминг с `<Suspense>`:
- **Блокирующая часть** (в самом `page.tsx`): `auth()`, hero `FeaturedRelease`
  (LCP — за Suspense не прячем) + `FlowBlock` (лёгкие counts). `getLatestReleases`
  оборачивается в React `cache()` — им делятся hero и стримовая секция «Свежие релизы».
- **Стримовые секции** — async server-компоненты в `app/(listener)/home-sections.tsx`
  (или по файлу на секцию в `components/home/`), каждая фетчит своё с существующими
  `.catch(() => [])`:
  - `PersonalBlock` (RecentRail + «Для тебя», только userId),
  - `FeedSection` («Новое у подписок», только userId),
  - `HotTracksSection`, `FreshReleasesSection`, `UpcomingSection`,
  - `ListeningNowSection`, `PlaylistsSection` (3 запроса + liked), `ArtistsSection`.
- **Fallback-скелетоны** — только у секций, которые почти всегда непустые
  (HotTracks, Свежие релизы, Подборки, Артисты): заголовочная плашка + ряд
  карточек-заглушек с теми же размерами (`w-48/w-40/w-28 aspect-square` + две строки
  текста), чтобы замена fallback→контент не сдвигала лейаут. Условно-пустые секции
  (персональные, фид, upcoming, listening-now) стримятся с `fallback={null}` —
  скелетон, исчезающий в ничто, дал бы больший сдвиг, чем позднее появление ниже сгиба.
- **Без анимации скелетонов** (никаких `animate-pulse`): бесконечные opacity-анимации
  на видимых элементах запрещены анти-джиттер-правилом app-shell. Статичные блоки
  `bg-foreground/[0.04]` + `rounded`.
- Пустое состояние каталога (`empty`) переезжает в стримовую секцию артистов/релизов
  (проверка после фетча) — блокирующая часть о нём не знает.

## 3. «Играть следующим» / «В очередь» с карточек хаба

**Модель (чистые функции, `apps/web/lib/player/queue.ts`):**
- `insertIntoQueue(queue, queueIndex, tracks, position: 'next' | 'end')` →
  `{ queue, inserted }`: дедуп входа, треки, уже присутствующие в очереди, не
  вставляются повторно (`inserted` — сколько реально вошло; 0 → тост «Уже в очереди»).
  `next` — после `queueIndex`, `end` — в конец.
- Юнит-тесты в `lib/player/queue.test.ts` рядом с существующими.

**Движок (`controls` в `audio-engine.ts`):**
- `controls.enqueue(tracks: PlayerTrack[], position: 'next' | 'end', context?)`:
  - очередь пуста / нет `track` → ведёт себя как `playQueue` (начать играть);
  - иначе патчит `queue` (и `originalQueue` при `shuffle=true` — вставка после позиции
    текущего трека в оригинале для `next`, в конец для `end`) через `_setState`;
  - `waveMode` не выключает: вставленные треки играют раньше докупленного буфера волны.
- Возвращает число вставленных — UI показывает тост.

**UI (только карточки главной, по бэклогу):**
- `ReleaseQuickLook` peek-шит: рядом с «Слушать» два вторичных действия
  «Дальше» / «В очередь» (весь релиз через `useLazyQueue.load()`).
- Строки треков на главной (`HotTracks`, «Для тебя» → `PlayableTrackList`): кебаб-меню
  (⋯) в `trailing`-слоте `TrackRow` с теми же двумя пунктами для одного трека.
  Меню — переиспользовать существующий поповер-паттерн (`TrackShare`), не тянуть
  новую зависимость; тач-таргет ≥44px.
- Тосты: «Будет следующим» / «В очереди» / «Уже в очереди».

## 4. Ревизия чипов «Потока»

**Проблема.** Под hero: `WaveStartButton` (CTA «Запустить») + два подписанных ряда
(все настроения + все жанры) — 11+ чипов, три конкурирующие точки входа в один флоу.

**Решение.** Один ряд вместо двух:
- `FlowBlock` объединяет mood- и genre-чипы в один `WaveChips`-ряд: топ-N по `count`
  смешанно (mood и genre вперемешку), кап **8 видимых**; подписи рядов
  («Настроение»/«Жанр») уходят.
- Хелпер `topWaveChips(moods, genres, cap)` в `wave-chip-items.ts` (чистая функция,
  сортировка по count, стабильный tie-break по label) + юнит-тест.
- `WaveStartButton` остаётся единственным главным CTA. Итог: CTA + один ряд из 8.
- Лейблы mood/genre самодостаточны («Спокойное», «Хип-хоп») — префиксы вида не нужны;
  `kind` сохраняется внутри item для сида волны.

## 5. Компонентный тест Announcements

`apps/web/components/announcements.test.tsx` (`@vitest-environment jsdom`,
`@testing-library/react` — уже в devDeps):
1. чистый localStorage → маунт → авто-показ первого анонса (`stage1`);
2. клик «Понятно» → диалог закрыт, `vire_notice_stage1_v1` записан,
   **второй анонс (`auth`) не появляется в этом же маунте**;
3. новый маунт (ремаунт) → показывается `auth`;
4. ручное открытие через `OPEN_ANNOUNCEMENT_EVENT` работает и после потребления
   авто-показа, закрытие ручного не пишет seen-флаг.

## Тестирование и гейты

- Юнит: `insertIntoQueue`, `topWaveChips`, дедуп `buildFan` (экспортировать хелпер),
  тест Announcements.
- Инвариант app-shell (`layout-shell.test.ts`) не трогаем — скелетоны без запрещённых
  анимаций, `min-h-screen` не появляется.
