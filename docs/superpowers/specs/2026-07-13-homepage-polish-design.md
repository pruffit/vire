## Контекст и рамки

Главная уже переработана в v1.6.0 (Spotify-Home модель) — это **полиш внутри принятой
модели**, не ре-концепт. Ограничения продукта: никакого поиска на главной, никаких
слоганов; главная = контент-хаб. Ключевой диагноз критики: компоненты качественные,
страница проседает на макро-уровне — стек модалок до первой ноты, «мёртвые» сетки на
малом каталоге, монотонный ритм после hero.

## Решения

### 1. [P1] Один авто-анонс за визит (`components/announcements.tsx`)

Сейчас закрытие авто-анонса сразу показывает следующий из очереди (стек из двух модалок
первому гостю). Меняем: за один маунт показывается максимум один авто-анонс; закрытие
помечает его просмотренным и НЕ открывает следующий — тот выйдет при следующем визите.
Ручное открытие (`OPEN_ANNOUNCEMENT_EVENT`) не меняется.

Реализация: выбор активного анонса вынести в чистый хелпер
`nextAutoAnnouncement(announcements, isSeen)` (модульно тестируемый); после закрытия
авто-анонса компонент запоминает «в этом маунте уже показывали» и больше не берёт из
очереди. Тест: `announcements.test.ts` на хелпер + логику «один за маунт» (jsdom не
обязателен — хелпер чистый, поведение маунта покрыть через выделенную функцию-редьюсер,
если компонентный тест дорог).

### 2. [P1] «Мёртвые» сетки → content-width rails (`app/(listener)/page.tsx`)

«Скоро выйдет» (GRID 6 кол.) и «Артисты» (grid 8 кол.) при 1–3 айтемах — пустой холст,
читается как заброшенность. Обе секции переводим на `ScrollRow` (переиспользование, как
«Свежие релизы»/«Подборки»): ширина определяется контентом, при росте каталога —
горизонтальный скролл с существующими краевыми зонами.

- «Скоро выйдет»: `ReleaseQuickLook upcoming` в rail, ширина карточки w-40 (как сейчас).
- «Артисты»: `ArtistHoverChip` в rail с фиксированной шириной айтема (w-28~32 по факту
  текущей сетки); проверить, что hover-превью чипа не клипается ScrollRow (вертикальный
  выпуск `-my-2 py-2` уже является паттерном; если превью — портал, проблемы нет).
- Константа `GRID` в page.tsx после этого не используется → удалить.

### 3. [P2] Ритм: масштаб «Свежих релизов» + mono-счётчики секций

- Карточки «Свежих релизов» w-40 → **w-48** (главная контентная лента крупнее
  остальных rails; «Новое у подписок»/«Подборки» остаются w-40) — осознанный сбой
  однородности «всё по 160px».
- `listener/section.tsx`: показывать mono-`count` и при наличии `href` (сейчас count
  рендерится только без ссылки) — «Свежие релизы 12 · Посмотреть все →». TE-ридаут
  данных в заголовках. Передать count из page.tsx для секций, где известен размер
  (rest.length, allPlaylists.length, topArtists.length).

### 4. [P2] Hero: TE-ридаут данных (`featured-release.tsx`, `packages/db`)

Мета-строка hero обогащается инструментальными данными: `АЛЬБОМ · 2025 · 8 ТРЕКОВ · 34:12`.

- Новый запрос в `packages/db/src/queries/discovery.ts`: `getReleaseCardStats(releaseId)`
  → `{ trackCount: number; totalDurationSec: number }` одним запросом по `tracks`
  (только READY-треки; duration из `track_audio` — свериться с тем, как длительность
  считает страница релиза, и переиспользовать подход). Экспорт из `@vire/db`.
- page.tsx зовёт его только для `featured` (`.catch(() => null)` — секция не роняет
  страницу), прокидывает в `FeaturedRelease` опциональным пропом `stats`.
- Формат: `pluralTracks` + `totalDuration`/`formatDuration` из `apps/web/lib/format.ts`
  (уже есть и покрыты тестами). `stats == null` или `trackCount === 0` → мета как сейчас.

### 5. Casey: тап-таргет «Запустить» (`wave-start-button.tsx`)

Кликабельная область кнопки «Запустить» ≥44×44px (padding/hit-area), не меняя визуальный
размер строки «Поток».

### 6. [§2.3] Снять Stagger из PlayableTrackList (`track-list.tsx`)

Единственный оставшийся промоутер композит-слоя на главной: `Stagger`/`StaggerItem`
(motion) оставляют transform-слои на строках «Для тебя» и «Горячих треков»
(зафиксированный паттерн джиттера, рецидивы v1.0.41–v1.13.0). Замена: контейнер —
обычный `div` с одноразовой CSS-анимацией `animate-fade-up` (по завершении CSS-анимации
слой демотируется, в отличие от inline-transform motion); поэлементный каскад убираем
(жертвуем им ради гладкого скролла — принятый компромисс). `motion.div whileTap` на
строках остаётся (слой только на время жеста). Затрагивает также /search
(search-tracks-section) — поведение то же, отдельной работы нет.

Reveal с главной снят ранее — упоминание «Reveal-секции на главной» в stage-2 §2.3
устарело, поправить формулировку при закрытии.

### 7. Токены: FlowBlock (`home/flow-block.tsx`)

`bg-white/[0.03] ring-white/10` → токены (`bg-card`-производные / `border`-токены,
сверить с ui-kit). Hardcode `#0c0b0a` и `white/X` в hero НЕ трогаем — осознанный
изолированный канвас под изображением (всегда тёмный независимо от темы).

### 8. [§1.8] Комментарии в затронутых файлах

Снять пересказы «что делает» (например `featured-release.tsx` «Затемнение под текст
(контраст)»), оставить только quirks (UTC-гидрация, обходы композит-слоёв, sizes-ретина и т.п.).
Только файлы, затронутые этим проходом.

## Не делаем (зафиксировано как отложенное)

- Чипы «Потока» (11 видимых) — ценность механики, не режем; пересмотр при следующем проходе.
- CoverFan fallback на тонком каталоге, skeleton-состояния секций, «в очередь»/«следующим»
  с карточек (Alex), compact-режим — в бэклог TODO.md.
- Ре-концепт Spotify-Home-скелета (вопрос №2 критики) — продуктовая развилка, не полиш.
