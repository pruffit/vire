# Плейлисты: обложки-коллажи + шеринг — дизайн

Закрывает хвост stage-2 §7.3 (обложки-коллажи, шеринг). Коллаборативность
(`is_collaborative`) — вне скоупа, она стыкуется с §8 «Джем».

## Проблема

1. **Обложка.** Пользовательский плейлист без своей обложки выглядит пустым:
   шапка `/playlists/[id]` и карточка в медиатеке падают в `coverUrl ?? tracks[0] ?? иконка`.
   При этом коллаж уже реализован — `hydratePlaylists` собирает до 4 обложек треков,
   `CoverFan` их рисует, — но только для редакционных подборок на главной.
2. **Шеринг.** Поделиться плейлистом нельзя вообще: компонента нет, `generateMetadata`
   отдаёт только `title`, OG-картинки нет → ссылка в мессенджере разворачивается
   в дефолтную заглушку платформы.
3. **Попутно.** `getUserPlaylists` (`packages/db/src/queries/playlists.ts:72`) — N+1:
   на каждый плейлист два отдельных запроса (`count` + первый трек) в `Promise.all`.

## Решения

### Коллаж

- **Мозаика 2×2 только при ≥4 уникальных обложках.** При 1–3 — первая обложка,
  при 0 — плейсхолдер. Частичная мозаика оставляет дыры и читается как поломка;
  тот же порог у Spotify/Apple.
- **Своя обложка всегда побеждает** — коллаж это фолбэк, не замена.
- **Веер `CoverFan` на главной не трогаем** — другой визуальный язык (карточки хаба,
  наклонённые слои). Общим выносим только плейсхолдер-иконку и выборку обложек,
  чтобы не держать два источника правды.
- Новый `components/playlist-cover.tsx` — единственная точка фолбэка обложки плейлиста:
  `variant="mosaic"` (шапка, карточка медиатеки) и `variant="single"` (сайдбар 40px —
  четыре картинки в 40px читаются как шум, там всегда первая обложка).
- Раскатка: шапка `/playlists/[id]`, `components/listener/playlist-card.tsx`,
  `components/listener/library-sidebar.tsx`.

### Данные

- Выделить `fetchPlaylistMeta(ids): Map<id, { trackCount, covers }>` — то, что сейчас
  зашито внутри `hydratePlaylists` (два batch-запроса на все id сразу).
  `hydratePlaylists` строится на нём; `getUserPlaylists` переводится на него же →
  N+1 уходит, `PlaylistSummary` получает `covers: string[]`.
- Страница плейлиста: `getPlaylistWithTracks` уже отдаёт треки с `coverUrl` — обложки
  для шапки берутся из них чистой функцией `pickCovers(playlistCoverUrl, trackCovers)`
  (дедуп, ≤4, своя обложка первой). Покрыть тестом.

### Шеринг

- `PlaylistShare` в шапке `/playlists/[id]`:
  - **PUBLIC** → копировать ссылку; на тач-устройствах сперва `navigator.share`
    (нативный шит), с фолбэком на копирование.
  - **PRIVATE + владелец** → «Сделать публичным и поделиться»: один клик делает
    `PATCH { visibility: 'PUBLIC' }`, затем копирует ссылку.
  - **PRIVATE + не владелец** недостижим — страница отдаёт 404.
  - Secret-link с токенами **не вводим**: отдельная таблица токенов ради фичи,
    которой никто не просил; модель видимости PUBLIC/PRIVATE уже есть.
- Появляется 4-й поповер → выносим общий примитив `components/popover.tsx`
  (outside-click + Escape + AnimatePresence-шелл + позиционирование/флип) и переводим
  на него `track-share.tsx` и `track-queue-menu.tsx`. Это записанный техдолг из
  `TODO.md` («третья копия поповер-паттерна»).

### OG-картинка и метаданные

- `app/(listener)/playlists/[id]/opengraph-image.tsx` — динамическая `ImageResponse`
  (паттерн из `app/opengraph-image.tsx`: nodejs runtime, 1200×630): коллаж/обложка
  слева, название + автор + число треков справа.
- **Приватность гейтится внутри самой OG-картинки.** Роут OG публичный и сессии не
  видит → для `PRIVATE` он не должен отдавать ни названия, ни обложек; отдаём
  нейтральный фирменный фон. Это тест, а не комментарий.
- `generateMetadata`: для PUBLIC — canonical + OG/Twitter; для PRIVATE — `robots: noindex`
  и никаких OG-полей.

## Что НЕ делаем

- Коллаборативные плейлисты (`is_collaborative`) — §8.
- Кроп/ресайз обложки на клиенте — как и было, ограничение фичи.
- Изменение `CoverFan`/карточек главной.

## Тесты

- `pickCovers` — дедуп, приоритет своей обложки, порог 4 (чистая функция).
- `fetchPlaylistMeta` / `getUserPlaylists` — covers и trackCount без N+1.
- OG-роут приватного плейлиста **не отдаёт название** (регресс на утечку).
- `PATCH visibility` из шеринга — только владелец (роут уже owner-gated, тест на месте).
