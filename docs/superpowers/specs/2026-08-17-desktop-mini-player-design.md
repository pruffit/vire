# Десктоп: мини-плеер поверх окон — дизайн

**Контекст:** `apps/desktop` (Tauri v2, срезы 0–7 закрыты — `docs/features/desktop-app.md`).
Следующий пункт из «Ограничения/на будущее»: отдельное always-on-top окно с обложкой/
названием/транспортом, не требующее фокуса на главном окне.

## Ключевая развилка: как окно мини-плеера узнаёт состояние плеера

IPC от прод-домена (`viremusic.ru`/`localhost:3000`) в Rust сознательно не открыт нигде в
проекте (`docs/features/desktop-app.md` → «Трей и медиа-клавиши»): единственный мост —
одностороннний `WebviewWindow::eval` (Rust → веб). Открывать `dangerousRemoteDomainIpcAccess`
ради мини-плеера — та же категория решения, что уже один раз сознательно отложена для
синка подписи трея (срез 2) — не делаем.

**Решение: не трогать Rust/IPC вообще.** Мини-плеер — обычная страница того же домена
(`/desktop/mini-player`), синк с главным окном — через `BroadcastChannel` (стандартный
веб-API, сообщения долетают между разными окнами/вкладками одного origin в одном
storage-partition, без участия нативного кода). Два окна Tauri, грузящие один origin,
по умолчанию используют один и тот же WebView2-профиль — проверяется эмпирически в
реализации (тот же принцип, что и remainder слайсов: не верить, а прогнать).

Если эмпирика опровергнет (BroadcastChannel не долетает между окнами) — запасной путь:
локальный HTTP-сервер в Rust на 127.0.0.1 (fetch из обеих страниц, без Tauri IPC) — задел
в этом дизайне не реализуется заранее, только фиксируется как fallback.

## Компоненты

### 1. Веб: чистая страница без chrome

`/desktop/mini-player` — top-level, нелокализованный маршрут (как `/admin`, `/fwqa688`).
Корневой `app/layout.tsx` монтирует `Nav`/`PlayerWrapper`/`MobileTabBar`/`DeferredWidgets`/
чат-бутстрап/`YandexMetrika` **безусловно для всех роутов** — второй root layout в
Next.js потребовал бы убрать текущий `app/layout.tsx` и завести группы для каждой
существующей ветки (весь `[locale]`, `admin`, `fwqa688`, `sitemaps`, `api`) — непропорционально
для одного окна. Вместо этого: `proxy.ts` для `pathname.startsWith('/desktop/mini-player')`
пропускает без i18n-редиректа (как `/fwqa688`) и форвардит запросный заголовок
`x-desktop-chrome: none` (тот же приём, что next-intl уже использует для `x-next-intl-locale`,
см. `headerLocaleOrDefault()` в `layout.tsx`). Root layout читает заголовок и скипает
монтирование chrome-компонентов для этого пути — минимальный, точечный диф, не трогающий
инвариант «один root layout».

Страница НЕ монтирует `PlayerWrapper` → не инициализирует `audio-engine.ts` → никакого
дублирования звука. Она только читает и шлёт сообщения через `BroadcastChannel`.

### 2. Веб: синк в главном окне

`apps/web/lib/desktop-bridge.ts` (существующий файл, тот же паттерн, что уже используется
для трея/медиаклавиш) расширяется: на десктопе (`isDesktopApp()`) открывает
`new BroadcastChannel('vire-desktop-player')`, подписывается на `usePlayerStore`
(track/isPlaying/positionSec/durationSec), рассылает обновления (на смену состояния + раз
в секунду во время игры — для прогресс-бара), отвечает на `{type:'requestState'}` (окно
мини-плеера, открытое позже старта трека, догоняет состояние при маунте), принимает
`{type:'togglePlay'|'next'|'prev'}` и вызывает те же `controls.*`, что уже вызывает
`bridge.rs` через `eval` — исполнение команды не дублируется.

### 3. Веб: UI мини-плеера

Обложка, название/артист (marquee при переполнении), прогресс-бар (визуальный, из
присланного состояния + локальная интерполяция таймером между сообщениями), три кнопки
(prev/play-pause/next). Область окна — `data-tauri-drag-region` (перетаскивание
безрамочного окна). Никакой кнопки закрытия в странице — см. «Открыть/закрыть» ниже.

### 4. Rust: второе окно

`apps/desktop/src-tauri/src/main.rs`: пункт трея-меню «Мини-плеер» (`CheckMenuItem`, тот же
паттерн, что автозапуск, срез 3) — создаёт/показывает/прячет `WebviewWindow` (label
`"mini-player"`), ~300×110, `always_on_top(true)`, `decorations(false)`, `resizable(false)`,
`skip_taskbar(true)`, `WebviewUrl::External(shell_url() + "/desktop/mini-player")`.
`CloseRequested` на этом окне — `prevent_close()` + `hide()`, тот же паттерн, что у главного
окна (срез 4) — открывается заново только через пункт трея. Не форсирует скрытие/показ
главного окна — независимое дополнительное окно, не замена.

`tauri-plugin-window-state` уже трекает любое не-denylisted окно — `"mini-player"` не
добавляется в denylist (в отличие от `"splash"`), позиция/размер переживают перезапуск
без дополнительного кода.

## Что сознательно не делаем в этом срезе

- Не открываем Tauri IPC ни для одного окна — исполнение дизайна проверяет это как инвариант.
- Не форсируем скрытие главного окна при открытии мини-плеера (и обратно).
- Не даём в-страничную кнопку закрытия — единственная точка управления видимостью — трей
  (тот же принцип, что у автозапуска: «других поверхностей управления нет»).
- Не делаем кастомные хоткеи под мини-плеер — вне скоупа.

## Проверка (эмпирически, по образцу остальных срезов desktop-app.md)

- `BroadcastChannel` реально долетает между главным и мини-окном на собранном `.exe`
  (не просто в `cargo tauri dev`).
- Мини-плеер, открытый ДО начала воспроизведения — после `requestState` не показывает
  пустое состояние вечно.
- Мини-плеер, открытый ПОСЛЕ начала воспроизведения — синхронизируется в разумное время
  (розыгрыш периодического тика, не только событийных обновлений).
- Крестик (если решим оставить рамку) или трей-toggle — окно прячется, не убивает процесс.
- Позиция/размер окна переживают перезапуск `.exe`.
- `cargo tauri build` — оба бандла собираются.
