# Десктоп-клиент, срез 6 — сплэш-экран на холодном старте — дизайн

**Статус:** реализуется · **Основание:** продолжение срезов 0-5

## Проблема

Главное окно грузит `shell_url()` (localhost:3000 / viremusic.ru) как внешний URL —
на холодном старте это сетевой запрос, и пользователь несколько секунд видит пустое/белое
окно ОС, прежде чем страница отрисуется. Обычный неприятный первый опыт у любого
webview-приложения (тот же паттерн у Electron-based приложений).

## Решение — полностью нативно, без канала веб→Rust

Не требует IPC/eval/invoke — используется нативный Tauri-колбэк `on_page_load`
(`PageLoadEvent::Finished`), который Rust получает **напрямую от вебвью**, без участия
JS-кода веб-страницы:

1. Небольшое окно-сплэш (`WebviewWindowBuilder` с локальным HTML — можно взять
   существующий `apps/desktop/frontend-stub/index.html` за основу или сделать отдельный
   минимальный файл с логотипом/спиннером — без сети, грузится мгновенно), видимое сразу
   при старте.
2. Главное окно создаётся **скрытым** (`.visible(false)`), как и раньше, грузит
   `shell_url()`.
3. `.on_page_load(|window, payload| { if payload.event() ==
   tauri::webview::PageLoadEvent::Finished { window.show(); /* закрыть сплэш */ } })` на
   главном окне — как только страница реально догрузилась, показать его и закрыть сплэш.
4. Второй запуск при уже открытом приложении (single-instance, срез 5) не должен создавать
   сплэш вообще — там просто фокусируется существующее окно, сплэш-путь не участвует
   (проверить, что текущая структура кода это уже так делает, а не нечаянно завела бы
   второй сплэш).

## Риск, который нужно проверить эмпирически (не гадать)

`tauri-plugin-window-state` (срез 5) вешает свои слушатели на **любое** созданное окно —
если сплэш тоже попадёт под это, в `.window-state.json` может засориться лишняя запись
геометрии несуществующего постоянного окна. Проверить по факту: если плагин даёт способ
ограничить его конкретным окном (label) — использовать; если нет и мусор в json
безвреден (сплэш всё равно каждый раз новое короткоживущее окно с одним и тем же лейблом,
геометрия не важна) — задокументировать как принятый факт, не городить обход.

## Явно НЕ в этом срезе

- Анимация/брендинг сплэша сверх простого — минимальный логотип+спиннер достаточно
- Таймаут-фолбэк «показать окно всё равно через N секунд, если страница не догрузилась»
  — если понадобится по факту тестирования (страница реально виsnet), добавить, иначе нет

## Проверка

Собранный `.exe` (не `cargo tauri dev` — там hot-reload/уже тёплый Rust-кэш может смазать
ощущение холодного старта): запустить с нуля (веб-сервер живой) → сплэш появляется сразу,
исчезает, когда страница реально готова (не раньше — проверить, что это не просто таймер).
Второй запуск поверх уже открытого приложения — сплэш не появляется вообще, просто фокус.
