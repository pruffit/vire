# Дашборд слушателя: переработка оболочки платформы

**Дата:** 2026-06-28
**Статус:** черновик на ревью
**Тип:** фронтенд-рефактор оболочки (shell), новые/переработанные страницы

## Контекст и цель

Дашборды артиста (`/dashboard`) и админа (`/admin`) уже переработаны под левый
сайдбар + дизайн-кит. Всё остальное (публичная/слушательская часть) остаётся в
старой модели «верхний Nav с инлайн-ссылками + центрированный контент + футер».

Цель: превратить слушательскую часть в **дашборд для слушателя по модели Spotify** —
постоянный левый сайдбар с навигацией и медиатекой, переработанная главная под
персональный home-фид, разделение «Медиатеки» (контент) и «Профиля» (аккаунт),
удаление бесполезной страницы «Лента» и инлайн-ссылок из шапки.

Backend, API, схема БД — **не трогаются**. Это работа во фронт-слое (FSD):
`app/` (layouts/pages) + `components/` (widgets/features) + переиспользование
существующих репозиторных функций.

## Решения по продукту (закрыты с пользователем)

1. **Оболочка** — левый сайдбар (Spotify-модель), не обогащённый топ-бар.
2. **Глобальный верхний Nav сохраняется** на всех страницах (вкл. дашборды): лого,
   поиск, вход/выход, кнопки Дашборд (артистам) и Админка (модер+), ссылка на
   профиль. Убираются только центральные инлайн-ссылки **Артисты / Релизы / Лента**.
3. **Медиатека и Профиль — две разные страницы**: `/library` (твоя музыка) в сайдбаре,
   `/profile` (аккаунт/настройки) через Nav.
4. **Мобилка** — нижний таб-бар (Главная / Поиск / Медиатека), мини-плеер над ним.

## Архитектура оболочки

### Инварианты, которые НЕ нарушаем

- App-shell: `<body h-full overflow-hidden>`, скролла документа нет. Единственный
  скролл-контейнер — `#main-content` (root layout). Тест `app/__tests__/layout-shell.test.ts`.
- `ScrollState` и `ScrollRestoration` завязаны на `#main-content` — **второй скроллер
  не вводим**. Сайдбар реализуется как `sticky`-рейл внутри `#main-content`.
- Никаких `min-h-screen` / `h-screen` на страницах и layout'ах.
- Плеер — глобальный flow-элемент в root (играет и в дашборде), его не двигаем.

### Route-группа `(listener)`

Левый сайдбар нужен только на слушательских страницах. Вводим route-группу
`app/(listener)/` со своим `layout.tsx` (сайдбар). Дашборд/админка/auth/fwqa688
остаются вне группы и сайдбара не получают.

В группу `(listener)/` переезжают (URL не меняются — route-группа невидима в пути):

```
app/(listener)/
  layout.tsx          ← НОВЫЙ: sticky-сайдбар + контентная колонка + футер
  page.tsx            ← главная (из app/page.tsx)
  library/page.tsx    ← НОВАЯ страница «Медиатека»
  profile/            ← из app/profile (ужимается до аккаунта)
  artists/            ← из app/artists
  releases/           ← из app/releases
  playlists/          ← из app/playlists
  search/             ← из app/search
  smartlink/          ← из app/smartlink
  about/ terms/ privacy/ feedback/ design/   ← инфо-страницы
```

Остаются на месте (без сайдбара): `app/(auth)/`, `app/dashboard/`, `app/admin/`,
`app/fwqa688/`, `app/api/`.

Удаляется: `app/feed/` (роут). Контент фида остаётся секцией на главной.
Старые ссылки `/feed` не должны 404-ить → `app/feed/page.tsx` заменяется на
redirect `/feed → /` (либо `next.config` redirect). Выбираем серверный redirect
в `app/feed/page.tsx` (минимальный файл `redirect('/')`), чтобы не плодить конфиг.

### Структура DOM оболочки

Root `layout.tsx` (правки минимальны):

```
body (h-full flex col overflow-hidden)
  Nav                                  ← глобальный, БЕЗ центральных ссылок
  #main-content (flex-1 min-h-0 overflow-y-auto)   ← единственный скроллер, без изменений
    {children}                         ← (listener)/layout даёт сайдбар; др. секции — свой layout
  Player                               ← без изменений
  MobileTabBar                         ← НОВЫЙ client-компонент: md:hidden, null на не-listener роутах
```

`MobileTabBar` ставится в root (после Player, как flow-элемент `shrink-0`), потому
что должен быть ниже плеера и переживать клиентскую навигацию. Сам прячется через
`usePathname` на `/dashboard`, `/admin`, `/sign-in`, `/fwqa688`.

`(listener)/layout.tsx` (рендерится внутри `#main-content`):

```
<div className="flex">
  <aside className="hidden md:flex md:flex-col sticky top-0 self-start
                    h-[calc(100dvh-var(--nav-h)-var(--player-h))] w-64 shrink-0
                    border-r ...">
    <SidebarPrimaryNav />     {/* Главная, Медиатека (SideNav, vertical) */}
    <LibrarySection />        {/* «Любимые треки» + плейлисты + подписки, свой overflow-y-auto */}
  </aside>
  <div className="flex-1 min-w-0 min-h-full flex flex-col">
    <div className="flex-1">{children}</div>
    <Footer />
  </div>
</div>
```

Высота sticky-рейла = высота видимой области `#main-content`. Считаем через CSS-vars:
`--nav-h` (3rem) и `--player-h` (0 / 4rem). Плеер публикует `--player-h` на
`document.documentElement` при появлении/исчезновении трека (мини-добавка в стор/эффект
плеера). Внутренний список библиотеки — `flex-1 min-h-0 overflow-y-auto`, чтобы при
длинной библиотеке скроллился он, а не рейл.

## Компоненты

Новые — в `apps/web/components/listener/` (widget-слой FSD). Переиспользуем готовое.

| Компонент | Тип | Назначение | Переиспользует |
|---|---|---|---|
| `(listener)/layout.tsx` | server | оболочка сайдбара, фетч библиотеки | `getLikedTracks` (count), `getUserPlaylists`, `getFollowedArtists` |
| `listener/library-sidebar.tsx` | server | блок «Медиатека» в рейле | `next/image`, `Icon` |
| `listener/sidebar-primary-nav.tsx` | client | Главная/Медиатека (актив по пути) | `SideNav` |
| `listener/mobile-tab-bar.tsx` | client | нижний таб-бар (Главная/Поиск/Медиатека) | `Icon`, `usePathname` |
| `(listener)/library/page.tsx` | server | страница «Медиатека» | `PlaylistCard`, `LikedTrackRow`, `FollowedArtists` (из profile) |

`PlaylistCard`, `LikedTrackRow`, `FollowedArtists`, `ProfileCard`, `LinkedAccounts`
сейчас лежат в `app/profile/`. Те, что нужны и в `/library`, и в `/profile`, выносим в
`components/listener/` (или `components/library/`), чтобы не дублировать. Конкретно
переезжают в общий слой: `liked-track-row`, `playlist-card`, `followed-artists`.
`profile-card`, `linked-accounts` остаются с профилем.

### Сайдбар: блок «Медиатека»

- Заголовок «Медиатека» + кнопка `+` (создать плейлист — открывает существующий
  флоу создания плейлиста; если его нет как отдельной кнопки, ведём на `/library`).
- Закреплён первым пункт **«Любимые треки»** (иконка-сердце, ведёт на `/library#liked`
  или секцию лайков).
- Далее: плейлисты юзера (обложка + название + «Плейлист»), отслеживаемые артисты
  (аватар + имя + «Артист»).
- **Гость** (не залогинен): вместо списка — компактный промо-блок «Войди, чтобы
  собирать любимое и плейлисты» + кнопка «Войти».

### Top bar (глобальный Nav) — изменения

Минимальные. В `components/nav.tsx`:
- Убрать центральный блок ссылок `Артисты / Релизы / Лента`.
- Оставить: лого, `NavSearch`, Дашборд (условно), Админка (условно), профиль (имя),
  вход/выход. Поведение и условия ролей — без изменений.

## Страницы

### `/library` (новая) — «Медиатека»

Контент, который сейчас на `/profile`, но как полноценная страница-дашборд:
- Секция «Плейлисты» (сетка `PlaylistCard`) + кнопка создать.
- Секция «Любимые треки» (`LikedTrackRow`, очередь для плеера) — якорь `#liked`.
- Секция «Подписки» (`FollowedArtists`).
- (История прослушивания — только если есть готовый запрос; иначе фаза 2, не блокер.)
- Пустые состояния для каждой секции (как сейчас в профиле).
- `redirect('/sign-in?callbackUrl=/library')` для гостя.

### `/profile` (переработка) — «Профиль / Аккаунт»

Оставляем только аккаунт: `ProfileCard` (имя/аватар/дата), статистика (лайки/подписки/
плейлисты — числа), `LinkedAccounts` (способы входа). Музыкальные секции (плейлисты/
лайки/подписки списком) уезжают в `/library`. Добавляем явную ссылку «Моя медиатека →
/library».

### Главная (переработка) — Spotify Home

`app/(listener)/page.tsx`. Для вошедших — персональный home сверху, ниже — дискавери.
Порядок секций:
1. **Снова в эфире / быстрый доступ** (только вошедшим) — компактная сетка 6–8 плиток:
   недавнее (если есть запрос истории) / любимые плейлисты / вход в лайки. При нехватке
   сигнала добиваем подборками. (История — best-effort; без неё стартуем с лайков/фида.)
2. **Новое у тех, на кого подписан** (фид — был на `/feed`, теперь секция; вошедшим).
3. **Сделано для тебя** — вход в Волну (`WaveStartButton`) + по настроению (`MoodWaveChips`).
4. **Подборки** (editorial + личные) — как сейчас.
5. **Слушают сейчас** (`ListeningNow`), **Скоро выйдет**, **Свежие релизы**, **Артисты**.
6. **Редакционный featured** (`FeaturedRelease`) — оставить вверху для дискавери/LCP
   (без анимации, как сейчас), либо как первый блок для гостя.

Для гостя — порядок дискавери (featured → волна → подборки → свежие → артисты), без
персональных секций.

Сохранить текущие перф-заметки: `FeaturedRelease` без fade (LCP), motion-обёртки не
вешать на секции-сетки (scroll-jitter / композит-слои — см. память проекта).

### Footer (переработка/расширение)

Остаётся внизу контентной колонки (`(listener)/layout`). Расширяем: блоки Площадка
(Артисты, Релизы, О платформе, Дизайн), Поддержка (Стать артистом, Обратная связь),
Правовое (Условия, Конфиденциальность) + соцсети/контакты (если есть). Ссылки
Артисты/Релизы здесь компенсируют их уход из шапки.

## Последствия для дашбордов

Глобальный Nav остаётся (по требованию пользователя) — кнопки «на сайт»/профиль/выход
там уже есть, доп. правок в `/dashboard` и `/admin` layout НЕ требуется. Проверить, что
их собственные `<main overflow-y-auto>` корректно сосуществуют с `#main-content`
(статус-кво, не регрессируем).

## Тесты

- `layout-shell.test.ts` — расширить: нет `min-h-screen` в новых layout'ах; присутствует
  `#main-content` как единственный скроллер; сайдбар — `sticky`, не отдельный скроллер.
- Снять/обновить тесты, ссылавшиеся на `/feed` и на инлайн-ссылки Nav, если такие есть.
- `MobileTabBar` — юнит: возвращает `null` на `/dashboard`, `/admin`, `/sign-in`.
- Существующие route-тесты профиля — обновить под переезд компонентов (импорты/пути).
- Дизайн-гейт `audit:design` обязателен (трогаем UI).

## Out of scope (YAGNI / фаза 2)

- Драг-н-дроп сортировка медиатеки, фильтры-пилюли в сайдбаре (Плейлисты/Артисты/Альбомы).
- Реактивное (без revalidate) обновление списка библиотеки при мутациях.
- Полноценная история прослушивания, если нет готового запроса (стартуем без неё).
- Изменения backend/API/схемы БД.
