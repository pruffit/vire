# Экспорт дизайн-токенов — дизайн

**Статус:** реализуется · **Основание:** `docs/multiplatform.md` §6, §12 (пункт 5)

## Проблема

Единственный сегодняшний источник платформенных токенов — `packages/ui/src/globals.css`:
OKLCH-переменные в `:root` + Tailwind v4 `@theme inline`, который мапит их в утилитные
классы. Это веб-специфичный формат (CSS custom properties + Tailwind), непереносимый на
будущие RN/Tauri-клиенты буквально. Мобильный/десктопный клиент либо скопирует значения
руками (дрейф гарантирован при следующей правке темы), либо ждёт, пока появится
платформо-нейтральный источник.

## Решение

`packages/design-tokens` — новый пакет, `tokens.json` источник правды, два генератора:
CSS (потребитель — `packages/ui`) и TS-объект (потребитель — будущий RN-клиент, сегодня
только тесты внутри монорепо).

### Что токенизируем

Ровно то, что уже есть как платформенный токен в `globals.css`: 15 цветовых пар/значений
(`background`, `foreground`, `card`/-foreground, `popover`/-foreground, `primary`/-foreground,
`secondary`/-foreground, `muted`/-foreground, `accent`/-foreground, `destructive`, `border`,
`input`, `ring`) + `radius` (одно базовое значение, `sm`/`md`/`lg`/`xl` — существующая
формула `base-2px`/`base`/`base+4px`/`base+8px`, воспроизводится в каждом генераторе).

**Не токенизируем** (сознательно, нет источника): spacing/duration — Tailwind default
scale используется как есть, отдельного платформенного токена под них в коде сегодня нет;
заводить его сейчас — абстракция без потребителя (§3 брифа платформы). Артист-тема
(`--artist-bg/-text/-accent`) — рантайм-фолбэк на платформенные токены, значения приходят
per-артист из БД, не статичны, трогать не нужно.

### Формат значения в JSON

Цвет — структурная тройка OKLCH, не CSS-строка:
```json
{ "l": 0.085, "c": 0.006, "h": 75 }
```
Радиус — число в px (не rem — rem предполагает CSS root font-size, RN так не работает):
```json
{ "radius": 6 }
```
Почему не строка `"oklch(0.085 0.006 75)"`: строка — уже CSS-синтаксис, привязанный к
одной платформе. Числа переживают любой рендерер; CSS-генератор форматирует их в
`oklch(l c h)`, TS-генератор отдаёт структуру как есть — конвертация в RN-совместимый
формат (hex/rgb) не пишем сейчас: второго потребителя нет буквально, конвертер без
вызывающей стороны — преждевременная абстракция.

### Генерация

`packages/design-tokens/scripts/build.mjs`: читает `tokens.json`, пишет
`dist/tokens.css` (`:root { --background: oklch(...); ... }`, `radius`-переменные в `rem`,
т.е. `px/16`) и `dist/tokens.ts` (типизированный `export const tokens = {...} as const`,
радиус в px как есть). Скрипт — часть `build` пакета (`pnpm --filter @vire/design-tokens build`
генерирует `dist/`; `packages/ui` объявляет зависимость на пакет, чтобы turbo пересобирал
токены раньше `packages/ui`).

`packages/ui/src/globals.css` вместо хардкода `:root` значений делает
`@import "@vire/design-tokens/tokens.css";` первой строкой — `@theme inline` (Tailwind-маппинг,
непереносим) и `@utility`/`@layer base` (компонентный CSS) остаются в `globals.css` как есть.

### Проверка отсутствия дрейфа

Тест в `packages/design-tokens`: сгенерированный `dist/tokens.css` содержит те же 15
цветовых значений и радиус, что в `tokens.json` (round-trip: JSON → CSS-строка → парсинг
обратно → сравнение чисел). Отдельный тест в `apps/web` (или `packages/ui`) — визуальный
результат не должен измениться: значения, которые раньше были в `globals.css` руками,
теперь идентичны сгенерированным (сравнение построчно/по значению, не снапшот всего файла
— комментарии и структура файла могут отличаться).

## Риски / отклонения от §6 при реализации

- Пакет называется `design-tokens`, не переименовывать в процессе.
- Если Tailwind v4 не даст импортировать сгенерированный CSS-файл пакета из другого
  workspace-пакета через голый `@import` (резолв путей в Lightning CSS) — решать на месте:
  либо `transpilePackages`-подобный путь, либо копирование `dist/tokens.css` в
  `packages/ui/src/generated/` через сам build-скрипт (генератор кладёт файл прямо туда).
  Главное свойство сохраняется: `tokens.json` — единственное место, где меняют значение.
