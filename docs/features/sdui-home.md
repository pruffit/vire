# SDUI на главной

Состав и порядок секций главной задаёт сервер, а не вёрстка страницы. Клиент получает
композицию блоков и рендерит их через реестр. Раскатка за флагом `sdui.home`, откат —
выключение флага. Архитектура протокола — `docs/sdui.md`.

## Что делает

- `GET /api/v1/screens/home` отдаёт `{ screen, version, revision, blocks[] }`. Персональные
  блоки (`personal`, `feed`, `friends-activity`, `discovery`) попадают в композицию только
  авторизованному — клиент не получает правил, только результат.
- Клиент может объявить, что умеет рендерить, заголовком `X-Vire-Blocks:` — сервер не
  отправит незнакомые ему типы. Веб заголовок не шлёт и получает полную композицию.
- Главная рендерит **через реестр**, когда флаг включён, и прежним JSX, когда выключен.
  Обе ветки живут рядом; порядок блоков в композиции обязан совпадать со статической
  веткой один в один.

## Где код

- **Контракт:** `packages/api-contracts/src/sdui.ts` (`screenSchema`, `blockSchema`, `dataSourceSchema`)
- **Композиция:** `packages/core/src/platform/sdui/home-screen.ts` — чистая
  `composeHomeScreen({ isAuthenticated, supportedBlocks })`, `revision` = отпечаток состава
- **Эндпоинт:** `apps/web/app/api/v1/screens/home/route.ts`
- **Реестр рендереров:** `apps/web/components/sdui/home-registry.tsx` (тип → компонент,
  скелетон, признак `eager`)
- **Страница:** `apps/web/app/[locale]/(listener)/(home)/page.tsx` — ветвление по флагу
- **Флаг:** `sdui.home` (`docs/features/feature-flags.md`), по умолчанию выключен

## Проверено

Прод-сборка, обе ветки на одной и той же локальной базе: одинаковый порядок секций,
одинаковое число скелетонов (`animate-pulse` 116/116), секций (8/8), заголовков (7/7),
`snap-start` (4/4). Разница в размере HTML — 49 байт (идентификаторы стриминга).

## Ограничения / на будущее

- **Типы блоков — семантические секции** (`hot-tracks`, `fresh-releases`), а не generic
  (`release-grid`, `track-list`) из `docs/sdui.md` §3. Причина: generic-блок требует, чтобы
  данные ходили через единый контракт, а сейчас каждая секция сама читает свой read-сервис.
  Переход на generic осмыслен вместе с появлением мобильного клиента, а не раньше.
- **`source` пока не используется вебом:** RSC-блоки читают сервисы в процессе (стриминг
  сохраняется). Поле заполнено для будущего мобильного рендерера, который дёрнет эндпоинты.
- Персонализация ограничена «авторизован / нет»: A/B-корзин, профиля вкуса и времени суток
  в композиции нет — появятся, когда будет что ими решать.
- Статическая ветка удаляется **только** после того, как протокол подтвердит мобильный
  клиент (`docs/sdui.md` §10).
