# Визуализация (экран вечеринки)

Полноэкранная генеративная графика на `<canvas>`, реагирующая на звучащий трек. Включается
кнопкой на экране вечеринки (`/nrvz914/[code]`, режим «Экран»), состояние живёт в
`localStorage` (`vire-visualizer`).

## Что реагирует

Сцены получают кадр (`Frame` в `components/visualizer/scenes.ts`) из четырёх величин:

| Величина | Что даёт картинке |
|---|---|
| `amp` | общий размах: длина лучей, шаг частиц, амплитуда лент |
| `bass` | масса и ядро: радиус свечения в центре, толщина линий |
| `treble` | детализация: яркость и тонкие штрихи |
| `beat` | импульс на удар (1 в момент онсета, затухает) — рывок частиц, вспышка ядра |

Семь сцен (`bloom`, `starburst`, `ribbons`, `spiral`, `lattice`, `plasma`, `particles`)
сменяют друг друга каждые 16–30 секунд с перетеканием — это одна непрерывная визуализация,
а не набор режимов.

## Откуда берётся звук

Web Audio (`AnalyserNode`, FFT 1024) — `lib/visualizer/analyser.ts`. Источник регистрируется
в `lib/visualizer/audio-tap.ts`; поток захвата перебивает элемент.

| Источник | Анализ | Почему |
|---|---|---|
| Каталог VireMusic | ✅ настоящий | hls.js играет через MSE → `blob:` → поток своего происхождения |
| Локальный файл | ✅ настоящий | `URL.createObjectURL` → тоже свой origin |
| Audius | ❌ | чужой домен без CORS: `createMediaElementSource` отдал бы тишину **и заглушил** воспроизведение |
| YouTube / SoundCloud | ❌ | звук внутри чужого `iframe`, из кода недоступен в принципе |
| Захват вкладки | ✅ настоящий, любой источник | `getDisplayMedia` — пользователь сам разрешает |

**Кнопка «Слышать всё»** (`components/visualizer/capture-button.tsx`) появляется рядом с
переключателем визуализации: запрашивает `getDisplayMedia({ audio: true, video: true })`
(без `video` Chrome не предлагает звук вкладки), видеодорожку сразу останавливает, аудио
отдаёт в анализатор. В динамики поток **не** выводится — иначе тот же звук звучал бы дважды.
Это единственный способ заставить картинку реагировать на YouTube.

Без живого звука визуализация не застывает: `amp` берётся из предрассчитанных
`waveform_peaks` трека (каталог) или процедурной огибающей, `bass`/`treble` раскладываются
из него же, `beat` = 0.

## Разбор ритма

`lib/visualizer/features.ts` — чистые функции, покрыты тестами (`features.test.ts`):

- `rms` — громкость по волне;
- `bandEnergy` — энергия среза спектра в долях полосы (не зависит от размера FFT);
- `createBeatTracker` — онсет по всплеску энергии баса против скользящего среднего за 1.4с;
  порог адаптивный (растёт с разбросом), удары чаще 240/мин отбрасываются как дребезг;
  темп — медиана межударных интервалов, свёрнутая в 60–190 BPM.

## Ограничения

- `createMediaElementSource` необратим: элемент навсегда играет через граф Web Audio,
  поэтому узел кэшируется в `WeakMap` и всегда соединяется с `destination`.
- Тональность/BPM из `track_audio` в картинке не используются — темп считается на лету
  (у внешних источников метаданных всё равно нет).
- `prefers-reduced-motion` останавливает анимацию: рисуется один статичный кадр.
