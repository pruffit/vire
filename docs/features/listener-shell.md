# Оболочка слушателя (дашборд-модель Spotify)

Слушательская/публичная часть площадки оформлена как дашборд по модели Spotify:
постоянный левый сайдбар с навигацией и медиатекой, мобильный нижний таб-бар,
разделение «Медиатеки» (контент) и «Профиля» (аккаунт), переработанная главная.

## Что делает

- **Левый сайдбар** (десктоп ≥ md) на всех слушательских страницах: первичная
  навигация (**Главная**, **Медиатека**) + блок «Медиатека» — закреплённые
  «Любимые треки», плейлисты пользователя, отслеживаемые артисты. Кнопка «+» в
  шапке блока создаёт пустой плейлист и ведёт на его страницу (там переименование).
  Гостю — промо «Войти». Сайдбар — `sticky`-рейл внутри единственной скролл-области,
  его внутренний список скроллится отдельно.
- **Мобильный нижний таб-бар** (< md): Главная / Поиск / Медиатека / Сообщения (4
  таба, было 6); мини-плеер над ним. Скрыт на дашборде/админке/входе/секретных
  роутах. «Джем» и «Друзья» переехали внутрь `/library` строками (сайдбар с ними
  виден только на md+, на мобилке таб-бара для них больше нет). Бейдж входящих
  заявок в друзья (точка) показывается на табе «Медиатека», бейдж непрочитанных
  сообщений — на «Сообщения».
- **Верхний Nav** остаётся глобальным (лого, поиск, вход/выход, кнопки Дашборд/
  Админка, профиль) — но без прежних центральных ссылок Артисты/Релизы/Лента.
- **`/library`** — «Медиатека»: плейлисты (+ кнопка «Создать плейлист»), любимые
  треки (якорь `#liked`), подписки. На мобилке (< md) сверху — строки «Джем» и
  «Друзья» (с бейджем входящих заявок), недоступные иначе без сайдбара.
- **`/profile`** — только аккаунт: карточка профиля + статистика, ссылка «Моя
  медиатека → /library», способы входа. Музыкальные секции уехали в `/library`.
- **Главная** — Spotify Home: для вошедших сверху «Новое у тех, на кого подписан»,
  затем «Сделано для тебя» (Волна + по настроению), live, подборки, скоро, свежие,
  артисты; гостю — дискавери без персональных секций.
  - Полиш 13.07.2026 (критика Impeccable 27/40 → доводка, спека
    `docs/superpowers/specs/2026-07-13-homepage-polish-design.md`): секции
    «Скоро выйдет» и «Артисты» переведены с фикс. гридов на `ScrollRow`-rails —
    ширина по контенту, деградирует горизонтальным скроллом при росте каталога
    вместо пустого холста на 1–3 айтемах. Карточки «Свежих релизов» укрупнены
    до `w-48` (остальные rails — `w-40`), осознанный сбой однородности ради
    ритма после hero. Заголовки секций (`listener/section.tsx`) показывают
    mono-счётчик и при наличии ссылки-`href` («Свежие релизы 12 · Посмотреть
    все →»). Мета-строка hero обогащена TE-ридаутом инструментальных данных
    (`АЛЬБОМ · 2025 · 8 ТРЕКОВ · 34:12`) через `getReleaseCardStats` (`@vire/db`).
  - Авто-анонсы (`components/announcements.tsx`) показывают максимум один
    попап за визит — закрытие не открывает следующий из очереди, он выйдет
    при следующем маунте (`nextAutoAnnouncement` — чистый хелпер выбора).
- **`/feed`** удалена — серверный redirect на `/` (контент ленты остался секцией
  главной). Ссылки на `/feed` убраны из Nav, command-palette, `llms.txt`.
- **Футер** расширен (в т.ч. Релизы — компенсация ухода ссылок из шапки), живёт
  внизу контентной колонки слушательской оболочки.

## Где код

- **Route-группа:** `apps/web/app/(listener)/` — `layout.tsx` (сайдбар + футер) и все
  слушательские страницы (главная, `library`, `profile`, `artists`, `releases`,
  `playlists`, `search`, `smartlink`, инфо-страницы). URL не меняются.
- **Root layout:** `apps/web/app/layout.tsx` — каркас app-shell (`#main-content` —
  единственный скроллер), глобальные `Nav`, `PlayerWrapper`, `MobileTabBar`.
- **Компоненты:** `apps/web/components/listener/` — `sidebar-primary-nav.tsx`,
  `library-sidebar.tsx` (+ внутр. `LibraryRow`), `mobile-tab-bar.tsx`,
  `section.tsx` (общий editorial-`Section`), перенесённые `liked-track-row.tsx`,
  `playlist-card.tsx`, `followed-artists.tsx`.
- **Логика оболочки:** `apps/web/lib/listener-shell.ts` — `isListenerShellPath()`
  (где показывать сайдбар/таб-бар). `apps/web/lib/listener-data.ts` — `cache()`-
  обёртки `getLikedTracks/getFollowedArtists/getUserPlaylists` (дедуп запросов
  между layout и страницей в одном RSC-рендере).
- **Высота сайдбара:** плеер публикует CSS-переменную `--player-h`
  (`apps/web/components/player/index.tsx`); рейл — `h-[calc(100dvh-3rem-var(--player-h,0px))]`.
- **Инвариант:** `apps/web/app/__tests__/layout-shell.test.ts` (нет `min-h-screen`;
  один скроллер; сайдбар — sticky, не второй скроллер; футер не дублируется в root).

## Env

- Не требуется.

## Ограничения / на будущее

- **Список медиатеки не реактивен:** layout в App Router персистентен и не
  перевыполняется при soft-навигации — после лайка/создания плейлиста сайдбар
  обновится только при `router.refresh()`/хард-релоаде. Живое обновление — фаза 2.
- **Счётчик «Любимых треков» в сайдбаре** ограничен лимитом `getLikedTracks` (100);
  при >100 лайках показывается «100». Отдельный count-запрос — на будущее.
- **История прослушивания** на главной/в медиатеке не реализована (нет готового
  запроса) — «быстрый доступ» строится из подписок/лайков.
- **Дашборд/админка** глобального футера больше не показывают (он переехал в
  оболочку слушателя) — намеренно.
- Драг-н-дроп сортировка медиатеки и фильтры-пилюли в сайдбаре — фаза 2.
