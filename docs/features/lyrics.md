# Синхронизированный текст трека

Артист добавляет текст песни (синхронизированный LRC или простой), слушатель
смотрит его в плеере с подсветкой строки по ходу воспроизведения.

## Что делает

- **Артист** в дашборде релиза (раскрытая карточка трека → «Текст трека») вставляет
  LRC-текст вида `[мм:сс.хх] строка` или просто текст без таймкодов. Сохранение —
  отдельной кнопкой; индикатор «синхронизирован / без таймкодов» и счётчик строк.
- **Слушатель** в фуллскрин-плеере жмёт «Текст» (кнопка появляется только если у
  трека есть текст). Синхронизированный — активная строка подсвечивается по времени,
  панель доскролливает к ней, клик по строке перематывает на её таймкод. Текст без
  таймкодов показывается статично.
- **Страница трека** (`/artists/[slug]/releases/[releaseId]/tracks/[trackId]`):
  секция «Текст» под волной — рендерится серверно из `track.lyrics` (если есть),
  поэтому индексируется (SEO). Подсветка строки синхронна с плеером-волной (тот же
  глобальный стор). Клик по строке: если трек уже играет — перемотка на таймкод;
  если нет — запуск трека с этого таймкода (play-or-seek). Темизированный вариант
  (`--artist-accent`), в отличие от нейтрального плеер-оверлея.

## Где код

- **Данные:** `tracks.lyrics` JSONB — массив `{ t: число секунд | null, text }`
  (миграция `0020`). Тип `LyricLine` — `packages/core/src/types/release.ts`.
- **Парсер/сериализатор LRC:** `apps/web/lib/lrc.ts` (`parseLrc`, `serializeLrc`,
  `isSynced` — чистые функции, тесты в `lib/__tests__/lrc.test.ts`).
- **Запись:** PATCH `/api/v1/dashboard/tracks/[id]` принимает сырой LRC в поле
  `lyrics` (парсит, пусто → null). Репозиторий — `packages/db/src/repositories/track.ts`.
- **Чтение (публичное):** GET `/api/v1/tracks/[id]/lyrics` → `getPublicTrackLyrics`
  (`packages/db/src/queries/lyrics.ts`) — отдаёт только для **опубликованных** релизов.
- **Редактор:** `apps/web/components/lyrics-editor.tsx` (в `track-manager.tsx`).
- **Просмотр (плеер):** `apps/web/components/player/lyrics.tsx` (фуллскрин-плеер,
  ленивый fetch + тоггл) → общий `apps/web/components/lyrics-scroll.tsx`.
- **Просмотр (страница трека):** `apps/web/app/(listener)/artists/[slug]/releases/
  [releaseId]/tracks/[trackId]/track-lyrics.tsx` (play-or-seek) → тот же
  `lyrics-scroll.tsx` (`variant="artist"`, гард синхрона по `trackId`).

## Env

- Не требуется.

## Гочи

- Скролл-контейнер `lyrics-scroll.tsx` обязан иметь `relative` — `offsetTop`
  активной строки меряется от ближайшего позиционированного предка
  (`offsetParent`). Без `relative` на контейнере им становится первый попавшийся
  позиционированный родитель выше (в фуллскрин-плеере — `fixed inset-0`
  оверлей целиком), и целевой `scrollTop` считается с огромным лишним
  смещением: подсветка активной строки работает, а доскролл бьёт мимо.

## Ограничения / на будущее

- Текст тянется лениво при открытии фуллскрин-плеера (по `trackId`), кэш ответа 60с.
- Лимиты: до 1000 строк, до 300 символов на строку, до 20 000 символов на ввод.
- Нет встроенного редактора таймкодов «на слух» — артист готовит LRC во внешнем
  инструменте или проставляет вручную. Простой текст без таймкодов поддерживается.
- Текст недоступен для черновиков/непубличных релизов (эндпоинт фильтрует по статусу).
