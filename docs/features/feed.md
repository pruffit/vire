# Лента

Секция «Ваша лента» на главной (`/`): персонализированный список релизов, скорых
релизов и анонсов артистов, а не просто хронология подписок.

## Что делает

- Показывает до 24 элементов трёх видов: вышедший релиз, скорый релиз (с отсчётом
  и пресейвом), анонс артиста — каждый с подписью-причиной («Вы подписаны» /
  «Похоже на ваши вкусы» / «Свежее на площадке»).
- Сначала видно 12, «Показать ещё» раскрывает остаток без повторного запроса.
- Клик по релизу/скорому релизу ведёт на страницу релиза, по анонсу — на страницу артиста.
- Ранжирование учитывает свежесть, близость (подписка/вкус) и популярность, с явной
  защитой малых артистов и добивкой при холодном старте.
- Секция скрывается, если после сборки нечего показать (`.catch(() => [])` — сбой
  ленты не роняет главную).

## Ранжирование

`score = recency·0.45 + affinity·0.40 + popularity·0.15 + kindBonus`

- **recency** — `exp(-ageDays / halfLife)`; halfLife: релиз 7д, анонс 3д, скорый
  релиз — от даты выхода вперёд (чем ближе, тем выше), тот же halfLife, что у релиза.
- **affinity** — максимум сигнала, не сумма: подписка `1.0` → анонсы подписок так
  считаются исходно (`isFollowed`); артист из профиля вкуса `0.7`; совпадение по
  жанру/настроению вкуса `0.5`; иначе `0.25` (добивка).
- **popularity** — `log1p(plays30d) / log1p(plays30d + 100)`: насыщается логарифмом,
  вес всего 0.15 — «не мёртвое», а не «самое популярное».
- **kindBonus** — анонс `+0.05`, скорый релиз `+0.1` (событие впереди ценнее прошедшего).

`reason` (подпись в UI) идёт по тому же приоритету, что и affinity: `follow` →
`taste` → `fresh`.

## Состав и защита малых артистов

`composeFeed` (чистая функция, без IO): сортировка по score → кап **2 элемента на
артиста** → квота **минимум 30% слотов** артистам с `plays30d` ниже медианы (по
артисту, не по элементу) кандидатов, если такие есть → дедуп по `kind+id` → срез
до лимита. Это прямая защита из stage-2 §4.3 «без алгоритма, хоронящего малых
артистов» — не пожелание, а шаг композиции.

## Холодный старт

Если после композиции меньше 6 элементов, `buildFeed` добирает свежими вышедшими
релизами платформы (`getFreshFeedCandidates`, исключая уже отобранные id) с
принудительным `reason: 'fresh'` — подпись остаётся честной даже когда элемент
попал в ленту не по сигналу, а потому что каталог тонкий.

## Где код

- **Ранжирование/состав (чистые функции):** `packages/core/src/services/feed-ranking.ts`,
  типы — `packages/core/src/types/feed.ts`
- **Кандидаты (БД):** `packages/db/src/queries/feed.ts` — `getFeedCandidates`
  (релизы подписок + вкуса, анонсы подписок за 30д, скорые релизы подписок,
  агрегат `plays30d`), `getFreshFeedCandidates` (добивка)
- **Сшивка:** `apps/web/lib/feed.ts` — `buildFeed(userId, limit)`
- **UI:** `apps/web/components/home/feed-section.tsx` (серверный сбор + презейв-статусы),
  `apps/web/components/home/feed-list.tsx` (клиент: рендер трёх видов карточки +
  «Показать ещё» 12→24), встроен в `apps/web/app/(listener)/home-sections.tsx` /
  `app/(listener)/page.tsx` под заголовком «Ваша лента»
- **Переиспользовано:** `components/countdown-badge.tsx`, `components/upcoming-presave-button.tsx`,
  `components/explicit-badge.tsx`, `components/chat/chat-avatar.tsx`, `components/listener/section.tsx`

## Env

Не требуется (только `DATABASE_URL`).

## Ограничения / на будущее

- Активность друзей и персональные треки-рекомендации («Для тебя») намеренно НЕ
  смешиваются с лентой — разные единицы контента, остаются отдельными секциями.
- Без «не интересно» / скрытия элемента — нет UI под обратную связь, отдельная фича.
- Без бесконечной прокрутки и серверной пагинации — жёсткий потолок 24 элемента.
- На малом каталоге лента может состоять из 5–10 элементов даже с добивкой —
  ожидаемо на текущем объёме контента.
