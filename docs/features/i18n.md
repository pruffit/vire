# Локализация (ru/en)

Публичная часть платформы и письма/пуш доступны на русском (по умолчанию) и английском.
Строки живут в словарях, URL различаются префиксом `/en`, выбор языка сохраняется за
пользователем.

## Что делает

- Слушательская оболочка, каталоги, дашборд артиста, соцслой, юр. страницы, SEO-метаданные,
  OG-картинки, письма и пуш-уведомления отдаются на языке пользователя.
- URL: `localePrefix: 'as-needed'` — ru без префикса (`/artists/x`), en с префиксом
  (`/en/artists/x`). Внешние ссылки/смартлинки/sitemap на ru не меняются — нулевой SEO-риск
  для существующего трафика.
- Выбор языка: переключатель в `/profile` (настройки → внешний вид) пишет cookie
  `NEXT_LOCALE` сразу и `PATCH /api/v1/user/profile` для залогиненного пользователя
  (`users.locale`, фолбэк `ru`). Локаль **не** кладётся в JWT — письма/пуш всегда читают её
  из БД на момент отправки, а не из сессии на момент логина.
- Письма и пуш триггерятся с языком получателя (`users.locale`), не отправителя/актёра.
- Ошибки сервисов (`packages/core`) несут стабильный `code` (`ValidationError.code` и т.п.)
  рядом с русским `message` для логов; route handlers отдают `{ error, code }`, клиент
  переводит по `code` через словарь `errors.json` с фолбэком на серверный текст.
- `/admin` и внутренняя витрина дизайн-системы (`/design`, noindex) — не локализованы,
  остаются на русском (backoffice и dev-инструмент, не часть продукта для конечного
  пользователя).

## Где код

- **Пакет словарей:** `packages/i18n` — `src/config.ts` (`LOCALES`, `DEFAULT_LOCALE`,
  `LOCALE_LABELS`, `LOCALE_OG`, `localizedPath`), `src/messages.ts` (`NAMESPACES`,
  `getMessages`), `src/translator.ts` (`getTranslator(locale, namespace?)` — переводчик вне
  React-дерева: письма, пуш, `apps/worker`, root not-found/error).
  `messages/{ru,en}/<namespace>.json` — один файл на неймспейс, ключи `camelCase`.
- **Роутинг Next:** `apps/web/i18n/{routing,navigation,request}.ts`
  (`createNavigation`/`getRequestConfig` из `next-intl`); `next.config.ts` обёрнут
  `createNextIntlPlugin`. Внутри `app/[locale]/**` и `components/**` (кроме
  `components/admin/**`) — только `Link`/`redirect`/`usePathname`/`useRouter` из
  `@/i18n/navigation`, не из `next/*`.
- **Middleware:** `apps/web/proxy.ts` — `createMiddleware(routing)` первым, затем
  существующий auth-гейт (пути сравниваются после снятия префикса локали через
  `stripLocale`); `/admin` и `/fwqa688` — вне локализации.
- **Переключатель:** хук `apps/web/lib/use-locale-switch.ts` (PATCH профиля + `router.replace`
  на новый префикс + `router.refresh()`), точки входа — `components/listener/profile/
  appearance-settings.tsx` и кнопка RU/EN в `components/listener/listener-sidebar.tsx`.
  `refresh()` обязателен: провайдер `next-intl` и `<html lang>` живут в корневом
  `app/layout.tsx`, а он общий для всех маршрутов и в дифф soft-навигации не входит — без
  него менялся только серверный контент под `[locale]`, а клиентские компоненты оставались
  на прежнем языке до перезагрузки (`lib/use-locale-switch.test.tsx`).
- **Данные:** `packages/db/src/schema/users.ts` — `locale varchar(8)` (nullable, фолбэк `ru`
  в чтении).
- **Ошибки:** `packages/core/src/errors.ts` (`code?: string` на `NotFoundError`/
  `ConflictError`/`ValidationError`/`ForbiddenError`), `apps/web/lib/api-error.ts`.
- **Письма/пуш:** `packages/core/src/platform/notifications/email-templates.ts`,
  `apps/worker/src/workers/notify-external.worker.ts`, `notify-release.worker.ts`.
- **Гейт:** `apps/web/scripts/check-i18n.mjs` (`pnpm --filter @vire/web check:i18n`) —
  статический детектор кириллицы в JSX-тексте/`title`/`label`/`placeholder`/`aria-label`/
  `toast(...)` внутри локализованной зоны; падает (exit 1) на находке вне allowlist
  (`/design`). Висит на `prebuild` и в CI-job `gates`.
- **Тест паритета словарей:** `packages/i18n/src/__tests__/messages-parity.test.ts` —
  для каждого неймспейса сверяет множество ключей ru/en (включая элементы массивов —
  `legal.json`), отсутствие пустых значений и совпадение имён ICU-плейсхолдеров
  (`{count}`, `{kind, select, ...}` и т.п.) в парных значениях.

## Env

Не требуется — базовый URL для абсолютных ссылок в письмах/OG берётся из существующего
`NEXT_PUBLIC_SITE_URL`/`AUTH_URL` (`lib/site.ts`).

## Ограничения / на будущее

- `/admin` и `/design` не локализованы (см. выше) — намеренно, не пробел.
- `check:i18n` детектит только JSX-текст/перечисленные атрибуты/`toast(...)`; строковые
  литералы, возвращаемые из server actions (`return 'текст'`), в его регекс не попадают —
  такой пробел уже находился и чинился точечно (`account-actions.ts`), но регекс не
  гарантирует полноты для этого паттерна.
- Локаль не хранится в JWT: смена языка учтённым сервером письмам/пуш требует записи в БД
  (уже происходит в переключателе), но открытая клиентская сессия узнаёт о смене только
  после `router.replace` + `router.refresh()` — не требует перелогина (в отличие от роли).
- Смена языка стоит двух запросов (навигация + refresh корневого дерева). Убрать можно
  только переносом шелла (`<html>`/Nav/плеер) под `app/[locale]/layout.tsx` с отдельным
  root layout для `/admin` — большая перестройка, сейчас не оправдана.
