# Уборка файлов удалённых сущностей

Фоновый уборщик S3: удаление трека или релиза раньше стирало только строки в БД, а мастер,
HLS-сегменты и обложки оставались в хранилище навсегда.

## Что делает

- При удалении трека/релиза сервис **до** удаления строк регистрирует префиксы файлов в
  таблице `storage_orphans`. Порядок обязателен: после удаления строк id треков уже не узнать.
- Раз в час воркер берёт записи старше **суток** (grace-период), листит каждый префикс в S3
  и удаляет найденные объекты, помечая запись `cleaned_at`.
- Сбой одной записи не останавливает пачку: пишется `attempts`/`last_error`, следующий проход
  пробует снова. После 5 неудач запись больше не берётся — это сигнал разобраться руками.

Grace-период — защита от ошибки: сутки файлы лежат на месте, и удаление можно отменить,
убрав запись из `storage_orphans` (строки в БД он не вернёт, но мастер артиста цел).

## Какие префиксы удаляются

| Что удалили | Бакет | Префикс |
|---|---|---|
| Трек | vault | `tracks/{trackId}/` (мастер `source.*`) |
| Трек | stream | `tracks/{trackId}/` (HLS: манифест + сегменты) |
| Релиз | stream | `covers/{releaseId}.` + префиксы всех его треков |

Точка в конце `covers/{id}.` обязательна — иначе префикс задел бы обложку релиза, чей id
начинается так же.

**Не удаляются:** аватары (`avatars/…`), обложки плейлистов и смартлинков — их сущности
удаляются другими путями и в этот проход не входят.

## Где код

- **Порт + сервис:** `packages/core/src/platform/storage/repositories/orphan.ts`,
  `.../services/cleanup.ts` (`StorageCleanupService`, `ORPHAN_CLEANUP_GRACE_MS`)
- **Раскладка ключей:** `packages/core/src/music/catalog/services/storage-keys.ts` — чистые
  функции, менять только парой с местами загрузки
- **Регистрация:** `TrackService.deleteTrack`, `ReleaseService.deleteRelease`
  (зависимость `orphanStorage` опциональна: без неё поведение прежнее)
- **Репозиторий:** `packages/db/src/repositories/orphan-storage.ts`,
  таблица `storage_orphans` (миграция `0055`)
- **Воркер:** `apps/worker/src/workers/storage-cleanup.worker.ts`, очередь
  `storage-cleanup`, расписание `30 * * * *` (МСК) в `apps/worker/src/index.ts`

## Env

Не требуется — работает на тех же `S3_*`, что и остальная работа с хранилищем.

## Ограничения / на будущее

- **Файлы, осиротевшие до этой фичи, не убираются.** Записей о них нет; нужен разовый
  проход-ревизия (сверка ключей `tracks/*` в S3 с `tracks.id` в БД) — не сделан.
- Уборщик работает по префиксу, а не по точному списку ключей: если в `tracks/{id}/` окажется
  что-то постороннее, оно тоже будет удалено. Раскладка ключей это исключает.
- Обложка релиза при замене перезаписывается по тому же ключу, только если совпало
  расширение; смена `jpg` → `png` оставляет старый файл. Это отдельная (мелкая) утечка,
  в этот проход не входила.
- `storage_orphans` не чистится от записей `cleaned_at` — журнал полезен для разбора,
  растёт медленно.
