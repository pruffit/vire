# Письма и рассылки (Brevo)

Вся почта идёт через **Brevo HTTP API** (`api.brevo.com/v3/smtp/email`). SMTP не
используется — хостинг (Timeweb) блокирует исходящие почтовые порты.

## Что делает
- **Транзакционные письма** (`lib/mailer.ts`, `sendMail`): magic-link для входа
  (см. [authentication](authentication.md)) и форма обратной связи (`replyTo`, `FEEDBACK_TO`).
- **Рассылка о релизе подписчикам** (воркер): когда артист публикует релиз, в
  очередь `notify-release` кладётся задача; воркер берёт e-mail подписчиков и
  шлёт каждому персональное письмо со ссылкой на релиз.
  - Брелок Brevo `messageVersions` — батч до 1000 на запрос (берём по 500), у
    каждого адресата своё письмо (без CC), с персональным приветствием по имени.
  - HTML письма собирается в воркере (тёмная тема, обложка, кнопка «Слушать»,
    ссылка «Управлять подписками»).

## Где код
- **Транзакционный мейлер (web):** `apps/web/lib/mailer.ts`
- **Воркер рассылки:** `apps/worker/src/workers/notify-release.worker.ts`
  (регистрация — `apps/worker/src/index.ts`)
- **Очередь/типы:** `QUEUE_NOTIFY_RELEASE`, `NotifyReleaseJobData` в `@vire/core`;
  задача ставится при публикации релиза (см. [tracks-and-releases](tracks-and-releases.md))
- **Адресаты:** `getFollowerEmails(artistProfileId)` в `@vire/db`

## Env
- `BREVO_API_KEY` — ключ Brevo (Transactional → SMTP & API). Обязателен; без него
  воркер/мейлер бросают ошибку.
- `SMTP_FROM` — отправитель в формате `VireMusic <noreply@viremusic.ru>` (домен должен
  быть верифицирован в Brevo). Имя «SMTP_*» историческое — реально это HTTP API.
- `FEEDBACK_TO` — адрес, куда падает форма обратной связи.
- `NEXT_PUBLIC_APP_URL` / `NEXT_PUBLIC_SITE_URL` — базовый URL для ссылок в письме.
- `REDIS_URL` — очередь BullMQ для рассылки.

## Ограничения / на будущее
- Отписки от писем точечной настройки нет — ссылка «Управлять подписками» ведёт в
  `/profile` (управление подписками), отдельного списка рассылки нет.
- Письма только о релизах; о новых постах артиста рассылки нет (см. [posts](posts.md)).
- Дайджестов/частоты нет — письмо на каждый опубликованный релиз.
- Воркер должен быть запущен (`pnpm --filter @vire/worker dev`), иначе задачи
  копятся в очереди.
