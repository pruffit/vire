# Пресейвы релизов

Слушатель «сохраняет заранее» ещё не вышедший (SCHEDULED) релиз. В момент выхода
воркер автоматически добавляет треки релиза в «Лайки» пресейвера и шлёт письмо
«вышло». Гость без аккаунта оставляет email и получает только письмо.

## Что делает

- На странице ещё не вышедшего релиза (полноэкранный обратный отсчёт) есть кнопка
  пресейва:
  - **залогиненный** — «Сохранить заранее» в один клик (оптимистично, повторный
    клик снимает пресейв);
  - **гость** — «Напомнить о выходе» → поле email → письмо при выходе.
- Когда наступает `release_date`, планировщик в воркере:
  1. атомарно публикует релиз (`SCHEDULED → PUBLISHED` + `published_at`);
  2. шлёт письмо подписчикам артиста (`notify-release`, как и при ручной публикации);
  3. исполняет пресейвы (`fulfill-presave`): авто-лайк READY-треков пресейверам-юзерам
     + письмо «вышло» юзерам и гостям; помечает пресейвы `fulfilled_at`.
- Раньше запланированные релизы становились «в эфире» по дате неявно (через предикаты
  запросов), но писем подписчикам при авто-выходе **не уходило вовсе** — планировщик
  закрывает и эту дыру.

## Где код

- **API:** `app/api/v1/releases/[id]/presave/route.ts` — POST (юзер/гость), DELETE
  (снять, только юзер), GET (состояние). Пресейв доступен только для `SCHEDULED` с
  будущей датой.
- **UI:** `components/presave-button.tsx`; встроен в `components/release-countdown.tsx`,
  состояние пробрасывает серверная страница релиза
  `app/artists/[slug]/releases/[releaseId]/page.tsx`.
- **Данные:** `packages/db/src/schema/interactions.ts` → таблица `release_presaves`
  (`release_id`, `user_id` nullable, `email` nullable, `fulfilled_at`). Уникальность
  `(release_id, user_id)` и `(release_id, email)` — NULL-различимость Postgres
  разделяет пресейвы юзеров и гостей. Запросы: `packages/db/src/queries/release-presaves.ts`.
- **Воркер:** `apps/worker/src/workers/scheduled-publish.worker.ts` (cron раз в минуту,
  публикация по дате) + `apps/worker/src/workers/fulfill-presave.worker.ts` (авто-лайк
  + письма). Очереди/типы: `packages/core/src/jobs.ts`
  (`QUEUE_SCHEDULED_PUBLISH`, `QUEUE_FULFILL_PRESAVE`, `FulfillPresaveJobData`).
- **Миграция:** `packages/db/src/migrations/0022_new_trauma.sql`.

## Env

- `BREVO_API_KEY`, `SMTP_FROM` — отправка писем (как у остальных рассылок).
- `NEXT_PUBLIC_APP_URL` / `NEXT_PUBLIC_SITE_URL` — базовый URL в ссылках письма.
- `REDIS_URL` — очереди BullMQ (планировщик + исполнение).

## Ограничения / на будущее

- **In-app центра уведомлений нет:** «in-app» = авто-лайк (релиз появляется в «Лайках»)
  + письмо. Отдельная лента уведомлений — будущая фича.
- Идемпотентность писем при ретрае джобы: ошибки отдельных адресатов не валят джобу
  (ловятся), `fulfilled_at` ставится в конце; полный крэш между рассылкой и пометкой
  теоретически может повторить письма уже уведомлённым (риск низкий на текущем масштабе).
- **Гость не может снять пресейв в один клик** (нет аутентификации), но может
  отписаться от будущих писем: каждое письмо «вышло» гостю несёт HMAC-подписанную
  ссылку `/api/v1/presave/unsubscribe?email=…&sig=…` (`apps/web/lib/presave-unsubscribe.ts`
  и зеркало `apps/worker/src/lib/presave-unsubscribe.ts` — секрет и схема подписи общие,
  `LINK_SIGNING_SECRET`/`AUTH_SECRET`). Переход удаляет все ещё не исполненные гостевые
  пресейвы этого email (`deletePendingGuestPresavesByEmail`); неверная/просроченная
  подпись → 403. Без секрета в env ссылка не строится — письмо уходит без неё, не с
  битой ссылкой. Продуктовое решение: IP-лимит на гостевой POST (20/час, отдельно
  от email-лимита — см. `presave/route.ts`) + эта ссылка вместо полного double opt-in
  (double opt-in не убирает нежелательное письмо, только переносит его момент, и режет
  конверсию — см. спеку `docs/superpowers/specs/2026-07-10-audit-tail.md`, C1).
- **Привязка смартлинков к релизу (Фаза B) — сделано:** дропдаун в редакторе
  смартлинка + кнопка «Слушать/Пресейв на Vire» первой на лендинге (см.
  [Смартлинки](smart-links.md)). Внешние пресейв/follow-ссылки (Spotify/Apple/Яндекс)
  добавляются как обычные ссылки площадок смартлинка — без OAuth.
- Инлайн-пресейв в секции «Скоро выйдет» на странице артиста — есть
  (`components/upcoming-presave-button.tsx`): вошедший сохраняет в один клик
  (оптимистично, батч-состояние через `getPresaveStates`), гость идёт на страницу
  релиза с email-флоу.
