# PWA: установка и офлайн-медиатека

VireMusic ставится как приложение (иконка на домашнем экране, без браузерного хрома) и
переживает потерю сети: оболочка отдаётся из кэша, а явно скачанные треки играют без интернета.

## Что делает

- **Установка.** Chrome/Edge/Safari предлагают установить приложение; кнопка «Установить»
  в медиатеке ловит `beforeinstallprompt` и прячется, если приложение уже стоит.
- **Офлайн-оболочка.** Без сети любая навигация ведёт на `/offline` вместо ошибки браузера.
  Статика (`/_next/static`, иконки, шрифты) и картинки отдаются из кэша.
- **Скачивание.** В меню трека — «Сохранить офлайн» (и «Докачать»/«Удалить из офлайна» по
  состоянию), на странице плейлиста — «Скачать плейлист» с общим прогрессом и отменой.
  Меню есть на главной, в поиске, в трек-листе релиза, на странице трека, в любимых треках,
  на странице плейлиста и в очереди плеера (локальным файлам его не выдаём — качать нечего).
- **Экран «Скачанное»** (`/offline`) — список скачанного, воспроизведение без сети, занятое
  место, удаление, аварийный сброс кэша приложения.

**«Скачать» здесь ≠ файл.** Сегменты HLS кладутся в Cache Storage браузера; файла в
«Загрузках» не появляется, играет только наш плеер. Выдача настоящего файла — по-прежнему
только покупка FLAC по presigned URL (Этап 2).

## Где код

- **Service worker:** `apps/web/public/sw.js` — единственный SW (пуши там же). Кэши:
  `vire-shell-v1` (precache `/offline` + иконки), `vire-static-v1`, `vire-img-v1` (лимит 200
  записей), `vire-offline-v1` (скачанное; не версионируется, `activate` его не трогает).
- **Регистрация:** `apps/web/components/service-worker-registrar.tsx` (в `DeferredWidgets`)
  — регистрирует `/sw.js` с `updateViaCache: 'none'`, сверяет владельца офлайн-библиотеки,
  прогревает `/offline` через `router.prefetch`.
- **Ядро офлайна:** `apps/web/lib/offline/` — `download.ts` (загрузка/удаление/`estimateUsage`,
  чистая `planDownload`), `hls.ts` (`parseHlsSegments`), `db.ts` (IndexedDB `vire-offline`,
  store `tracks`, `purgeOfflineLibrary`), `owner.ts` (`shouldPurge`), `to-download-meta.ts`.
- **Состояние:** `apps/web/store/offline.ts` — статусы `idle | downloading | partial | done`,
  прогресс, guard от повторного запуска (module-level `Set`, как в `store/likes.ts`);
  там же `covers` (trackId → object URL локальной обложки) и хук `useOfflineCover`.
- **Поверхности:** `app/offline/{page,offline-screen}.tsx`, `components/install-app-button.tsx`,
  `components/track-queue-menu.tsx`, `app/(listener)/playlists/[id]/playlist-download-button.tsx`,
  плитка «Скачанное» в `app/(listener)/library/page.tsx`.
- **Манифест и заголовки:** `app/manifest.ts` (`id`, `scope`, `shortcuts`, maskable-иконка),
  `next.config.ts` — `/sw.js` отдаётся с `Cache-Control: no-cache`.
- **Иконка:** `scripts/make-maskable-icon.mjs` — разовая генерация `public/icon-maskable-512.png`
  (в билд-цепочке не участвует).

## Стратегии кэша

| Запрос | Стратегия |
|---|---|
| навигация | сеть, при сбое — `/offline` из precache |
| `/_next/static/**`, иконки, шрифты | cache-first |
| картинки | stale-while-revalidate, подрезка до 200 записей |
| `/api/v1/tracks/{id}/manifest` | сеть, при сбое — кэш (пишет туда только загрузчик) |
| `.m3u8`, `.ts` | кэш по попаданию, промах → сеть **без записи** |
| остальное и любые не-GET | сеть напрямую |

**Обложка скачанного трека живёт в IndexedDB (`coverBlob`), не в Cache Storage.** Картинки с
CDN — чужой origin, а такие SW намеренно не перехватывает (перехват ломал превью YouTube и
упирался в `connect-src`), поэтому офлайн запрос к CDN просто не проходит. Качаем не оригинал,
а то же оптимизированное превью, что показывает UI (`/_next/image?...&w=640&q=75` —
`coverPreviewUrl`): мастер-обложка бывает на десяток мегабайт. Object URL выдаётся на рендере
через `useOfflineCover` и **не** попадает в `PlayerTrack`: очередь плеера персистится в
`vire-player`, а `blob:`-ссылка после перезагрузки мертва.

**HTML не кэшируется намеренно** (кроме `/offline`): корневой layout персонализирован, и
кэш документа прошлого аккаунта на общем устройстве был бы утечкой. Аудио не кэшируется
попутно при прослушивании — только по явной команде, иначе хранилище растёт бесконтрольно.

**Офлайн-библиотека принадлежит аккаунту.** IndexedDB и Cache Storage общие на браузер,
поэтому при смене пользователя (`userId` в регистраторе не совпал с сохранённым) скачанное
удаляется целиком — иначе следующий вошедший видел бы чужую медиатеку.

## Env

Не требуется. `NEXT_PUBLIC_VAPID_PUBLIC_KEY` относится к пушам в том же SW (см. `notifications.md`).

## Ограничения

- **iOS Safari:** нативный HLS-стек (ветка `canPlayType('application/vnd.apple.mpegurl')` в
  `audio-engine.ts`) может ходить мимо service worker — офлайн-воспроизведение там не гарантировано.
- **Яндекс Браузер** не умеет WebAPK — установка недоступна, ограничение из
  `mobile-patterns.md` снимается только для Chrome/Edge/Safari.
- **Права проверяются онлайн, не офлайн.** Плеер берёт манифест из сети, и на снятом с
  публикации треке получает 404 — воспроизведение не начнётся. Уже скачанные сегменты играют
  без проверки: это неизбежное свойство офлайн-кэша, снимается только удалением копии.
- **Пере-транскод** (кнопка «⟳ HLS» в админке) перезаписывает файлы по тем же S3-ключам.
  Скачивание и докачка всегда перезапрашивают плейлист, но уже лежащие сегменты остаются
  старыми, пока пользователь не удалит и не скачает трек заново.
- **Статистика офлайн теряется:** play-события и presence-хартбиты уходят в никуда, очереди
  на отправку при восстановлении сети нет.
- Скачивание идёт из вкладки (Background Fetch не используем): уход со страницы обрывает
  загрузку, запись помечается `partial` и докачивается позже.
- Первая офлайн-навигация оживает только если JS-чанки `/offline` уже попали в кэш статики —
  для этого регистратор прогревает страницу `router.prefetch`.
