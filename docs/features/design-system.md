# Дизайн-система: роли и границы китов

Типографические роли поверх OKLCH-токенов + разделение `packages/ui` (фундамент) и
`apps/web/components/{ui-kit,content-kit}.tsx` (составные компоненты плотных зон).

## Что делает

- Даёт две CSS-роли-утилиты для повторяющихся типографических паттернов вместо
  копирования классов построчно в каждый компонент.
- Разграничивает `packages/ui` (токены, роли, примитивы, motion — фундамент) и
  продуктовые киты `ui-kit.tsx`/`content-kit.tsx` (составные компоненты поверх фундамента).
- Держит статический гейт (`design-tokens.test.ts`), который ловит откат к сырым
  цветовым литералам и к копипасте eyebrow-паттерна вместо роли.

## Роли

Определены в `packages/ui/src/globals.css` рядом с токенами (`@utility`, подхватывается
Tailwind v4 через `@import "@vire/ui/globals.css"` в `apps/web/app/globals.css` — проверено
прод-сборкой, отдельный источник в `apps/web` не понадобился).

| Класс | Состав | Когда |
|---|---|---|
| `label-mono` | `font-mono`, 11px, `uppercase`, `tracking: 0.08em` | Плотный UI-хром: подписи полей, шапки таблиц, служебные пилюли |
| `label-wide` | `font-mono`, 11px, `uppercase`, `tracking: 0.2em` | Редакционные eyebrow: заголовки секций, hero, экраны джема и вечеринки |
| `readout` | `font-mono`, `tabular-nums`, `slashed-zero` | Данные: длительность, таймкод, BPM, метрики |

Лейблов две роли, а не одна: широкая разрядка моно-капса — приём TE-эстетики
(`ui-principles.md`), а плотная подпись поля — служебный хром. До ревизии обе семьи
существовали россыпью значений (0.08/0.12 в одной, 0.15/0.18/0.2/0.22/0.25 в другой);
роли схлопывают разнобой внутри каждой семьи, но не сливают семьи между собой.

Цвет и вес в роли не зашиты — задаются на месте применения (`text-foreground/45`,
`text-muted-foreground`, `color-mix(--artist-text …)` и т.д.). `label-mono` не задаёт
`line-height` — наследуется от контекста.

Число внутри обычного текста (например, счётчик лайков в предложении) получает только
`tabular-nums` из Tailwind — `readout` там неуместен, моношрифт в прозе читается как код.

Полноценная типографическая шкала не вводится — Tailwind-шкала уже покрывает подавляющее
большинство размеров в проекте.

`h1, h2, h3 { text-wrap: balance; }` — базовое правило в `@layer base` того же файла
(`ui-principles.md:161-168`), не утилита.

## Границы `packages/ui` vs `ui-kit.tsx`/`content-kit.tsx`

- **`packages/ui`** — фундамент: OKLCH-токены, роли, `Button`/`Input`, motion-примитивы
  (`Reveal`/`FadeUp`/`Stagger`/`Press`). Ничего продуктового.
- **`ui-kit.tsx`** — составные компоненты плотных продуктовых поверхностей (dashboard,
  admin): `Field`, `Panel`, `StatCard`, `Table`/`Th`/`Td`, бейджи статусов и т.д. Строится
  поверх ролей `packages/ui`, не дублирует их состав.
- **`content-kit.tsx`** — то же для публичных/маркетинговых поверхностей (`Eyebrow`,
  `StatusPill`, `ContentHero`, `FeatureCard`).

`Card`/`CardHeader`/`CardTitle`/`CardContent` и `buttonVariants` убраны из публичного API
`packages/ui` — карточка в продукте закрыта `Panel`/`StatCard` из `ui-kit.tsx`, а
неиспользуемый примитив рядом с используемым был ровно тем рассинхроном, который убирает
эта ревизия.

## Гейт

`apps/web/app/__tests__/design-tokens.test.ts` — статический инвариант по образцу
`layout-shell.test.ts`, обходит `*.tsx` в `app/` и `components/`:

1. Запрещает `text-white`/`bg-white`/`border-white`/`white/NN`/`black/NN` и hex в
   Tailwind-arbitrary-синтаксисе (`bg-[#...]`) вне allowlist.
2. Запрещает сырой eyebrow-паттерн — `font-mono` + `uppercase` + `tracking-[...]` в одной
   строке className — вместо роли `label-mono`.

Оба правила ведут allowlist прямо в файле теста (константа-массив/сет, обоснование на
запись). Ревизия (срезы A–C плана дизайн-системы) закрыта: цветовые литералы вне allowlist
не встречаются нигде в `app/`/`components/`, каждая оставшаяся запись — легитимный
`overlay: true` (текст/контролы поверх видео, обложек, произвольного пользовательского
цвета в редакторах темы/палитры, где OKLCH-токен даёт непредсказуемый контраст), кроме
демо-витрины токенов (`app/(listener)/design/page.tsx`) — она сознательно показывает сырые
значения. Тот же принцип для eyebrow-паттерна: единственная оставшаяся запись — секретная
пасхалка (`app/fwqa688/page.tsx`) с уникальным значением 0.3em вне переиспользуемого хрома.

Тест дополнительно проверяет сам allowlist на протухание в обратную сторону: если файл
больше не нарушает правило, а запись осталась — тест падает, требуя убрать запись.

### Как завести исключение

1. Нарушение реальное (не ловится точечной правкой) → добавить запись в
   `COLOR_LITERAL_ALLOWLIST` или `RAW_EYEBROW_ALLOWLIST` в `design-tokens.test.ts`.
2. Медиа/цветовой оверлей (поверх видео/произвольного изображения/пользовательского
   цвета, где OKLCH-токен даёт непредсказуемый контраст) → `overlay: true` с обоснованием
   в одну строку.
3. Всё остальное — обычная поверхность, литерал переводится на токен вместо записи
   в allowlist; `overlay: false` держат только осознанные постоянные исключения
   (демо-витрина токенов).

## Ограничения / на будущее

- Allowlist ведётся вручную и может протухать в сторону избыточных временных записей —
  вторая проверка каждого правила ловит только «запись осталась, а нарушения больше нет»,
  не «нарушение появилось где-то новое без записи» (это ловит основная проверка).
- Число без `tabular-nums` в прозе статически не отличить от числа-данных — гейтом не
  покрывается, держится ролью и ревью.
- `btnPrimary`/`btnGhost` на `Button` из `@vire/ui` не переведены — тактильный отклик
  плотных зон (dashboard/admin) сейчас другой, решение отложено.
