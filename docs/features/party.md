# Вечеринка

Режим джем-сессии для живой тусовки: общая очередь, в которую можно закинуть **что угодно** —
трек из каталога VireMusic, ссылку с любого сервиса или файл с устройства. Вход скрытый,
страница не индексируется. Базовая механика (коды, участники, синхронизация, SSE) — общая
с джемом, см. [`jam.md`](jam.md).

## Что делает

- **Секретный вход.** `/nrvz914` — «начать вечеринку» + вход по коду. Никаких ссылок в
  навигации; попасть можно тройным кликом по копирайту в футере (окно 600мс, без подсказок).
  Ссылка на саму комнату `/nrvz914/{code}` работает у любого, кому её дали — иначе гости
  не зашли бы по QR. Секретен вход, не комната.
- **Одно поле на всё.** Гость вводит что вспомнил или вставляет ссылку (можно несколько сразу —
  добавятся все). Ссылка отправляется сразу, текст идёт в подсказки. Подсказки разведены по
  готовности: **«Играет сразу»** — каталог VireMusic и то, что кто-то уже добавлял на вечеринках
  (индекс отрезолвленного, без сети и квоты), **«Найдём в сети»** — хинты iTunes/Deezer, которые
  ещё надо резолвить. Стрелки ↑/↓ и Enter выбирают строку, добавленное подтверждается тостом,
  позиция в очереди помечена «Ищем в сети…», пока сервер резолвит. Тупика нет: если резолвить
  нечем, приходит список кандидатов, а не ошибка. Вставленная ссылка (или несколько сразу)
  отправляется прямо из обработчика `paste`; в простое есть блок «Ещё раз» с тем, что уже
  играло на этой вечеринке.
- **Очередь по кругу.** В режиме `PARTY` новая позиция встаёт не в хвост, а в round-robin по
  участникам — один человек не забивает вечеринку десятью треками подряд.
- **Экран вечеринки.** Витрина на весь вьюпорт (портал в body поверх оболочки — без скролла
  и без плеера снизу): сцена (видео / визуализатор / обложка), что играет и кто добавил,
  прогресс, крупные контролы (play/pause, пропуск), следующие позиции, QR для гостей,
  кнопка полноэкранного режима. Открытие клеймит устройство спикером; пока экран
  открыт, держится `navigator.wakeLock` (`lib/use-wake-lock.ts`) — устройство не гаснет.
- **Локальный файл.** Кнопка «Файл с устройства» видна только на устройстве-колонке; файл
  остаётся в браузере, на сервер уходит только id и снапшот метаданных.
- **Голосование за пропуск.** Кнопка «Пропустить» в комнате и на экране вечеринки; больше
  половины присутствующих (`listPresent`, не список когда-либо заходивших) — позиция
  уходит, хост пропускает всегда. Голоса живут в Redis (`jam:{jamId}:skip:{itemId}`) и
  умирают вместе с позицией — истории голосований нет. Переход на следующую позицию —
  тот же приватный путь `JamService`, что и обычный клик по треку; нет следующей — пауза
  на месте, джем не завершается. `POST /api/v1/jam/[code]/skip`.
- **Автодобор из волны.** Хвост очереди опустел — `JamService.refillFromWave` берёт до 5
  треков из `WaveService` (якорь похожести — последняя каталожная позиция, вкус —
  залогиненный присутствующий участник по ротации) и кладёт их в хвост без round-robin.
  Внешние/локальные позиции волне ничего не говорят; без инъектированной волны — no-op.
  Триггерит клиент (`handleTrackEnded` в `jam-session-provider.tsx`) при пустом хвосте на
  вечеринке; волна пуста или роут упал — тишина, как раньше. `POST /api/v1/jam/[code]/refill`
  (лимит по джему, не по участнику — добор общий).
- **Предложка по вкусу (Last.fm).** В `/profile` слушатель может привязать ник Last.fm
  (только вкус — никакого OAuth, никакого скробблинга, ничего не проигрывается оттуда).
  `GET /api/v1/party/suggest` без `q` отдаёт `user.getTopTracks` привязанного ника как
  подсказки-`HINT`, минус уже лайкнутое (дедуп по нормализованному «артист + название»).
  `PartyAddPanel` дёргает его один раз при монтировании и показывает в простое, после
  «Из любимых», блоком «Из вашего вкуса». Ника нет / ключа `LASTFM_API_KEY` нет / API
  молчит / гость без сессии — блока просто нет, без ошибок. Обложки Last.fm не входят в
  белый список `cover-hosts.ts` — отпадают в `null` осознанно.

## Каскад резолва (любой ввод → играбельная позиция)

`ExternalResolveService.resolve()`, каждый шаг деградирует в следующий:

1. своя ссылка на трек (`viremusic.ru/.../tracks/{id}`) → `VIRE`;
2. ссылка YouTube → oEmbed/Data API → `ExternalTrackRef`;
3. любая другая ссылка (Spotify, Apple Music, Яндекс, SoundCloud, что угодно) → метаданные
   страницы (провайдерский API → oEmbed-дискавери → og/twitter → JSON-LD) → шаг 4 по
   «артист + название»;
4. совпадение с каталогом по нормализованному «артист + название» (`scoreCatalogMatch`) → `VIRE`;
5. кэш резолва (`external_resolutions`, ключи `URL` и `QUERY`) → готовый `ExternalTrackRef`;
6. YouTube `search.list` → `ExternalTrackRef`;
7. ничего не сошлось → `candidates` (каталог + подсказки метаиндекса), пользователь выбирает.

**Audius — второй полноценный источник.** Публичный API без ключей и квот
(`lib/external/audius.ts`): поиск отдаёт сразу играбельные позиции, поток идёт официальным
эндпоинтом `/v1/tracks/{id}/stream` в обычный `<audio>` — **без iframe и без видео-поверхности**,
поэтому колонкой может быть любое устройство, даже с закрытым экраном вечеринки. В каскаде
Audius стоит до поиска YouTube (бесплатно), ссылки `audius.co/{артист}/{трек}` резолвятся их же
`/v1/resolve`. Хост потока разрешён в `media-src`; обложки живут на произвольных узлах сети и
в белый список не попадают — рисуется плейсхолдер.

**Никакого извлечения аудиопотока.** Играют только официальные встраиваемые плееры —
YouTube IFrame API и SoundCloud Widget. Ничего не скачивается, не перезаливается и не
проксируется через наш сервер.

### Индекс отрезолвленного

`external_resolutions` работает не только кэшем, но и **поисковым индексом**
(`DrizzleResolvedIndex`): всё, что кто-то однажды добавил, находится по «артист + название»
мгновенно, без сети и без квоты YouTube, и отдаётся как готовый к добавлению кандидат
(`kind: 'EXTERNAL'`). Чем больше вечеринок прошло, тем меньше поиск зависит от внешних API.

### Провайдерские API вместо скрейпа страницы

Страницы стримингов боту не отдаются: Spotify уводит на `accounts.spotify.com/login`
(гео + бот-UA), Apple Music отдаёт SPA-шелуху с `og:title` «Apple Music Web Player»,
`www.deezer.com` — редирект на `/soon`. Поэтому `fetchProviderMeta`
(`lib/external/providers.ts`) ходит на официальные эндпоинты по id из ссылки
(`parseProviderTrackUrl` в core): Spotify — `open.spotify.com/oembed`, Apple —
`itunes.apple.com/lookup?id=`, Deezer — `api.deezer.com/track/{id}`. Не провайдерская
ссылка или молчащий API → прежний путь (oEmbed → страница).

Ключи кэша резолва версионированы (`CACHE_VERSION` в `external-resolve-service.ts`): смена
логики каскада обесценивает старые записи — иначе негативный результат «не нашли», записанный
прежней логикой, держал бы ссылку мёртвой 30 дней.

Страница не отдалась вовсе (Яндекс.Музыка и VK отвечают ботам 403) — последним шагом
спрашиваем Odesli (`lib/external/odesli.ts`, `api.song.link`): он знает трек по ссылке любого
сервиса и отдаёт исполнителя с названием. Играбельных ссылок YouTube оттуда не приходит —
это только метаданные для дальнейшего каскада. Тот же Odesli добирает **исполнителя** для
Spotify (в oEmbed его нет): без артиста запрос «Yes Future!» приводил поиск к целому альбому.

Найденное на YouTube подписывается метаданными хинта, а не заголовком ролика с именем канала
(`labelFromHint`): в очереди стоит «Portishead — Numbed In Moscow», а не
«Harry — Portishead - Numbed In Moscow (1994 - Singles…)». Совпадение отсеивает альбомы и
сборники (`BULK_MARKERS`) — по токенам «Yes Future» проходил «…- Full Album».

Spotify oEmbed отдаёт название без исполнителя — артист достаётся из метаиндекса
(iTunes+Deezer) и принимается только при точном совпадении нормализованного названия,
иначе остаётся пустым. Обложки Spotify живут на `*.spotifycdn.com` — хост добавлен в
`cover-hosts.ts`, `img-src` и `images.remotePatterns` (три места синхронны).

## Слой источников звука

`lib/jam/jam-audio.ts` — диспетчер: наружу один `JamAudioEngine`, внутри переключение
адаптеров по `kind` активной позиции. Смена `kind` уничтожает предыдущий под-движок,
смена id внутри того же `kind` переиспользует его.

| `PlayableSource` | адаптер | как играет |
|---|---|---|
| `VIRE` | `sources/vire-source.ts` | HLS через `hls.js` (как в глобальном плеере) |
| `YOUTUBE` | `sources/youtube-source.ts` | IFrame API, нужен видео-контейнер |
| `SOUNDCLOUD` | `sources/soundcloud-source.ts` | Widget API, нужен видео-контейнер |
| `AUDIUS` | `sources/audius-source.ts` | прямой поток в `<audio>`, поверхность не нужна |
| `LOCAL` | `sources/local-source.ts` | `<audio>` над `URL.createObjectURL(file)` |

Видео-поверхность одна на вкладку и живёт в app-shell (`PartyVideoDock`), а не на странице:
iframe нельзя переносить по DOM, а размонтирование убивает звук. **Контейнера нет →
источник недоступен**: устройство просто не может быть колонкой для встраиваемой позиции,
движок молча простаивает. Адаптеры монтируются в собственный дочерний узел контейнера, а не
в сам React-узел: `YT.Player` подменяет переданный элемент на iframe — отдав ему React-узел,
мы потеряли бы поверхность навсегда после первого же трека.

**Где рисуется видео (не поверх интерфейса).** Страница объявляет слот —
`<PartyVideoSlot>` (`lib/jam/sources/video-slot.ts`, регистр в духе `video-container.ts`):
на экране вечеринки это сцена 16:9, в комнате на звуковом устройстве — компактная сцена
над очередью. Док остаётся `fixed` и в rAF подгоняет свой прямоугольник под слот. Слота нет
(ушли на другую страницу) или виден меньше чем на 90% — док возвращается в уголковый PiP
(≥200×200 — требование ToS YouTube), который **перетаскивается** и прилипает к ближайшему
углу, угол запоминается (`vire-party-pip-corner`). В комнате большая сцена под видео есть
только на десктопе: на телефоне она съедала пол-экрана, там работает PiP.

Пауза/плей **внутри** встроенного плеера (кнопка в самом окне YouTube/SoundCloud) доезжает
до джема: адаптер сравнивает событие со своим намерением (`shouldPlay`) и, если состояние
изменил пользователь, дёргает `onUserToggle` — провайдер шлёт обычную команду playback. Своё
собственное play/pause эха не даёт, поэтому цикла нет.

Позиция SoundCloud приходит событием `PLAY_PROGRESS` (у виджета `getPosition` асинхронный,
а контракт движка синхронный).

## Визуализатор

`components/visualizer/` — **один непрерывный режим**, а не набор пресетов: сцены (фрактальное
облако, лучи, ленты, спираль, фигуры Лиссажу, лава-лампа, разлёт частиц) сами сменяют друг
друга каждые 16–30 секунд с перетеканием, оттенок всё время уезжает по кругу, а параметры
каждой сцены (число рукавов, секторов, скорость, направление) разыгрываются при появлении —
как визуализации старого Windows Media Player. Включается кнопкой на экране вечеринки,
состояние в localStorage (`vire-visualizer`).

Каждая сцена рисует в свой буфер (`engine.ts`) — иначе затухающие следы одной стирали бы
другую во время перехода. Свечение — двойной обвод (широкий полупрозрачный + тонкий яркий)
вместо дорогого `shadowBlur`; симметрия — поворот с отражением вокруг центра.

Амплитуда берётся из **готовых waveform-пиков** каталожного трека (`fetchManifest`, тот же
LRU-кэш, что у плеера); у внешних и локальных позиций пиков нет — идёт процедурная огибающая.
**Web Audio не используется вообще** — тракт воспроизведения не трогаем, звук рвать нечем.
Один rAF-цикл, DPR ≤1.5, остановка на паузе, при `document.hidden` и при reduce-motion
(рисуется один статичный кадр).

При включённой визуализации встраиваемое видео уходит в угол сцены (356×200, не меньше
200×200 — ToS YouTube), а не занимает её целиком.

## Мобильный ввод

Панель добавления на телефоне живёт в нижней шторке, и клавиатура перекрывала и поле, и
список: `fixed`-элементы стоят в layout viewport, который клавиатура не сжимает. `Sheet`
теперь поднимается на `useKeyboardInset()` (`lib/use-keyboard-inset.ts`, по `visualViewport`) —
чинит все нижние шторки разом. В самой панели: поле 16px (иначе iOS зумит на фокусе),
`inputMode/enterKeyHint=search`, крестик очистки, кнопка отправки, статус «Ищем «…»» вместо
подсказок «Из любимых», которые не связаны с набранным.

## Безопасность

- Роут внешнего добавления проверяет участие и `kind === 'PARTY'` **до** резолва —
  посторонний не доводит дело до сетевого запроса и не жжёт квоту поиска.
- Произвольные пользовательские URL ходят только через `lib/external/safe-fetch.ts`:
  белый список протоколов, ручные редиректы с ревалидацией каждого хопа, резолв DNS и
  запрет приватных/зарезервированных IP (вкл. IPv6 и `::ffff:`-обёртки), таймаут,
  ограничение размера ответа и белый список content-type.
- oEmbed YouTube/SoundCloud идёт на фиксированный эндпоинт — пользовательский URL там
  только параметр, SSRF-поверхности нет.
- Обложки внешних треков проходят белый список хостов (`lib/external/cover-hosts.ts`),
  синхронный с `img-src` и `images.remotePatterns` в `next.config.ts`: `og:image`
  произвольной страницы иначе уронил бы `next/image` или упёрся в CSP. Чужой хост →
  обложки нет, рисуется плейсхолдер.

## Env

Настроены ли `YOUTUBE_API_KEY` и `LASTFM_API_KEY`, видно в админ-обзоре (`/admin`, карточки
«Поиск в сети» и «Вкус Last.fm») — иначе непонятно, почему поиск в сети молчит.

- `YOUTUBE_API_KEY` — опционально. Без ключа прямые ссылки на YouTube/SoundCloud резолвятся
  через oEmbed, работает и каталожный матч; отваливается только поиск по названию
  (`search.list`) — ввод без ссылки чаще будет отдавать кандидатов на выбор.
- `LASTFM_API_KEY` — опционально. Без ключа блок «Из вашего вкуса» просто не появляется.

## Ограничения / на будущее

- Квота YouTube Data API — 10 000 единиц в сутки, `search.list` стоит 100. Поэтому поиск
  дёргается только при добавлении (не при наборе — подсказки берутся из бесплатных
  iTunes/Deezer), а результат кэшируется в `external_resolutions` глобально, включая
  негативный результат с перепроверкой раз в 30 дней.
- Встраиваемые источники играют только на устройстве с открытым экраном вечеринки. На
  пультах гостей чужого плеера нет вовсе — это требование ToS (плеер обязан быть видимым),
  а не техническое ограничение.
- Локальные файлы переживают перезагрузку только в Chromium (хэндлы File System Access в
  IndexedDB, `restorePersistedFiles` на маунте комнаты). В Safari/Firefox файл живёт до
  закрытия вкладки. На другие устройства файл не передаётся.
- Автоплей на iOS требует жеста — на экране вечеринки для этого есть «Нажмите, чтобы
  продолжить».
- Сохранение очереди в плейлист берёт только каталожные позиции: внешние сохранять некуда.
- Last.fm-ник хранится как есть, без проверки существования аккаунта.
- Отложено: локальные файлы в глобальном плеере вне вечеринки.
