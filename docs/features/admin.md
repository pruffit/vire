# Backoffice (/admin)

## Что делает

Панель администратора. Доступна пользователям с ролью `VIEWER`, `MODERATOR`, `ADMIN`, `SUPERADMIN`.

### Роли и права

| Роль | Вход в `/admin` | Менять данные |
|------|:---:|:---:|
| `VIEWER` | ✅ | ❌ — read-only |
| `MODERATOR` | ✅ | ✅ (кроме backfill BPM/Key и генерации подборок — только `ADMIN`+) |
| `ADMIN` / `SUPERADMIN` | ✅ | ✅ всё |

`VIEWER` — read-only бэкофис (для дизайнера/наблюдателя): листает все табы и видит
данные, но управляющие элементы выглядят как обычно, а сервер **молча** игнорирует любую
мутацию (клик не меняет данные и не показывает ошибку). Гейт: `VIEWER` входит в view-роли
(`proxy.ts`, `app/admin/layout.tsx`, `nav.tsx`), но не в mutate-роли — `requireAdmin()` в
`app/admin/actions.ts` возвращает `canMutate=false`, и каждый экшен делает no-op. Эндпоинты
`backfill-analysis` и `editorial` для `VIEWER` возвращают тихий no-op-успех.

### Разделы

**Обзор** (`/admin`)
- **Требует внимания:** зависшие треки (PROCESSING > N минут), заблокированные треки, неверифицированные артисты
- **Health системы:** пинг Postgres/Redis, live-слушатели (Redis), BullMQ-очереди с ошибками
- **Каталог:** счётчики юзеров по ролям, артисты, релизы/треки по статусам
- **Вовлечённость:** прослушивания 24ч/7д/30д, уникальные слушатели, лайки/подписки/плейлисты/посты/теги/моменты

**Аналитика** (`/admin/analytics`)
- Динамика прослушиваний по дням (14 дней), график
- Топ треков за 30 дней
- Топ артистов за 30 дней
- История платформы — кривые роста (пользователи/лайки/подписки) из ежедневных
  снапшотов, период 30/90/180 дней; см. [`platform-metrics.md`](platform-metrics.md)

**Пользователи** (`/admin/users`)
- Список всех пользователей
- Смена роли (LISTENER/ARTIST/VIEWER/MODERATOR/ADMIN/SUPERADMIN)
- Верификация аккаунта

**Артисты** (`/admin/artists`)
- Фолловеры, релизы, прослушивания
- Верификация (`is_verified`)
- Скрытие с витрины (`is_active`)
- Редактор (`/admin/artists/[id]/edit`) — имя, slug, bio, avatar URL и **тема страницы**
  (пресеты/цвета/шрифты/зерно, `theme_tokens`) в обход ownership-гарда дашборда; форма
  переиспользует `ThemeEditor` (`apps/web/components/theme-editor.tsx`) — тот же
  компонент, что и в дашборде артиста. Ссылки/видео/загрузка аватара файлом — только
  в дашборде

**Треки** (`/admin/tracks`)
- Аудио-характеристики (BPM, key, genre)
- Прослушивания, лайки
- Маркер `!hls` — трек в READY без HLS-манифеста
- Редактор трека (`/admin/tracks/[id]/edit`) — паритет с дашбордом артиста: название,
  флаги (18+/эксклюзив/WIP), BPM/тональность (+переанализ), **версия** («Radio Edit»…),
  настроения, жанры (+анализ), **кредиты**, текст (LRC). Кредиты переиспользуют
  `CreditsEditor` в управляемом режиме (проп `onChange`, без своей кнопки) — состояние
  лифтится в форму и сохраняется общим `actionAdminUpdateTrack`

**Релизы** (`/admin/releases`)
- Смена статуса (DRAFT/PUBLISHED/SCHEDULED/HIDDEN)

## Где код

- **Страницы:** `apps/web/app/admin/`
- **Health-утилиты:** `apps/web/lib/admin-health.ts`
- **API admin:** `apps/web/app/api/v1/admin/` — users, artists, tracks, releases, stats
- **Middleware:** `apps/web/proxy.ts` — пускает в `/admin` роли `VIEWER`+

## Env-переменные

```
DATABASE_URL=
REDIS_URL=
```

## Известные ограничения

- SUPERADMIN не может быть понижен через UI (только через `db:make-admin`)
- Health-эндпоинт не кешируется — каждый запрос пингует Postgres и Redis
- Статистика вовлечённости — агрегаты из Postgres, без кеша; тяжёлые запросы при росте базы
