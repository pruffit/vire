# Документация фич Vire

По файлу на фичу: что делает, где код, какие env нужны, известные ограничения.
Цель — чтобы любую фичу можно было понять и поддержать, не читая весь код.

> **Правило:** новая фича не считается готовой без файла в `docs/features/`.
> (Закреплено в `CLAUDE.md`.)

## Шаблон файла

```markdown
# <Название фичи>

Одно-два предложения: что это и зачем.

## Что делает
- поведение с точки зрения пользователя/артиста/админа.

## Где код
- **Страницы/роуты:** app/...
- **API:** app/api/v1/...
- **Сервисы/логика:** packages/core/... | apps/web/lib/...
- **Данные:** packages/db/src/schema/..., таблицы/колонки.

## Env
- ПЕРЕМЕННАЯ — назначение (или «не требуется»).

## Ограничения / на будущее
- известные ограничения, edge-cases, что отложено.
```
