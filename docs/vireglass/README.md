# VireGlass

Материал «жидкое стекло» для интерфейсов Vire. Сейчас реализован **только на Android**
внутри мобильного приложения.

## Модель материала

VireGlass описывается объектом `VireGlassMaterial` (`apps/mobile/lib/vireglass/material.ts`) —
оптическими понятиями, а не униформами шейдера. Геометрия (`{width, height, cornerRadius}`)
задаётся отдельно; круг и капсула — частные случаи скруглённого прямоугольника.

```
blur · refraction · refractionScale · thickness · fresnel · fresnelPower
specular · specularPower · dispersion · tint · tintStrength
edgeStrength · edgeWidth · opacity · environment
```

Дефолт продукта — **VireGlass Material v1**. Приоритеты выбора: читаемость → оптическая
правдоподобность → сдержанность → устойчивость → стоимость. Не максимальная интенсивность.
Обоснование каждого значения — `material-lab.md`.

Материал переводится в рендер двумя адаптерами (`adapters.ts`): `toLensProps` — пропы
нативной вьюхи, `toSurfaceUniforms` — статические униформы SKSL. Деталей Android в
публичной модели нет.

## Известные ограничения

- **Оптика Material v1 проверена глазами** на Xiaomi 2311DRK48G (Android 16, release) и
  на эмуляторе: преломление связно, морфинг даёт непрерывную среду, тень сдержанна.
  Не изолировались тумблерами `thickness` и `fresnel` — их вклад по отдельности глазами
  не разводился (`material-lab.md` E-04, E-05).
- **Material v1 не дороже конвейера с вырожденным преломлением** — совпадение p50 во всех
  шести сценах, на 10 поверхностях до миллисекунды
  (`benchmarks/2026-08-29-material-v1-device.md`). Оптика линзы не стоит ничего измеримого;
  дорог захват бэкдропа.
- **Рабочий диапазон — до 6 одновременных поверхностей.** 1–6 держат 113–120 кадров/с
  при GPU 4–7 мс; с 7-й наступает насыщение (101 кадр/с), с 9-й — 80 и ниже.
  `benchmarks/2026-08-29-scaling-validation.md`. Реальный максимум VireMusic — 3.
- **Цена — в числе поверхностей, а не в площади блюра.** Полноширинная панель 383×320 dp
  (площадь ×11.4 к кнопке) стоит 8 мс и держит 120 кадров/с; семь кнопок меньшей суммарной
  площади — 12 мс и 101. Каждая поверхность несёт свой `BlurView`, перерисовывающий весь
  экран независимо от размера стекла.
- **`Janky frames` этого не показывает.** Дедлайн приложения — 10 мс, у части кадров снят
  вовсе, поэтому просадка 120 → 72 идёт при `0.00 % janky`. Судить по частоте кадров, а не
  по jank. Там же — про удвоенный счётчик `Total frames rendered` на этом ROM.
- **Прежний замер (0.2–0.3 мс на поверхность) мерил конвейер без RenderEffect** — линза не
  включалась из-за рассинхрона имён пропов (`material-lab.md` E-01). Его цифры верны для
  того, что мерили, но опорной точкой для Material v1 не являются.
- **Настоящее стекло доступно только вне экранов** — таб-бару и мини-плееру. Внутри
  экрана оно деградирует до полупрозрачной плашки: положить стекло внутрь его же цели
  захвата нельзя, дерево RenderNode замыкается и рантайм падает. ADR-001 §2.
- **Преломление требует Android 13+.** Ниже — равномерное увеличение, это лупа, не линза.
- **Измерено на одном устройстве** (Dimensity 7200 Ultra, Android 16, release, 120 Гц).
  Слабое железо, 60/90 Гц, крупные панели и длительная нагрузка не проверены.
- **Морфинг стоит дороже.** На слитой сцене нормаль берётся конечными разностями — это
  4 дополнительных вычисления SDF на пиксель. В продовом пути объединение выключено
  (`smoothing = 0` отсекает вторую форму до всех вычислений).

## Стенд

Стенд заменяет собой приложение и включается переменной окружения — по умолчанию выключен,
продовый путь не задевает.

**Стенд материала** (`EXPO_PUBLIC_GLASS_LAB=material`) — тумблеры на каждое оптическое
явление, слайдеры по всем параметрам с диапазонами из модели, пресеты, debug-режимы, выбор
формы, морфинг. Фон намеренно диагностический: мелкий текст, 1px-линии, шахматка, жёсткие
границы, светлые и тёмные зоны, насыщенные цвета, градиенты, движение. Красивый градиент
для этого не годится — он прячет проблемы рендеринга.

Тумблер эффекта **обнуляет параметр**, а не переключает вариант шейдера: сравнение ON/OFF
идёт на одной и той же программе.

**Проверка корректности** (зонды доступа к бэкдропу) — годится эмулятор:

```bash
emulator -avd VireMusic_Test -gpu host   # без -gpu host смысла нет
cd apps/mobile
EXPO_PUBLIC_GLASS_LAB=1 npx expo start --dev-client
```

**Замер производительности** — только физическое устройство и только release.
Эмулятор завышает стоимость GPU примерно в 20 раз и для этого непригоден:

```bash
cd apps/mobile/android
EXPO_PUBLIC_GLASS_LAB=bench ./gradlew assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
adb shell am start -n com.anonymous.viremobile/.MainActivity
```

Сцены: 1 / 2 / 3 / 6 / 10 поверхностей и контроль (0), плюс переключатель материала
`baseline` / `Material v1`. Протокол и метрики —
`benchmarks/2026-08-28-scaling-device-release.md`.

Зонд `glass-lab` переключается по кнопке между тремя режимами: сырая выборка, выборка
с маркером живости шейдера, карта альфы. Последний однозначно показывает, пришло ли
в шейдер хоть что-нибудь.
