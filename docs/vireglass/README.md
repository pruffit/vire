# VireGlass

Материал «жидкое стекло» для интерфейсов Vire. Ядро живёт в общем пакете
**`@vire/vireglass`** (`packages/vireglass`) и рисуется двумя целями из одного текста шейдера:
Android (AGSL, нативная линза) и веб (GLSL ES 3.0, WebGL2). Мобильные `apps/mobile/lib/vireglass/*` —
тонкие ре-экспорты из пакета; натив и компоненты остались в мобилке.

> **Ядро вынесено в open source 19.09.2026** — github.com/pruffit/vireglass, пакет npm
> `vireglass`, Apache-2.0, всё на английском. Публичный репозиторий — источник правды;
> монорепо перейдёт на зависимость с npm отдельным шагом, после публикации в реестре.
> До тех пор `packages/vireglass` живёт как есть, и две копии будут расходиться.
> Состав выноса, форма пакета и таблица переименований кириллического API —
> `docs/superpowers/specs/2026-09-19-vireglass-open-source.md`.
>
> `kit/` и `medium/` в вынос не вошли: по плану от 14.09 они в полёте и уезжают
> в отдельный продукт VireKit.

Веб-часть, стенд `/rnd` и измеритель кадра описаны отдельно — `docs/features/vireglass-web.md`.

## Модель материала

Материал описывается **причинами**, а не униформами шейдера
(`apps/mobile/lib/vireglass/material.ts`):

```
ior · thickness · bevel · roughness · film · environment · legibility · ink · presence
```

Всё остальное — **следствия**, они выводятся (`optics.ts`) и руками не задаются: сила
преломления, увеличение, Френель, блик, дисперсия, дифракция, интерференция, оттенок среды,
плотность тела, подхват цвета окружения. Отдельных ручек «сила радуги» или «яркость кромки»
в модели нет: из них собирались состояния, которых у стекла не бывает.

Геометрия (`{width, height, cornerRadius}`) задаётся отдельно; круг и капсула — частные
случаи скруглённого прямоугольника. Дефолт продукта — «вода»: `VIREGLASS_MATERIAL`.

Материал переводится в рендер двумя адаптерами (`adapters.ts`): `toLensProps` — пропы
нативной вьюхи, `toSurfaceUniforms` — статические униформы SKSL. Деталей Android в публичной
модели нет.

### Униформы едут одним каналом

`toLensProps` собирает `uniformNames` / `uniformSizes` / `uniformValues` — имя, размер и
значения вместе. Отдельных `Prop` под каждую величину в Kotlin больше нет: именно они давали
молчаливое отключение линзы при опечатке (`material-lab.md` E-01, E-35). У нативной вьюхи
остались только те униформы, которые знает она одна: свой размер и своё место на экране.

## Как стекло решает, каким ему быть

Три петли, все автоматические.

1. **Тело под фон, ГРАДИЕНТОМ.** Зонд отдаёт не одно число на поверхность, а плоскость
   светлоты: наклон по каждой оси. Стекло разводит свою светлоту с надписью в КАЖДОМ месте
   детали — над светлой половиной темнеет сильнее, над тёмной почти не трогает. Плоскость —
   самая грубая модель, которая описывает «одна половина светлее другой», и единственная
   гладкая по построению: точечная оценка на изломе плотности давала призрачные копии текста.
2. **Плотность под разнородность.** Мелкую фактуру (шахматка, строка текста) плоскостью не
   описать — там плотность поднимается целиком, по размаху светлоты. Это то же, что
   настоящее стекло делает шероховатостью: перестаёт быть окном.
3. **Различимость самой детали** (`presence`). Над однородным фоном преломлять нечего, и
   стекло честно исчезает — для куска фона это правильно, для элемента управления нет. Тело
   отходит от фона по светлоте не меньше чем на заданную величину, и знак берётся ОТ ФОНА:
   над тёмным светлеет, над светлым темнеет. Полярность надписи тут не годится — с ней
   требование меняло бы знак вместе с ней, и над светлым фоном «подсветка» деталь гасила бы.
   Требование не складывается с читаемостью, а конкурирует: побеждает сильнейшее, вместе
   со своим тинтом — их тинты могут смотреть в разные стороны.
4. **Полярность контента.** Решение принимается по ЦЕНЕ удержания, а не по контрасту:
   сколько плотности нужно телу, чтобы светлая надпись осталась читаемой. Ниже 0.48 —
   работает стекло; выше — деталь перестала бы быть стеклом и стала крашеной плашкой, и
   слово переходит к приложению. По контрасту решать нельзя: он падает и на насыщенном
   жёлтом, и светлые иконки перекрашивались в тёмные на цветных блоках. Правило продукта —
   надпись светлая везде, кроме очень светлого фона (примерно с 0.90); возврат с 0.72, три
   подтверждения подряд, перекраска 420 мс косинусом.

Светлоту фона считает **нативный зонд** (`GlassBackdropView`): раз в 180 мс он рендерит свой
узел захвата в сетку 48×96 через `HardwareRenderer` + `ImageReader` и отдаёт каждой линзе
статистику её прямоугольника — среднюю светлоту, перцентили 10/90 и пестроту (удвоенное
среднее отклонение). Считать это в шейдере нельзя: плотность — нелинейная функция светлоты
с изломом, и дискретность оценки превращалась в призрачные копии текста (E-36).

Приложению статистика приходит событием `onBackdropSample`; решение о полярности —
`lib/vireglass/adaptation.ts`, раздача цвета детям — `useInkColor` (`glass-ink.tsx`).
`GlassPanel` и `LiquidGlassButton` включают это по умолчанию.

## Оптика

| Явление | Где считается | Чем задано |
|---|---|---|
| Преломление, увеличение | линза (AGSL) | `ior`, `thickness` |
| Сферическая аберрация | линза, только фаска | `ior`, `bevel` |
| Дисперсия | линза, только фаска | отклонение канала по Коши (синий гнётся сильнее) |
| Отражение окружения | линза, только фаска | Френель от `ior`, сбор восемью отсчётами вокруг детали |
| Интерференция (переливы) | линза, множитель оттенка к отражению | `film` (толщина плёнки, нм) |
| Дифракция (краевые полосы) | линза, у самой кромки | та же λ-зависимость, что у дисперсии |
| Подсветка и подхват цвета | линза | окрестность детали; на светлом сходит на нет |
| Блик от ключевого света | поверхность (SKSL) | `roughness`, наклон устройства |
| Поглощение у кромки, тень | поверхность | `thickness`, `bevel` |

Дисперсия, дифракция и интерференция — одна причина (зависимость от длины волны) и один
множитель оттенка, нормированный на своё среднее: они красят отражение, но не делают его
ярче. Стоимость — арифметика, ни одной лишней выборки текстуры.

## Известные ограничения

- **Замеры до E-34 недействительны.** Узел захвата не получал `setPosition`, поэтому линза
  семплировала пустоту: всё, что мерилось «после чистого захвата», мерило стекло, которому
  нечего показать. Метрика шума такое состояние не отличает от чистого рендера — рядом
  всегда мерить контраст со средой (внутри против снаружи).
- **Разнородный фон закрывается тонированием, а не размытием.** Размытие в этой модели —
  вспомогательное средство: оно смягчает фактуру под надписью, но разводить светлоту обязана
  плотность. Дай размытию волю — и буквы под стеклом перестают быть буквами; никакая
  читаемость этого не стоит. Потолок шероховатости 12 dp, автоматическая часть вдвое слабее.
- **Ничто в теле не зависит от места на детали** — ни рассеяние, ни подсветка. Любой
  множитель вида `mix(a, b, t)` на теле читается пятном по центру: два разных стекла в одной
  форме. За резкость кромки отвечает геометрия, за её выделение — Френель.
- **Порог читаемости — потолок светлоты тела, а не разность с надписью.** Разность не
  описывает читаемость: «на 0.14 темнее белого» — это светлота 0.86, на которой белый текст
  не виден. Потолок 0.62…0.38 по требованию (E-43).
- **Вся геометрия движения — в одном трансформе обёртки.** Линза нативная, шейдер её не
  гнёт; продублировать деформацию в SKSL значит завести два конвейера на одно движение, и
  слои разъедутся на кадр. Два `rotate` в одном массиве `transform` при этом схлопываются —
  повороты обязаны лежать в разных узлах.
- **Зонд видит фактуру крупнее клетки 22 px.** Мельче — усредняется, и стекло считает фон
  однородным. Для продукта этого хватает (самая мелкая фактура — обложки и текст).
- **Настоящее стекло доступно только вне экранов** — таб-бару и мини-плееру. Внутри экрана
  оно деградирует до полупрозрачной плашки: положить стекло внутрь его же цели захвата
  нельзя, дерево RenderNode замыкается и рантайм падает. ADR-001 §2.
- **Преломление требует Android 13+.** Ниже — равномерное увеличение, это лупа, не линза.
- **Правка шейдера требует перезапуска приложения**, а не только Fast Refresh: исходник
  уезжает пропом из мемоизированного адаптера.
- **Перемерено на устройстве 31.08** (2311DRK48G, release, 120 Гц): цена поверхности около
  0.8 мс GPU при бюджете кадра 8.33 — 4 мс на одной, 7 на трёх, 8 на шести. Прежние цифры
  недействительны, они сняты с пустой линзы
  (`benchmarks/2026-08-31-device-after-capture-fix.md`).
- **Порог насыщения не найден.** Шесть поверхностей ещё держатся; семь и больше сцена стенда
  не выкладывает — они упираются в край экрана.
- **Судить о кадрах по эмулятору нельзя.** Он завышает стоимость GPU примерно в 20 раз;
  корректность проверять на нём можно, стоимость — нет.

## Стенд

Стенд заменяет собой приложение и включается переменной окружения — по умолчанию выключен,
продовый путь не задевает.

```bash
cd apps/mobile
pnpm dev --lab          # Metro + стенд материала на подключённом устройстве
```

**Стенд управляется снаружи** — тапами не воспроизводится, они приходят с опозданием и
теряются:

```bash
node scripts/glass-probe.mjs capture белое zone=11 preset=2   # выставить, дождаться, снять
node scripts/glass-probe.mjs stats белое 470 460 60 60        # светлота, шум, доля в упоре
node scripts/glass-probe.mjs band  белое 470 440 120 240      # полосы на градиенте
node scripts/glass-probe.mjs crop  белое 300 320 500 500 2    # кроп с увеличением
node scripts/glass-probe.mjs fps 5                            # кадры за окно
```

Состояние стенда читается прямо из кадра: в углу экрана метка из двух квадратов — маркер
фиксированного цвета (по нему скрипт находит метку, не зная плотности экрана) и данные:
индексы зоны, пресета и debug-режима, полярность надписи и замер фона.

Зоны фона намеренно недружелюбны к рендереру: чистый чёрный и чистый белый, почти-чёрный и
почти-белый градиенты (единственное место, где виден бандинг), граница чёрного и белого,
шахматка, мелкий текст, насыщенные цвета, продуктовый список с обложками. Красивый градиент
для стенда не годится — он прячет артефакты.

**Замер производительности** — только физическое устройство и только release. Эмулятор
завышает стоимость GPU примерно в 20 раз и для этого непригоден.
