# Замер на физическом устройстве — 28.08.2026, release

**Что меряли:** стоимость кадра в зависимости от числа стеклянных поверхностей
в текущей архитектуре (dimezis-захват + AGSL-линза + Skia-поверхность), на телефоне,
в release-сборке.

Это замер, ради которого затевалась Phase 2.1. Эмуляторные цифры из
`2026-08-28-scaling-emulator.md` он **опровергает** — см. §«Сравнение».

## Устройство

| Параметр | Значение |
|---|---|
| Модель | Xiaomi 2311DRK48G (кодовое имя `duchamp`) |
| SoC | MediaTek **MT6897** (Dimensity 7200 Ultra) |
| Android | **16** (SDK 36), HyperOS |
| ABI | arm64-v8a |
| RAM | 11.6 ГБ |
| Экран | 1220 × 2712, 480 dpi (×3), режимы 30 / 60 / 90 / **120** Гц |
| Сборка | **release** (`assembleRelease`), JS-бандл вшит, Metro не участвует |

**Частота во время замеров: 120 Гц** (`mActiveRenderFrameRate=120.00001`),
то есть бюджет кадра — **8.33 мс**.

### Питание и температура

**Телефон был подключён к USB и заряжался** (`USB powered: true`, `status: 2`),
уровень заряда 100% — то есть ток заряда минимальный, но нагрев от него не исключён.

> Первая редакция протокола писала в лог только `AC powered: false` и потому
> ошибочно фиксировала «не заряжается». Поправлено: скрипт логирует все три поля.

Температура батареи: прогон 1 — 33.0 → 34.1 °C; прогон 2 — 35.3 → 36.1 °C.
Троттлинга не наблюдалось (`Number Missed Vsync: 0` во всех конфигурациях).

### Что не удалось

**Переключить частоту на 60 / 90 Гц через adb не получилось.** Пробовали
`settings put system min_refresh_rate/peak_refresh_rate` и
`cmd display set-user-preferred-display-mode` — HyperOS их игнорирует, экран остаётся
на 120 Гц под нагрузкой. Замер сделан на 120 Гц, то есть **на самом жёстком бюджете
из трёх**. Для 60/90 Гц потребуется ручное переключение в настройках телефона.

## Протокол

Тап по кнопке N → 3 с на стабилизацию → скриншот сцены → **×3 повтора**:
`dumpsys gfxinfo reset` → 12 с анимации → снятие статистики.

Сцена и фон идентичны между конфигурациями. Каждая сцена подтверждена скриншотом
(§9): проверялось число видимых стёкол, наличие блюра и преломления.

## Что из этого следует

**1. Ни одного пропущенного кадра ни в одной конфигурации.**
`Janky frames: 0 (0.00%)`, `Number Missed Vsync: 0`, `Number Frame deadline missed: 0` —
включая 10 поверхностей на 120 Гц.

**2. Стоимость стекла на этом железе — на уровне шума измерения.**
GPU-время: контроль 5–7 мс, одно стекло 3–5 мс, десять стёкол 6–7 мс. Контроль местами
дороже одного стекла — так выглядит величина, тонущая в разбросе. Общее время кадра (p50)
вообще плоское: 15–18 мс независимо от N.

Осторожная верхняя оценка прироста: **+1–2 мс GPU на 6–10 поверхностей**, то есть
порядка **0.2–0.3 мс на стекло**.

**3. Рабочая точка продукта (2 поверхности) обходится бесплатно.**
GPU 4–6 мс против 5–7 мс контроля — разницы нет.

### Сравнение с эмулятором

| | Эмулятор (debug) | Устройство (release) |
|---|---|---|
| Прирост на стекло | **4.3–5.2 мс** | **~0.2–0.3 мс** |
| p50 при 10 стёклах | 77 мс | 17 мс |
| janky при 10 стёклах | 73.2 % | **0.00 %** |
| База (0 стёкол) | 34 мс | 17 мс |

**Эмуляторные цифры завышают стоимость стекла примерно в 20 раз.** Причины обе известны
и обе устранены здесь: десктопная iGPU через слой трансляции вместо тайлового мобильного
GPU, и debug-сборка с JS в dev-режиме.

Вывод для процесса: **эмулятор не годится даже для оценки порядка величины** в задачах,
упирающихся в GPU. Он пригоден только для проверки корректности (как в §9 ADR-001).

## Границы этого замера

- **Одно устройство.** Dimensity 7200 Ultra — средний сегмент 2024 года. На более слабых
  GPU (Helio, старые Adreno) картина может отличаться; переносить эти цифры на «Android
  вообще» нельзя.
- **Только 120 Гц.** 60 и 90 Гц не проверены (adb не переключает частоту на HyperOS).
  При этом 120 Гц — самый жёсткий бюджет, так что для 60/90 запас только больше.
- **Короткие прогоны.** 12 с × 3 повтора на конфигурацию, суммарно ~4 мин под нагрузкой.
  Устойчивую производительность на десятках минут это не показывает.
- **Телефон заряжался** — вклад зарядки в нагрев не изолирован.
- **Только вертикальная ориентация**, только эта сцена, только круглые кнопки 58 dp.
  Панели большой площади (мини-плеер во всю ширину) не мерялись, а площадь блюра —
  первое, что влияет на bandwidth.
