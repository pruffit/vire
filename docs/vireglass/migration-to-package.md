# Переезд на пакет `vireglass`

Ядро вынесено в open source 19.09.2026 (github.com/pruffit/vireglass, npm `vireglass`,
Apache-2.0). До переезда монорепо живёт на своей копии в `packages/vireglass`, и две
копии расходятся. Здесь — проверенный план подмены.

Потребители ядра: **VireBook** (расширение браузера, чистый JavaScript), **мобилка**
(React Native) и **веб**. Плюс тот, кто возьмёт его с GitHub, — из-за него планка выше,
чем «у нас собирается».

## Что делать

1. `pnpm add vireglass@^2 --filter @vire/vireglass` — после публикации 2.0.0 в реестре.
2. `packages/vireglass/src/index.ts` становится реэкспортом:

   ```ts
   export * from 'vireglass';
   export * from './reference-scene';
   ```

   Остальные `src/*.ts` удаляются. `web/reference-draw.ts` остаётся — он рисует наши
   полотна, а не чужие.
3. `useGlassAdaptation` и `GlassAdaptation` — из `vireglass/react`, не из корня. Ядро
   не тянет React намеренно: до этого `require('vireglass')` падал «Cannot find module
   'react'» в любом проекте, где его нет. Теперь это ловит гейт `check:package`.
4. Компоненты для RN — из `vireglass/native`. Он приезжает исходниками на TypeScript,
   как принято для RN-библиотек: Metro их транспилирует, а его peer-зависимости
   (Skia, Reanimated, expo-sensors) Node всё равно не разрешит.

## Переименовать: ключи пресетов

Найдено настоящей подменой, а не сверкой имён: ключи `MATERIAL_PRESETS` тоже переведены.
Сверка экспортов этого не видит — имя `MATERIAL_PRESETS` есть в обеих копиях, разошёлся
союз строковых литералов внутри.

| монорепо | ядро |
|---|---|
| `Вода` | `water` |
| `Стекло` | `glass` |
| `Кристалл` | `crystal` |
| `Матовое` | `frosted` |
| `Толстое` | `thick` |
| `Плёнка` | `thin` |
| `Бензин` | `iridescent` |

Пять мест обращения: `apps/mobile/components/liquid-glass.tsx`,
`apps/mobile/components/player/progress-line.tsx`, `apps/mobile/lib/vireglass/glass-ink.tsx`,
`apps/mobile/lib/__tests__/vireglass-material.test.ts`, `apps/web/rnd-src/main.ts`.

## Что не едет: сверочные полотна

Словарь видов слоя разошёлся при переводе ядра на английский.

| | виды слоя |
|---|---|
| монорепо | `заливка полосы шахматка ступень черта сетка градиент` |
| ядро | `flat stripes checker step bar grid gradient` |

Любой `switch (layer.kind)` в отрисовке сломался бы при подмене.

Это не блокер, а граница. Все потребители полотен — стендовые:
`apps/mobile/screens/material-lab*.tsx`, `apps/web/rnd-src/*`,
`packages/vireglass/src/web/reference-draw.ts` и тесты. Ни одного продуктового.

В ядре 2.0.0 полотна убраны с корня на подпуть `vireglass/reference` именно поэтому —
чтобы хост со своими полотнами мог взять материал, не обходя коллизию имён. Так что
стенд остаётся у нас, а из пакета берётся материал. Коллизии после подмены не будет:
корень ядра `REFERENCE_SCENES` больше не экспортирует.

## Что проверено

Подменой, а не рассуждением: пакет `vireglass@2.0.0` поставлен в монорепо,
`packages/vireglass/src/index.ts` заменён на реэкспорт, прогнан `typecheck`.

**Результат — четыре ошибки, все в исходниках приложения:**

| | |
|---|---|
| 3 × `useGlassAdaptation` не экспортируется | переезд в `vireglass/react`, см. шаг 3 |
| 1 × `"Вода"` не подходит под союз | переименование ключей пресетов, см. выше |

Веб чист. Сам пакет `@vire/vireglass` с подменённым `index.ts` типизируется без ошибок.

Отдельно сверено: 154 экспорта монорепо против 172 у ядра (недостающих четыре, все
объяснены), формы `VireGlassMaterial`, `VireGlassOptics`, `VireGlassGeometry` и
`BackdropSample` идентичны поле в поле, все входы пакета грузятся из настоящей установки
в CommonJS и ESM.

> **Ставить зависимость правкой `package.json` и `pnpm install` из корня, не
> `pnpm add --filter`.** Фильтрованный `add` при `autoInstallPeers` тащит peers мимо
> `pnpm.overrides` и плодит вторые копии типов RN — первый прогон этой проверки дал два
> десятка ошибок в `node_modules`, ни одной настоящей. См. предупреждение в корневом
> `CLAUDE.md`.
## Чем поведение будет отличаться

Ядро ушло вперёд по измеренному против референсных кадров. Крупное перенесено обратно
сюда — [#123](https://github.com/pruffit/vire/pull/123) (спектральная кромка, подхват
цвета) и [#132](https://github.com/pruffit/vire/pull/132) (лепесток ключевого света,
различимость по телу, насыщение размера), — так что подмена не должна сдвинуть картинку
заметно.

Чего в монорепо нет вовсе и что приедет вместе с пакетом:

- путь по живому DOM (`vireglass/dom`) — преломление настоящей страницы, без канваса;
  это то, на чём поедет VireBook;
- спектральная карта, тинт основного действия, материализация вместо появления через
  прозрачность, концентричность с запасным радиусом;
- закон (`vireglass/law`) — все 120 калиброванных чисел с происхождением каждого и
  честной пометкой тех 42, которых никто не измерял.

## Порядок

Переезд не обязан быть одним шагом. Сначала мобилка (её `lib/vireglass/*` — уже тонкие
реэкспорты, менять почти нечего), потом веб, потом удаление копии. VireBook начинает
сразу с пакета — у него своей копии нет.
