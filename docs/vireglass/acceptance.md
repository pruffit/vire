# Приёмка VireGlass — как проверить работу самому

Документ для того, чтобы не верить на слово. Каждый пункт — что запустить, куда смотреть и
что считать провалом. Числа в колонке «норма» получены на замерах, ссылки — на разбор.

Стенд заменяет собой приложение и включается переменной окружения; продовый путь не задевает.

```bash
cd apps/mobile
pnpm dev --lab                     # Metro + стенд на подключённом устройстве (debug)
```

**Телефон по Wi-Fi.** На телефоне: «Для разработчиков» → «Отладка по Wi-Fi» → включить. Дальше
с машины, без USB и без кода сопряжения, если телефон уже сопряжён:

```bash
adb mdns services                  # покажет adb-XXXX  _adb-tls-connect._tcp  192.168.x.y:PORT
adb connect 192.168.x.y:PORT
export ANDROID_SERIAL=192.168.x.y:PORT   # если рядом ещё и эмулятор
```

Порт меняется при каждом включении отладки — брать его из `mdns services`, а не запоминать.

Стенд управляется **диплинком**, а не тапами: тап через adb приходит с опозданием и
теряется, и замер уходит не в то состояние.

```bash
adb shell am start -a android.intent.action.VIEW -d 'vire://lab?zone=11&preset=0&panel=0'
```

Кавычки обязательны: без них `&` съедает шелл устройства и доезжает только первый параметр.
Параметры: `zone` (0…12), `preset` (0…6), `debug` (0…11), `stage`, `count`, `morph`, `move`,
`panel`, `auto`, плюс любой параметр материала по имени (`ior`, `film`, `legibility`, …).

Измеритель кадра — `node scripts/glass-probe.mjs`. Команды: `capture` (выставить состояние,
дождаться подтверждения, снять), `stats`, `band`, `crop`, `sweep`, `fps`, `bench`.

Состояние стенда читается прямо из кадра: слева под строкой степперов лежит метка — маджентовый
маркер и шесть серых клеток (зона, пресет, debug, полярность надписи, замер фона, пестрота).
Данные серые не случайно: экран телефона гонит скриншот через цветовой профиль, и насыщенные
цвета приезжают искажёнными (чистая маджента как 234,51,247), а серые проходят один в один.

## 1. Шум и артефакты на краях диапазона

```bash
node scripts/glass-probe.mjs sweep
```

Прогон по десяти зонам фона: чистый чёрный и белый, почти-чёрный и почти-белый градиенты,
граница чёрного и белого, шахматка с мелким текстом, список с обложками, насыщенные цвета.
В каждой зоне меряется ПАРА — внутри стекла и на том же участке экрана рядом.

| Что | Норма | Провал |
|---|---|---|
| `шум` внутри стекла | 0.00 во всех зонах | больше, чем снаружи |
| `упор` (пиксели в 0 или 255) | 0 % | на белом фоне было 88.8 % |
| `band` на почти-чёрном градиенте | 0 скачков > 0.8 | видимые полосы |
| `Δ` (стекло минус фон) | не ноль хотя бы в части зон | ноль везде = стекла на кадре нет |

Последняя строка — главная. Метрика шума одинаково хвалит и чистый рендер, и стекло,
которому нечего показать: ровно на этом полтора дня работы ушло в пустоту (`material-lab.md`
E-34). Судить по одному шуму нельзя.

## 2. Однородность линзы

```bash
node scripts/glass-probe.mjs capture проверка zone=4 preset=0 panel=0
node scripts/glass-probe.mjs crop проверка 350 400 400 380 1
```

Смотреть глазами на снимок. **Провал**, если середина детали размыта сильнее кромки: это
читается шаром с мутной серединой и резким ободком, то есть двумя разными стёклами в одной
форме. Рассеяние обязано быть одинаковым по всей линзе.

**Провал**, если буквы под стеклом перестали быть буквами. Размытие здесь вспомогательное:
оно смягчает фактуру, а разводит светлоту плотность тела. Проверять на зоне 4
(шахматка + текст 11…28 px) и на зоне 3 (список с обложками).

## 3. Автоматическая полярность контента

```bash
node scripts/glass-probe.mjs capture белое zone=11 panel=0
node scripts/glass-probe.mjs capture чёрное zone=0 panel=0
```

Над стеклом стоит надпись «Читаемость». Над **белым** фоном она обязана стать тёмной, над
**чёрным** — светлой. Переход — 420 мс, косинусом; заметить его как событие не должно.
Текущая полярность видна в метке состояния (`ink`: 1 светлая, 0 тёмная).

Перекраска — последнее средство, а не оптимизация контраста: над средним серым обе
полярности читаются, и стекло не обязано ничего трогать. Дёрганье надписи туда-обратно при
прокрутке — **провал**.

## 4. Градиентное тонирование

```bash
node scripts/glass-probe.mjs capture граница zone=5 panel=0
node scripts/glass-probe.mjs crop граница 350 400 400 380 1
```

Стекло стоит на границе чистого чёрного и чистого белого. Норма: чёрная половина осталась
чёрной, светлая притушена примерно до среднего серого, переход через деталь плавный,
граница под стеклом осталась границей. **Провал** — если половины затонированы одинаково
(тогда надпись тонет над светлой) или если граница размылась в кашу.

## 5. Оптика

Сравнивать пресеты: `preset=0` вода (продовый дефолт), `preset=2` кристалл (всё утрировано),
`preset=6` бензин (плёнка 620 нм — переливы).

| Явление | Где смотреть | Признак |
|---|---|---|
| Преломление | зона 5 или 12, кромка | линия под стеклом гнётся у фаски |
| Дисперсия | `preset=2`, зона 5 | цветной веер у кромки, синий уходит дальше красного |
| Интерференция | `preset=6`, зона 8 | бензиновый перелив на кромке, не на теле |
| Дифракция | `preset=2`, зона 0 → 5 | тонкие спектральные полосы у самого края |
| Отражение окружения | зона 3 (список) | кромка со стороны обложки берёт её цвет |
| Морфинг | `morph=1` | две формы = одно тело, блик и кромка непрерывны |

Отдельно: `debug=8` показывает поле дисперсии, `debug=10` — спектральный множитель,
`debug=11` — карту плотности (красный канал), `debug=6` — бэкдроп без оптики (опорная точка).

## 6. Кадры

**Только физическое устройство и только release.** Эмулятор завышает стоимость GPU примерно
в 20 раз — для проверки корректности годится, для оценки стоимости не годится даже по порядку.

```bash
# сборка стенда в release
PW=$(cat vire-upload-keystore.password.txt)
ORG_GRADLE_PROJECT_VIRE_UPLOAD_STORE_PASSWORD=$PW \
ORG_GRADLE_PROJECT_VIRE_UPLOAD_KEY_PASSWORD=$PW \
EXPO_PUBLIC_GLASS_LAB=material VIRE_FAST_BUILD=1 node scripts/build-release.mjs

adb install -r android/app/build/outputs/apk/release/app-release.apk
node scripts/glass-probe.mjs bench
```

Прогон по сценам: контроль без стекла, 1/2/3/6 поверхностей, продуктовый стек. Фон при этом
движется — на статике захват не перезаписывается и кадры не набираются.

Ориентир — замер 31.08 на 2311DRK48G (release, 120 Гц, бюджет кадра 8.33 мс):

| Сцена | GPU p50 |
|---|---|
| 1 поверхность | 4 мс |
| 2 поверхности | 5 мс |
| 3 поверхности | 7 мс |
| 6 поверхностей | 8 мс |
| продуктовый стек | 7 мс |

Смотреть на **GPU p50**, а не на `кадров/с`: счётчик `Total frames rendered` на этом ROM
удвоен, и абсолютное значение по нему брать нельзя. И не на `janky`: у приложения часть
кадров снята с учёта, просадка 120 → 72 идёт при 0 % janky. Записывать частоту экрана
(`dumpsys display | grep mActiveRenderFrameRate`), заряд и температуру — на зарядке и на
горячем телефоне результат другой.

**Провал**: GPU p50 на трёх поверхностях выше 8.33 мс, то есть продуктовый максимум
перестал помещаться в кадр.

## 7. Гейты

```bash
pnpm --filter @vire/mobile typecheck
pnpm --filter @vire/mobile test
pnpm turbo run typecheck
pnpm turbo run check:layers
```

Тесты закрывают в том числе то, что глазами не увидеть: совпадение констант модели тела в
JS и в тексте шейдера (иначе приложение судит о читаемости по одной физике, а рисует другую),
полноту канала униформ и то, что каждая униформа шейдера кем-то заполняется.
