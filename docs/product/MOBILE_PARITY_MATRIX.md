# Матрица паритета: Веб → Мобилка

Дата: 2026-08-29 · Коммит: `0aad30d1`
Метод: трассировка реализации в `apps/web`, `apps/mobile`, `packages/*`, `docs/features/*`.
Ни одна строка не выведена из имени файла.

## Как читать

**Статус паритета:**

| Код | Значение |
|---|---|
| `FULL` | функция есть на мобилке и работает эквивалентно |
| `PARTIAL` | есть, но урезана или неполна |
| `BROKEN` | есть, но не может работать корректно |
| `POOR UX` | есть и работает, но качество взаимодействия неприемлемо |
| `BACKEND READY` | бэкенд отдаёт всё нужное, мобильной реализации нет |
| `WEB ONLY` | осознанно только веб (обосновано в строке) |
| `DESKTOP ONLY` | принципиально не мобильный интерфейс |
| `N/A` | неприменимо к мобильной платформе |

**Важность для пользователя (В):** `1` критично · `2` важно · `3` полезно · `4` опционально
**Релевантность мобиле (М):** `↑` мобилка сильнее веба · `=` равнозначно · `↓` слабее · `✕` не нужно

**Доказательства:** `[C]` код · `[T]` тест · `[B]` артефакт сборки · `[E]` эмулятор · `[D]` устройство · `[I]` вывод · `[?]` неизвестно

## 15. Отчёт о прослушивании — семантика, которую нельзя нарушить

Задание требует не просто «дёрнуть эндпоинт». Прослеженная реализация веба `[C]`:

```
POST /api/v1/session          → сервер генерит uuid и подписывает HMAC-SHA256
                                (клиентский id подписывать нельзя — обесценит подпись)
      ↓ sessionId
проигрывание идёт, клиент копит время
      ↓ трек сменился / остановлен
POST /api/v1/tracks/{id}/play  { sessionId, source, durationPlayedSec, startedAt }
      ↓ rate limit 40/60с, verifySessionId
BullMQ play-events → insertPlayEvent
```

Ключевые ограничения, каждое проверено в коде:

1. **Событие шлётся в конце проигрывания, а не по нажатию Play.** `flushPlayEvent()`
   вызывается при смене трека и остановке и передаёт накопленное `durationPlayedSec`.
2. **`sessionId` обязан быть серверным и подписанным.** У мобилки его нет вообще —
   нужен вызов `/api/v1/session` и персист выданного id.
3. **`durationPlayedSec` — не косметика.** Волна считает по нему качество дослушивания
   `LEAST(1.0, duration_played_sec / duration_sec)` и порог скипа
   (`packages/db/src/queries/wave.ts:139,158`). Неверная длительность **испортит
   рекомендации всей платформы**, а не только мобильную статистику.
4. **`source` — из фиксированного перечня** `wave · release · playlist · artist · home ·
   feed · search · liked · purchased · direct`. Мобилка обязана вести контекст запуска
   очереди, иначе всё уедет в `direct` и аналитика источников обесценится.
5. **Офлайн-прослушивания** веб не решает. На мобилке они реальны и часты — нужна
   локальная очередь событий с отправкой при появлении сети. Это **новое требование,
   которого на вебе нет**, а не паритет.

Вывод: `P17` — не однострочник. Это отдельная подсистема с персистом, контекстом
источника и офлайн-очередью.

## 16. Чат — обязательное ревью безопасности до любых работ

`GET/POST /api/v1/keys` хранит **один `ik_pub` на пользователя**
(`upsertIdentityKey(caller.id, ikPub)`) `[C]`. Мобильный `bootstrapE2eeIdentity()`
публикует свой ключ **на каждом старте** `[C]`, веб делает то же со своей стороны.
Следствие `[I]`: два устройства перетирают ключ друг друга, и сообщения, зашифрованные
для одного, не читаются вторым.

Классификация домена: **`SECURITY / DATA INTEGRITY REVIEW REQUIRED`**.

Правильная инфраструктура на бэкенде уже есть — шесть роутов `keys/link/*` (SAS-привязка
устройств) `[C]`, мобилка в них не участвует. До решения:

* **не расширять** чат на мобилке;
* **не удалять** — код рабочий и криптографически корректный;
* **измерить ущерб**: запрос по `identity_keys` покажет, у скольких пользователей ключ
  уже перетирался;
* **закрыть флагом или предупреждением** до реализации привязки.

## 17. Что мобилка уже делает лучше веба

Не всё — догоняющее. Прослежено в коде:

| Функция | Почему мобилка сильнее |
|---|---|
| Фоновое воспроизведение и лок-скрин | Нативный foreground-service, медиа-контролы, `ContinuePlayback` — у веба этого класса возможностей нет |
| Офлайн-хранение | Настоящая файловая система вместо Cache Storage; переживает очистку данных браузера |
| Управление устройствами | Экран есть на мобилке и **отсутствует на вебе** |
| VireGlass | Материал существует только на Android |
| Безопасное хранение ключей | Android Keystore против IndexedDB |

Эти пять пунктов — не паритет, а собственная ценность мобильной платформы. В
реконструкции их надо усиливать, а не выравнивать по вебу.
