Починено: (1) логируем все ошибки hls.js + watchdog 20с; (2) hls.js-конфиг `maxBufferHole/nudgeOffset/nudgeMaxRetry` + явный перескок через ведущую дыру буфера — играет без пере-транскода; (3) на всякий случай в `/admin/tracks` кнопка **⟳ HLS** (пере-транскод из исходника) — для случаев реально битых/отсутствующих файлов. **Подтверждённый корень (1.1.6):** у исходников артиста обложка вшита ОТДЕЛЬНЫМ видео-потоком (не attached_pic) → ffmpeg без `-vn` мапил её в HLS видео-дорожкой из одного кадра → MediaSource вставал (bufferStalledError), хотя аудио целое. Системно: все файлы артиста так экспортированы, у других — нет. Фикс: `.noVideo()` в воркере. Дополнительно (defence-in-depth, тоже в воркере): `-fflags +genpts` + `aresample=async=1:first_pts=0` + `-avoid_negative_ts make_zero` (нормализация таймстампов); в плеере — толерантность к дырам + перескок. Новые загрузки чистые сразу; старые лечатся пере-транскодом (⟳ HLS).

## 5. Прямые продажи (ядро монетизации)

Бэкенд покупки трека написан ещё на этапе 1 и лежит отвязанным от витрины — его включаем и расширяем.

- **5.1 Покупка отдельного трека** `[частично]` — есть `POST /api/v1/tracks/[id]/purchase` → YooKassa redirect → webhook → PAID; скачивание FLAC по presigned URL; компоненты `download-button.tsx`, `purchased-track-row.tsx` готовы, не подключены. Осталось: **боевая настройка YooKassa** (SHOP_ID/SECRET_KEY + вебхук), **тесты роутов**, **подключить UI к витрине**.
- **5.2 Покупка релиза целиком** `[новое]` — корзина/единая транзакция на релиз, выдача всех треков + бонусов.
- **5.3 Мерч** `[новое] [обсудить]` — каталог физических товаров у артиста, заказ, оплата, фулфилмент/выдача, статусы. Модель данных + интеграция в страницу артиста/релиза.
- **5.4 Децентрализованный чекаут** `[новое] [обсудить]` — деньги идут **напрямую на мерчант артиста** (ИП или самозанятый), площадка по webhook только верифицирует оплату и открывает доступ; кассу по 54-ФЗ и налог несёт артист. Донат (CloudTips/Boosty) — запасной низкобарьерный путь.
- **5.5 Юридическая обвязка** `[новое] [обсудить]` — публичная оферта при регистрации артиста (ответственность за права/сэмплы), сверка со специалистом по IP/налогам. Купленные файлы остаются у слушателя навсегда (`purchased_files` независимы от статуса артиста).
- **5.6 Состав покупки** `[новое] [обсудить]` — FLAC/WAV + MP3 320, обложка в высоком разрешении и метаданные, liner notes, digital booklet (PDF); эксклюзивы (b-sides, демки, ранний доступ); артист видит, кто купил.

## 7. Алгоритмы, подборки, плейлисты

- **7.2 Кураторские и редакционные подборки** ✅ (17.07.2026) — качество и разнообразие
  генерации (`editorial.ts`): (P1) RELISTEN честно считает возвраты **одного** слушателя
  (`COALESCE(user_id, session_id)`, 2+ разных дня), а не глобальные дни-по-треку, и
  учитывает анонимов; (P2) все источники (RELISTEN/FRESH/MOOD/филлер) под единым

## 10. «Чёрное небо» — офлайн/локальная устойчивость `[новое] [R&D] [обсудить]`

Амбициозный трек на случай, если в РФ заблокируют весь интернет: возможность поднять Vire на **локальных сетях** (масштаб города / LAN). - **10.1 Заложить дёшево сейчас** `[новое]` — self-contained деплой без жёстких внешних зависимостей (Docker Compose уже есть); локальное хранилище (MinIO уже гоняем локально); вход, работающий офлайн (email/пароль — да; Яндекс-OAuth требует интернета — нужен офлайн-fallback); **offline-first PWA** с кэшем (стыкуется с PWA из [`concept.md` → «Интерфейсы»](../vision/concept.md#интерфейсы--четыре-оболочки-одно-ядро)).
- **10.2 Локальный запуск** `[новое]` — образ/инструкция поднять весь стек на одной машине в LAN без интернета (внутренний домен/DNS, без внешнего CDN для базовой работы).
- **10.3 Распространение и синк** `[R&D]` — как контент попадает в локальную ноду и синхронизируется между нодами; peer-to-peer / mesh — исследование, не сейчас.
